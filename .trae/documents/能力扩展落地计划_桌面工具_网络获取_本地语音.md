# Aerie 能力扩展综合方案 · 核心瘦身 / 插件化按需下载 / 桌面工具 / 网络获取 / 本地语音

> 项目：Aerie（`e:\Agent_reply`，Python FastAPI + Electron 桌面 Agent，产品名「云栖」）。
> 背景：项目处于多人并行开发期，目录与提交历史持续变动；架构高度耦合、前期框架有局限。
> 本文回答两个问题并合成一条路线：
> 1. **「核心包 + 功能模块分板块下载」是否可行**（技术可行性 / 实施复杂度 / 风险 / 优化建议）；
> 2. 三大能力扩展（本地桌面 AI 工具、网络获取、本地语音）如何在此架构上落地。
> 已锁定决策：桌面走通用自动化；网络走 trafilatura 爬虫 + 自建 Playwright；语音四项全要（入站 ASR / 出站语音条 / 实时通话 / 常驻唤醒）、设置可分别开关；推进顺序 **架构奠基与瘦身 → 桌面 + 网络 → 语音**。

---

## 一、总体结论（先给答案）

**结论：插件化分板块下载方案可行（可行性高），但真正的工作量不在"下载器"，而在三处：① 运行时模块装配契约；② 构建期依赖闭包拆分与发布清单；③ 原生依赖（torch/onnxruntime/DLL）的版本治理。** 好消息是，这套机制所需的全部"零件"在当前代码里都已有先例，不需要发明新范式。

| 议题 | 结论 | 一句话依据（2026-09-28 实测） |
|---|---|---|
| 分板块下载技术可行性 | **高** | Electron 侧已有生产级下载/解压自举（`runtime-bootstrap.js`，多镜像源+重定向+超时+PowerShell 解压）；数据目录已持久化到 `userData`；工具/技能/MCP 三套动态注册机制均已在跑 |
| 实施复杂度 | **中**（契约小、发布重） | 核心改动 ≤ 4 个挂点；重活在 wheelhouse 拆分、`.aeriepack` 打包、catalog 清单与镜像发布 |
| 核心包瘦身 | **高收益、低成本，应最先做** | 当前 runtime 整体拷 `.venv`（实测 **703MB**），其中 chromadb 闭包（kubernetes 74 + rust_bindings 60 + onnxruntime 43 + pandas 62 + tokenizers/grpc/hf_xet 等，**合计 ≥270MB**）本就是"可选+惰性 import+哈希兜底"，不拆白不拆 |
| 第三方开放插件市场 | **本期不做**（一期只做一方功能包） | 签名审核、UI 注入、沙箱、版本兼容矩阵成本远大于收益；契约按"未来可开放"设计，不提前付溢价 |
| 三大能力与插件化关系 | 浏览器 = 独立 pack；语音 = 两个 pack；桌面/爬虫 = 内置核心 | Playwright 内核 ~170MB、torch+RVC 模型 ~1GB，是体积矛盾的主要来源；桌面自动化与爬虫几乎无增量体积 |

**体积账（实测 + 估算，Windows x64）**

| 组成 | 当前（单体） | 目标拆分 |
|---|---|---|
| Python runtime site-packages | **703MB**（实测，整包拷贝） | 核心 ~400MB（拆出 chroma 闭包等 ≥270MB，再清理 tests/pycache） |
| ffmpeg | 220MB | 留核心（QQ 媒体/ASR 链路硬依赖） |
| NapCat | 90MB | 留核心（QQ 是核心通道） |
| Electron 本体 | ~200MB | 留核心 |
| Playwright Chromium | 未含 | **browser pack ~170MB，按需** |
| 语音 ASR（sherpa-onnx + SenseVoice int8 + silero + sounddevice） | 未含 | **voice-asr pack ~250MB，按需** |
| 语音 RVC（torch CPU ~600MB 安装态 + rmvpe 173MB + ContentVec 189MB + 权重） | 未含 | **voice-rvc pack ~1GB，按需** |
| 知识库向量（chromadb 闭包） | 在核心内 ≥270MB | **knowledge pack（候选），从核心移出** |
| 单体落盘体积（估） | **~1.2–1.3GB** | 核心 ~850MB–1GB；安装包（NSIS 压缩后）目标 **≤600MB** |

## 二、现状测绘（基于当前代码，非采样印象）

> 项目并行开发中，以下均带路径；执行阶段如行号漂移，以函数/文件名为准重新核对。

### 2.1 打包与分发链路（事实）

- 打包配置唯一事实源：`electron/electron-builder.yml`。目标 `nsis`（`oneClick:false`、`perMachine:false`、可改安装目录）+ `portable`；`asar:true`；`publish: null`（**无自动更新通道，用户靠重装更新**）；`deleteAppDataOnUninstall:false`（**userData 卸载后保留 → 插件装在 userData 可天然跨重装存活**）。
- `extraResources`：`runtime-build-vfix → python/runtime`（自包含 CPython）；项目根 `→ python`，filter 白名单为 `main.py / core / config / communication / knowledge / memory / tools / voice / world_service / emotion / persona / scheduler / skills / NapCat.Shell / ffmpeg/bin`，**显式排除 `data/**`、`logs/**`**；**当前没有 `models/**`**。
- 运行时构建：`scripts/build_python_runtime.py` 拷贝真实基础解释器，再把 `.venv/Lib/site-packages` **整体覆盖**进产物，仅排除 pip/setuptools/wheel/pytest（L56-72）——开发 venv 里装了什么，安装包里就有什么，无依赖闭包治理。
- 启动链：`electron/src/main.js` L472 `spawn(PYTHON_EXE, [PY_MAIN])`，`cwd=PYTHON_ROOT`；打包态设 `PYTHONNOUSERSITE=1`（L482，**插件自带 site-packages 必须显式注入 `sys.path`，不能靠 user site**）；注入 `AERIE_DATA_DIR/AERIE_DB_PATH/端口/token` 等环境变量。
- 数据目录：`main.js` L222-252，打包态 `data = app.getPath("userData")/data`，`logs = userData/logs`；后端侧 `core/paths.py` 仅 `project_root/data_dir/cache_dir/briefs_dir/city_cache_path`（**无 models_dir/plugins_dir**）。
- **已有的下载自举**：`electron/src/runtime-bootstrap.js` 导出 `downloadFile`（HTTPS/HTTP、5 次重定向、超时）、`extractZip`（PowerShell `Expand-Archive`）、三镜像源（python.org / 华为云 / TUNA）、失败教程兜底。**插件下载器直接复用这套，不重写。**
- 重依赖现状（requirements + 实测 venv）：`chromadb>=1.5.9` 实际启用（L122 未注释）；easyocr/openai-whisper 注释；torch / sherpa-onnx / playwright / sounddevice / scipy **代码中零 import**（仅 `ita-river-loft-room.design-project/render_png.py` 旁支用 playwright），拆包没有历史 import 包袱。
- 现存模型：`models/vosk-cn/vosk-model-small-cn-0.22`（~65MB，执行期需确认是否仍被引用）；`data/` 实测 617MB 但不入包。

## 三、ADR-1：模块架构决策（核心 + 功能包 + 模块中心）

### 决策问题
在不推倒现有单体后端的前提下，如何让安装包"小核心起步、功能按需下载"，并同时承载浏览器/语音等重能力，且兼容多人并行开发的高耦合代码库？

### 现状驱动力（Forces）

| # | 力 | 说明 |
|---|---|---|
| F1 | 下载体验 | 单体已 ~1.2GB，语音全量后逼近 4GB；torch/Chromium 仅少数用户需要 |
| F2 | 高耦合 + 并行开发 | 契约面必须极小（少改核心文件），否则与并行分支持续冲突；不能先大重构再做功能 |
| F3 | 单进程硬约束 | 用户要求语音与主后端同进程；故插件是**进程内装配**而非多服务，不能走重 IPC |
| F4 | Windows 分发现实 | perUser 安装、免管理员；`PYTHONNOUSERSITE=1`；无签名（`signAndEditExecutable:false`）；无自动更新通道 |
| F5 | 已有先例文化 | 技能加载器（目录+元数据+动态导入+隔离）、MCP（命名空间+冲突保护）、feature_flags、runtime-bootstrap 下载器都是团队已接受的模式 |
| F6 | 可演进性 | 一期一方功能包，但不能把"未来第三方/进程隔离插件"的门焊死 |

### 决策（Decision）

采用 **"瘦核心（单体不变）+ 进程内一方功能包（`.aeriepack`）+ Electron 模块中心（下载/校验/启停）"**：

1. **物理布局**：核心仍随 NSIS 安装；功能包下载到 `userData/plugins/<pack_id>@<version>/`（免管理员、跨重装保留），下载临时区 `userData/plugins/.staging/`，校验通过后原子改名（目录 rename），失败可整体丢弃。
2. **包格式**：`.aeriepack` = zip，内含
   ```
   pack.json          # 清单：id/version/api_level/min_core/entry/工具与技能声明/
                      #       依赖声明(共享库+独占库)/模型与二进制清单(sha256,size)/设置 schema
   py/                # 该包 Python 模块（entry 所在）
   vendor/            # 独占第三方库（解压后的包目录，非 pip 安装）
   models/  bin/      # 模型权重、原生二进制（如 Chromium）
   SHA256SUMS         # 包内全量哈希
   ```
3. **进程内契约**：新增唯一核心文件 `core/plugin_host.py`。启动时（`register_all_tools` 之前）扫描 plugins 目录 → 校验清单（`api_level` 精确匹配、`min_core` 满足）→ 把 `py/`、`vendor/` 注入 `sys.path` → import entry → 调 `register(ctx)`；`ctx` 只暴露五样：`tool_registry`、`settings`（plugins 段）、`event_bus`(chat_events)、`api_router`（固定 APIRouter 挂点）、`paths`。包可选实现 `async start(companion)/stop()`，由 Companion 统一各调一次。
4. **装配失败隔离**：单包 import/register 异常 → 标记 `broken`、warning + 模块中心可见，**绝不阻断核心启动**（沿用技能加载器与工具组注册的既定范式）。
5. **开关正交**："装没装"（模块中心）决定可用性；既有 `feature_flags` 决定行为启停。未安装包的工具不进注册表 → 模型看不到 schema；开关面板检测到缺包时引导安装（显示体积/来源）。
6. **下载与信任**：Electron 新增 `plugin-manager.js`，复用 `runtime-bootstrap.js` 的 `downloadFile/extractZip`，增加 **Range 断点续传、落盘 SHA256 校验、暂存区原子替换、安装/卸载需重启后端**（原生 DLL/torch 加载后无法卸载，明确告知）。来源为固定 allowlist 的 catalog（GitHub Releases + 国内镜像，沿用三源思路）；catalog 内含每包 `sha256/size/api_level/min_core`。
7. **共享库治理**：numpy / onnxruntime / scipy 等可被多包共用的原生库**只放核心 runtime 一份并锁版本**，功能包不得重复携带；包的独占库放 `vendor/`。`onnxruntime`（43MB）保留在核心（voice-asr 与 knowledge 共用）。
8. **一期边界**：只做一方包；无第三方包 UI 入口、无前端代码注入、无进程隔离包 UI（MCP 已是后者的逃生通道）；包内设置由模块中心按 schema 通用渲染。

### 被否决方案（Alternatives Rejected）

| 方案 | 否决理由 |
|------|----------|
| A0 维持单体，仅做功能开关 | torch+模型 ~1GB、Chromium ~170MB 无法靠开关消除；所有用户为不用的能力付下载成本 |
| A1 运行时 `pip install` 拉依赖 | 目标机无 Python 工具链保证、pip 环境污染、杀软拦截、断网不可用；`tools/_auto_install_deps.py` 是开发机一次性脚本（硬编码路径），已证明此路不可产品化 |
| A2 现在就做开放第三方插件市场/SDK | 签名审核、沙箱、前端注入、兼容矩阵成本巨大且无用户需求；违反"monolith-first、为明确收益才付分布式溢价"。契约保留逃生口，不提前实现 |
| A3 全部能力走 MCP 子进程隔离 | 语音要共享音频线程与低延迟回环、浏览器要共享内核会话，跨进程代价高且与用户"单进程"要求冲突；MCP 保留给未来隔离型扩展 |
| A4 出多个独立安装包（标准版/语音版/完整版） | 安装包与发布流水线乘数级维护，版本组合爆炸；一个模块中心一条发布线更省 |
| A5 直接上 electron-updater 做差量更新 | 当前 `publish:null` 无服务端基础设施；功能包分发先以静态 catalog + 固定 URL 解决，自动更新另题决策 |

### 后果（Consequences）

**正向**：核心安装包目标 ≤600MB（压缩态）；重能力零成本试装试卸；包成为功能迭代的物理边界，天然缓解并行开发互相踩踏；卸载重装不丢已购能力（userData 保留）；模块中心成为后续所有能力的统一入口。

**负向 / 代价**：
- 新增一条发布产品线（catalog、pack 构建、镜像同步、哈希清单）；
- `api_level` 契约需纪律维护，并行开发中改挂点必须同步升 level；
- 安装/卸载需重启后端（无法热卸载原生库）；
- 弱网下 GB 级包下载体验取决于续传与镜像；
- 模块中心与后端需处理"装了但核心版本不兼容"的拒绝路径。

**可逆性**：可逆（两向门）。插件机制是核心上的增量（1 个新文件 + 4 个挂点），功能包是独立目录；回滚只需删除挂点与目录。真正难逆的是"把代码从核心搬到 pack 后的发布习惯"——一旦 catalog 上线，撤回需一次核心版本发布。**触发重新评估的信号**：一方包数量超过 ~8 个且版本矩阵维护失控（→ 考虑独立更新通道）；出现强第三方扩展需求（→ 启用签名+MCP 隔离通道）。

### 责任与运行期可运维性
- 契约/宿主：后端 `core/plugin_host.py`；下载/安装：Electron `plugin-manager.js`；发布：构建脚本 + catalog（均为本仓库内可检查路径，不依赖外部运维）。
- 用户侧可调试：模块中心显示 `已安装/可更新/不兼容/损坏/下载失败(原因)`；`userData/plugins/<id>/pack.json` 与安装日志可直接查看；坏包可一键移除；语音包加载失败时自动回退纯文本（业务容错，非兼容层）。

### 限界上下文图（Bounded Context Map）

| 上下文 | 职责 | 与邻居关系 |
|---|---|---|
| core-kernel | API 服务、事件总线、注册表、flags、路径、Companion 生命周期 | 对插件暴露**只读契约面**（ctx 五件套）；插件 → 核心为 conformist（遵从契约） |
| pack:browser | Playwright 会话与 browser_* 工具 | 注册工具到 kernel；安装状态受模块中心管辖（customer/supplier） |
| pack:voice-asr / voice-rvc | 本地音频推理链 | 经 chat_events 发状态；RVC 失败由语音域自己回退原声 |
| pack:knowledge（候选） | chromadb 向量检索 | 上游 embedding provider；下游 memory/knowledge 已内置哈希兜底（防腐层已存在） |
| electron-shell | 窗口、下载器、IPC、模块中心 UI | 经 HTTP/IPC 与 kernel 协作；下载是对 kernel 的 supplier |
| distribution | wheelhouse/pack 构建、catalog、镜像 | 对 shell 提供版本与哈希（supplier）；api_level 是双方共享内核（shared kernel） |

### 交互方式决策
启动扫描为**同步且极轻**（目录枚举 + JSON 解析，禁止在发现阶段 import 重库；重库由包在 `start()` 内惰性加载）；下载/安装为 Electron 侧**异步带进度事件**（IPC 广播，splash 同款进度范式）；插件运行期状态走进程内事件总线，不轮询。

### 架构适应度函数（Fitness Functions，全部自动化）

| 性质 | 度量/规则 | 阈值 | 来源/节奏 | 失败反应 |
|---|---|---|---|---|
| 依赖方向 | grep：`core/**`（除 plugin_host）不得 import 任一 pack id 目录 | 0 处 | pytest/CI 每次 | 阻断合并 |
| 核心体积 | NSIS 产物大小 | ≤ 600MB（一期目标） | 构建脚本断言 | 构建失败并打印 Top20 大文件 |
| 空目录启动 | plugins 目录为空时启动成功且工具数=基线快照 | 完全一致 | pytest | 阻断 |
| 准入完整性 | 篡改 1 字节 / sha256 不符 | 拒绝安装 | 测试夹具 | 阻断发布 |
| 版本不匹配 | `api_level`/`min_core` 不符 | 拒绝加载并提示 | pytest | 阻断 |
| 失败隔离 | entry 抛异常 | 核心启动成功、包标 broken | pytest | 阻断 |
| 开关即资源 | flag 关闭时无麦克风线程/模型加载 | 日志断言 | 语音阶段测试 | 阻断 |
| 启动预算 | 未安装包对冷启动耗时增量 | = 0（仅目录扫描） | 启动计时 | 阻断 |

## 四、插件化方案技术设计

### 4.1 目录与路径
- `core/paths.py` 新增：`plugins_dir()`（默认 `userData/data` 同级的 `userData/plugins`，经 `AERIE_PLUGINS_DIR` 可覆盖）、`models_dir()`。
- Electron 侧 `userData/plugins/` 与后端路径通过环境变量对齐（沿用 `AERIE_DATA_DIR` 模式新增 `AERIE_PLUGINS_DIR`）。

### 4.2 pack.json（一期字段，克制不扩张）
```json
{
  "id": "voice-asr",
  "version": "1.0.0",
  "api_level": 1,
  "min_core": "0.3.2",
  "entry": "voice_asr_pack.plugin:register",
  "lifecycle": { "start": "voice_asr_pack.plugin:start", "stop": "voice_asr_pack.plugin:stop" },
  "tools": ["asr_transcribe_local"],
  "skills": [],
  "shared_requires": ["onnxruntime==1.*", "numpy"],
  "vendored": ["sherpa_onnx", "sounddevice"],
  "assets": [
    { "path": "models/sensevoice-int8.onnx", "sha256": "...", "size": 162529280 }
  ],
  "settings_schema": [
    { "key": "asr_provider", "type": "enum", "options": ["sensevoice", "whisper", "cloud"], "default": "sensevoice" }
  ],
  "feature_flags": ["voice_asr_v1"],
  "restart_required": { "install": true, "remove": true }
}
```
- `api_level`（整数）与 `min_core`（语义版本）双保险：契约破坏性改动升 level；核心内部重构用 semver。
- catalog.json：`{ "catalog_version": 1, "api_level_default": 1, "packs": [ {id, version, min_core, api_level, size, sha256, urls:[...mirrors], title:{zh,en}, release_notes} ] }`。

### 4.3 后端宿主 `core/plugin_host.py`（唯一新文件）
职责：发现 → 校验（清单 + SHA256SUMS 抽查）→ `sys.path` 注入 → import entry → `register(ctx)` → 生命周期登记 → `/api/plugins`（list/get/install-state 只读；下载动作在 Electron 侧）。挂点共四处：
1. `companion.py` 建 ToolRegistry 后、`register_all_tools` **之前**：`plugin_host.discover_and_register(registry, app)`；
2. `api_server.py` app 创建后：`app.include_router(plugin_host.router)`（一行）；
3. `Companion.start()/stop()` 各加一行 `await plugin_host.start_all(self)/stop_all()`；
4. `main.py` 热重载订阅增加 `plugins` 配置段（沿用现有订阅机制）。

### 4.4 Electron 下载与模块中心
- 新建 `electron/src/plugin-manager.js`：`getCatalog()`（三源拉取，同 bootstrap 思路）、`installPack(id)`（临时区 → 支持 Range 续传 → `extractZip` → 调后端或本地算 SHA256 → rename 原子切换 → 通知重启）、`removePack(id)`、进度 IPC 广播；复用 `runtime-bootstrap.js` 已导出的 `downloadFile/extractZip`。
- IPC：`plugins:catalog / list / install / cancel / remove / on-progress`，经 `preload.js` 白名单暴露（与现有 `api:request` 同审查级别）。
- UI：`settings.js` 增加第五种模式 `plugins`（模块中心），复用 provider-card 样式：图标用内置图标库（不用 emoji）、小字号、柔和圆角、充足留白；每张卡显示名称/一句话说明/体积/状态/安装或移除按钮/下载进度条；不兼容与损坏有明确徽标；安装后出现"重启后端生效"（复用现成重启按钮流程）。
- 语音开关（C5）在检测到缺包时，开关旁出现"安装语音模块（约 250MB）"引导，而非允许打开无效开关。

### 4.5 构建与发布
- 依赖分组：`requirements-core.txt`（瘦身后核心）、`plugins/browser/requirements.txt`、`plugins/voice-asr/requirements.txt`、`plugins/voice-rvc/requirements.txt`、`plugins/knowledge/requirements.txt`。
- `build_python_runtime.py` 从"拷 venv"改为**按 wheelhouse 清洁构建**（`pip download -r requirements-core.txt` 到干净目录再装配），消除开发机污染；保留 import 自检并扩展包级断言；新增体积断言与大文件 Top20 报告。
- 新增 `scripts/build_plugin_pack.py`：装配 `py/vendor/models/bin` → 生成 SHA256SUMS 与 pack.json → zip；产物与核心版本同发布。
- 发布：GitHub Releases 挂核心安装包 + 各 `.aeriepack` + `catalog.json`；国内镜像（OSS/云盘镜像，三源同 bootstrap）同步；**一期不做包独立升级**，包版本跟随核心版本（catalog 按 release tag 索引），避免版本矩阵爆炸。
- 安全（供应链最低线，对齐 supply-chain 纪律）：HTTPS + 域名 allowlist；**准入强制 SHA256**；安装留 provenance 记录（来源 URL/版本/哈希/时间，写 `userData/plugins/install-log.jsonl`）；安装器与包的 **Ed25519 签名列为二期**（当前安装包本身也未签名，属已知一致例外，不为插件单独搞 PKI 半成品）；不提供第三方包本地导入入口（开发调试用环境变量显式开启）。

### 4.6 一期不做什么（边界）
第三方包市场、包内前端代码注入、独立进程包的 UI、包独立热更新/差量、包内 pip 联网安装、插件商店账号体系。

## 七、优化建议（即便不做插件化也值得先拿的收益）

1. **立即做核心依赖审计**：`build_python_runtime.py` 增加排除组（chromadb 闭包、各包内 `tests/`、示例与多语言资源如 babel 本地化数据），保守估计核心 runtime 从 703MB 降至 ~400MB，无需任何功能包机制。
2. **清洁构建替代 venv 拷贝**：以 wheelhouse 装配 runtime，杜绝开发机偶发安装污染发布包（并行开发期尤其重要）。
3. ffmpeg（220MB）/ NapCat（90MB）留核心但在构建报告中持续可见；未来若出现"不用 QQ"用户群，NapCat 可作为第 4 个 pack 候选，机制已铺平。
4. 体积守卫写进构建（Top20 大文件报告 + 阈值失败），防止依赖悄悄膨胀。
5. 模块中心同时显示"数据目录占用"（data/ 已 617MB），为后续数据清理能力留入口。

## 十一、执行顺序总览

```
P0 核心瘦身 + 插件契约 + 模块中心（含 hello-pack 验收）
  └─ A 桌面 AI 工具（进核心）
  └─ B 爬虫（进核心）→ browser pack（首个真实插件，打通发布/下载/装配全链）
  └─ C1 ASR ─ C2 语音条/RVC ─ C3 通话 ─ C4 唤醒 ─ C5 面板（voice-asr / voice-rvc 两 pack）
  └─ D pack 构建 / catalog / 镜像 / 干净机器分发验收
```

P0 是关键路径：它既兑现"核心瘦身、按需下载"的直接诉求，又把浏览器与语音的体积矛盾变成两个普通的功能包；A 与 B 的爬虫部分与插件机制无依赖，可并行排期。
