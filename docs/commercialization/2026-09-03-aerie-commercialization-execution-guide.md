# Aerie 商业化执行总册：优势放大、定价与首轮投放

> 适用版本：`0.3.2-beta.0904-A12`
> 版本规则：`0.3.2-beta.mmdd-A(上午)P(下午)hh`。例如 9 月 3 日下午 2 点为 `0.3.2-beta.0903-P02`。发布前必须同步 `core/version.py`、各端 manifest、安装包、官网和 Release。  
> 读者：第一次做软件开发、上架、收费和投放的产品负责人。本文是执行建议，不替代法律、税务或支付机构意见。

## 1. 先确定卖什么

Aerie 不卖“一个会聊天的角色”，而卖一套**可控的桌面 AI 工作流**：对话负责理解，记忆负责保留上下文，工作区负责在授权后执行，连接器负责按需接入模型、语音和形象。

商业默认形象必须是中性、合规的 **Aerie Companion**。用户自己的“伊塔/云栖”或其他 persona 可以导入、隔离、删除，但不进入默认安装包、种子记忆、官网主视觉或广告文案。首屏应该让用户在 5 分钟内完成三步：选择合规角色、选择模型或本地降级、发送第一条消息。

推荐定位：

> **把 AI 放进你的桌面工作流：对话、记忆、权限和连接器由你掌控。**

## 2. 怎样把优势放大成竞争力

每个卖点都要有 30 秒演示和可验证边界，不能只写功能名称。

| 优势 | 演示证据 | 用户结果 |
|---|---|---|
| 本地优先 | 打开数据目录、联网开关和 Key 归属页 | 清楚知道什么留在电脑上 |
| 对话到执行 | “整理本周素材” -> 预览 -> 授权 -> 日志 | 少做重复操作，过程可追溯 |
| 记忆可控 | 查看、修改、删除记忆；切换 persona 后数据隔离 | 长期上下文有用但不失控 |
| 连接器可替换 | 断开云模型或 Companion Studio，显示结构化 disabled/降级 | 单个服务故障不拖垮核心聊天 |
| 主动性可解释 | 显示提醒原因、暂停和撤回入口 | 主动消息可控、可关闭 |
| 中性默认角色 | 首次启动为 Aerie Companion，用户再自定义 | 面向大众合规，不被私人设定绑架 |

真正应形成的护城河是“**本地数据边界 + 可审计工作流 + 可替换模型/人格/连接器**”的组合，而不是角色数量、情感依赖或无限调用承诺。

## 3. 迎合当前市场的表达

用户现在更关心三个结果：能否节省时间、数据是否可控、费用是否可预期。因此官网和广告只保留一个主动作：下载并完成第一条消息或一个工作区任务。语音、RVC、Live2D 和 Companion Studio 作为可选连接器展示；没有外部 URL、Key 或模型时，必须显示 `disabled`/降级，不得写成默认已可用。

首轮只改变标题，不同时改变功能和页面结构：

1. 隐私方向：**你的 AI 数据，留在你的设备上。**
2. 效率方向：**从一句话开始，把工作推进下去。**
3. 可替换方向：**模型、人格和连接器，都由你选择。**

建议优先测试个人效率用户，再测试内容创作者/主播；暂不从团队版和角色社区切入，因为账号、权限、发票和内容审核成本尚未成熟。

## 4. 同赛道对比

| 代表产品/方向 | 它们更强的地方 | Aerie 不应硬拼 | Aerie 的切入点 |
|---|---|---|---|
| Character.AI | 角色数量、社区规模 | 角色生态和云规模 | 本地边界、工作流执行 |
| Replika / Nomi / Kindroid | 陪伴叙事、关系连续性 | 情感关系深度和移动端成熟度 | 中性默认、persona 隔离、桌面生产力 |
| Pi | 上手简单、品牌认知 | 云端可用性和分发规模 | 模型可替换、无外部服务可降级 |
| LM Studio / Ollama | 本地模型和开发者控制 | 模型运行深度与生态 | 在本地模型之上增加记忆、权限、执行 |

对外避免“最像真人”“角色最多”“无限 AI”“替代心理咨询”等不可证或高风险表达。应反复演示“授权前预览、执行日志、可撤回、费用分开”。

## 5. 收软件费还是 API 费

首发采用：**免费本地核心 + Pro 软件订阅 + 第三方 API 单独计费**。

| 层级 | 首轮测试价 | 用户购买的内容 | 不包含 |
|---|---:|---|---|
| Free | 0 元/月 | 本地聊天、基础记忆、单 persona、单工作区、明确的离线降级 | 平台补贴的云端无限调用 |
| Pro A | 19 元/月 | 多 persona、更多工作区、主动提醒、高级记忆视图、连接器管理 | 无限 LLM/ASR/TTS/RVC |
| Pro B | 29 元/月 | 与 Pro A 相同，用于价格 A/B 测试 | 无限云额度 |
| 年付 | 月价的 8-10 倍 | 与 Pro 相同 | 真实支付前不开放 |
| 团队版 | 暂不公开，内部假设 99 元/月起 | 共享模板、管理员审计、部署支持 | 账号、权限、发票和客服未完成 |

软件订阅购买的是功能、更新和支持，不应包装成“AI 额度”。

### API 收费路径

**阶段 1，BYOK（推荐封闭测试）**：用户填写自己的 LLM、ASR、TTS、RVC 或生图 Key，费用直接由供应商收取，Aerie 不代收、不承诺无限。

**阶段 2，平台代付**：只有在真实支付、税务和供应商协议准备好后才做。建立独立 API 钱包，展示供应商、模型、输入/输出 token 或音频时长、单价、余额和硬上限；余额不足立即停止调用，禁止静默透支。

**阶段 3，双账本**：软件 entitlement 和 API 钱包是两个独立状态。取消 Pro 不等于退还已产生的 API 成本，API 余额也不能解锁 Pro 功能。

## 6. 非开发者的上线顺序

### 第 0 阶段：内部验收（1-3 天）

使用 D 盘构建包，在干净 Windows 配置验证安装、首次启动、默认角色、无模型降级、配置保存、第一条消息、退出重启、升级和卸载。目标：安装成功率 >= 90%，首条消息完成率 >= 80%，关键流程崩溃率 < 2%。

### 第 1 阶段：封闭测试（10-20 人，1-2 周）

每位测试者完成：创建合规 persona、配置模型或使用本地降级、执行一次工作区任务、使用一次提醒、断开外部服务后重试。只记录匿名流程指标和错误代码，不记录聊天正文、原始音频、屏幕内容或私有 persona。

### 第 2 阶段：价值与价格测试（2-4 周）

保持功能不变，分别测试 19 元和 29 元页面。核心指标是首次消息、工作区任务完成、7 日留存、试用激活、付费成功、退款率、支持工时和每活跃用户 API 成本。下载量不能单独证明产品有价值。

### 第 3 阶段：小预算公开投放（7 天）

只投放已经完成隐私审查的营销页，按 UTM 比较三个标题。没有真实 Pixel ID、用户同意机制和真实支付成功边界时，广告测量保持 no-op；不得伪造 `trial_started` 或 `subscription_created`。

### 第 4 阶段：商店上架

先用 GitHub Release + 自有官网，附 SHA-256、隐私政策、许可、已知限制和支持邮箱。等签名、升级、卸载、崩溃处理、退款和客服稳定后，再申请 Microsoft Store 等渠道，不要同时铺开多个商店。

## 7. 公开收费前的硬门槛

- 商业 EULA、隐私政策、删除/导出说明、退款/取消续费政策、发票或收据流程；
- 第三方模型、语音、Live2D/RVC 资产的商业许可清单；
- 支付成功、重复 webhook、失败、退款、取消续费、断网和重启的可复现测试；
- 服务端验签和幂等更新 entitlement，客户端不能凭按钮点击或本地文件认定已付款；
- 仓库 LICENSE 的商业使用边界已获得权利人确认。完成前只做免费或书面授权封闭测试。
