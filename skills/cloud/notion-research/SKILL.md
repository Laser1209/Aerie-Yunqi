# 跨库研究与产出（notion-research）

把散在 Notion 各处的资料捞齐、综合成一份**带出处、可直接拿去用**的简报或报告。

这个流程的价值全在"可追溯"：读的人能点回原始出处，才敢引用你的结论。

## 前置

凭据与通道都在设置页：先在「平台凭证 → Notion」填个人访问令牌，再到
**「MCP 服务器」里开启 Notion**（改完需重启后端生效）。

**如果当前没有 `mcp__notion__` 开头的工具**，说明通道没开。这时**直接告诉用户去开启**，
不要凭印象作答冒充"我在库里查到了"。

## 铁律

1. **搜索词一次一个**：一条查询只写一个字面词，多个说法就分多次搜。
   在一条查询里塞 `or` / `+` 只会把结果搅浑。
2. **只有库内页面/资料库/数据源的 URL 或 ID 才能拿去读**。搜索结果里可能混进外部来源的
   链接，那些只能作为背景或引用，不能当库内页面读。
3. **先列提纲再落笔**，把发现按主题或问题分组；边写边想必然写成一锅粥。
4. **标注证据**：关键事实记下出处；对没有出处、互相矛盾、明显缺口的，**明确标出来**，
   不要抹平。
5. **区分事实与判断**：引用原话 vs 你的推断，两者要能一眼分开。
6. **篇幅服从目的**：只为同步信息就别写成大部头。

## 输出形态选择

- 快速读数 → 一页纸简报
- 单主题深挖 → 研究摘要
- 多个方案权衡 → 对比
- 决策级深挖 → 完整报告

## 步骤

1. 明确问题与用途（要支撑什么决策），必要时先跟用户对齐范围。
2. 搜一轮，再按结果调整关键词多搜几轮；命中的页面逐篇读。
3. 抽取事实、数字、约束、日期，逐条记下出处。
4. 列提纲，按主题归类，标出缺口与矛盾。
5. 建页面：标题 → 摘要 → 关键发现 → 支撑证据 → 建议/下一步 → 引用列表。
6. 正文内嵌引用标记，文末给引用列表并链回原页面。
7. 需要跟进就建清单或任务条目并关联。

## 自检

- 每个关键结论都能顺着引用点回原页
- 缺口与矛盾被明确写出，而不是被平滑掉
- 事实与判断在措辞上可区分
- 摘要能独立读懂（不必翻正文）
- 没有把外部来源的链接当库内页面引用

## 反面例子

- 一条查询里堆七八个关键词，结果全是噪音
- 结论无出处，读者无法复核
- 把两个来源冲突的说法各写一半，不做取舍也不提示
- 上来就写正文，写完发现结构全乱
