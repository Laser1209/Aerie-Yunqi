# 功能包（.aeriepack）落地 与 平台能力接入 · 实施计划

> **面向执行者**：本计划按任务顺序执行。每个任务自带「改哪些文件 / 怎么验证 / 提交点」。
> 步骤用 `- [ ]` 勾选跟踪。**先跑验证再提交，不跳步。**

**目标**：把 `plugins/` 下 4 个只有 `requirements.txt` 的占位目录，做成**真能加载、真能调、真能打包分发**的功能包；同时把 12 个 scaffold 桩里**非支付类**的 9 个接到真实通道上（支付类 3 个不做）。

**架构**：沿用已落地的 ADR-1（见 `能力扩展落地计划_桌面工具_网络获取_本地语音.md`）——
核心保持单体且精简，重能力以 `.aeriepack`（zip）按需下载到 `userData/plugins/`，
后端 `core/plugin_host.py` 在启动早期扫描、校验、注入 `sys.path`、调 `register(ctx)`；
Electron `plugin-manager.js` 负责下载/断点续传/SHA256/原子替换。
本轮新增的是**包里的内容**与**分发通道**，不是新机制。

**技术栈**：Python 3.14 / FastAPI / Playwright / chromadb / sherpa-onnx / torch(CPU) /
Electron(Node) / Cloudflare R2 + Worker / wrangler。

## 三、先修一个"装了也白装"的地基缺陷（Part A0）

### 背景（这是执行前必须知道的事实）

`core/tool_registry.py:55` 的 `register()` **是直接赋值覆盖**，不做冲突拒绝：

```python
self._tools[name] = {"func": func, "schema": schema or {}, ...}
```

而 `core/companion.py:1290-1293` 是：

```python
# 功能包先注册、核心工具后注册：同名工具核心赢（ToolRegistry.register 拒绝覆盖）
plugin_host.discover_and_register(self.tool_registry)
register_all_tools(self.tool_registry)
```

注释说"拒绝覆盖"，实现却是"后者覆盖前者"。**结论：包先注册，核心后注册 → 核心覆盖包。**

对 browser pack 是致命的：包里注册的 `browser_navigate` / `browser_snapshot` … 会被
`tools/browser_tools.py`（Kimi WebBridge，`register_webbridge_tools`）**全部顶掉**，
用户装了 170MB 的包却仍在调 WebBridge。

**修法**（与 ADR 的 B2 一致，不改覆盖语义，改注册顺序的**可见性**）：
让 WebBridge 只在 `settings.yaml → browser.backend == "webbridge"` 时注册；
默认 `playwright`（即包提供）。

### 阶段 A1 · MCP 通道（Notion ×4 + 天眼查）

**为什么走 MCP**：用户已选"优先接现成 MCP"。这些平台官方/社区已有 server，
自写 HTTP 是重复劳动且要自己维护鉴权与分页。

research / spec-to-impl）**不是工具，是工作流方法论**——和已落地的 40 个指令型 skill

所以正确形态是：

* **读写 Notion 的能力** → MCP server 提供工具（`mcp__notion__*`）

* *4 个 notion-* skill\* → 转 **指令型**，正文里指明用 `mcp__notion__*` 工具

        for item in zin.infolist():

```javascript
/**
 * catalog 来源优先级：
 *   1) AERIE_PLUGIN_CATALOG_URL 指向的远程 catalog（你 R2 上的那份）
 *   2) 内置 electron/src/plugin-catalog.json（官方白名单，同时是远程不可达时的兜底）
 * 远程拉取失败**不得**让模块中心变空——回退内置并记 reason，UI 上明示。
 */
async function loadCatalog({ catalogUrl, timeoutMs = 8000 } = {}) {
  const bundled = _readBundledCatalog();
  if (!catalogUrl) return { packs: bundled, source: "bundled" };
  try {
    const remote = await _fetchJson(catalogUrl, timeoutMs);
    return { packs: remote.packs || [], source: "remote" };
  } catch (err) {
    return { packs: bundled, source: "bundled", error: String(err.message || err) };
  }
}
```
