# 会议情报（notion-meeting-intelligence）

开会前把**已有资料捞齐、议程定死、决策说清**，产出可直接发给参会人的会前材料。

会议开得散，九成是因为会前没人把"要决定什么"写下来。

## 前置

凭据与通道都在设置页：先在「平台凭证 → Notion」填个人访问令牌，再到
**「MCP 服务器」里开启 Notion**（改完需重启后端生效）。

**如果当前没有 `mcp__notion__` 开头的工具**，说明通道没开。这时**直接告诉用户去开启**，
不要假装已读到资料或已建好页面。

## 铁律

1. **先问清输入**：目标、期望产出/要做的决策、参会人、时长、时间、已有材料。
   缺哪项就问哪项，别猜。
2. **先捞后写**：从 Notion 搜出相关的过往记录、规格、OKR、上次决策，再动笔。
   不查历史就写议程，会把上次已经拍过的事再讨论一遍。
3. **按会议类型选模板**，不要一份模板套所有会：
   - 状态同步 → 进展式
   - 要做决策/审批 → 决策式（含备选方案与推荐）
   - 规划（迭代/项目） → 规划式
   - 复盘 → 复盘式
   - 一对一 → 一对一式
   - 找点子 → 脑暴式
4. **每项议程都要有主责人和时间盒**。没有主责人的议程项等于没有议程。
5. **把风险与未决问题前置**，不要藏在文末附录里。

## 步骤

1. 收集输入（见铁律 1），同时记录阻塞项与待答问题。
2. 搜并读关键页面，把带出处的要点整理出来。
3. 选模板，改写成这次的议程：背景 → 目标 → 议程（含主责人/时间盒/期望产出）→ 要做的决策 → 风险 → 需要谁提前准备什么。
4. 附上资料来源链接与必读清单。
5. 需要外部事实支撑时补上调研要点，**注明出处，把事实与判断分开**。
6. 定下一步与责任人；产生了任务就在对应资料库建条目并关联。
7. 细节有变就更新页面，改过多次时留一行变更记录。

## 自检

- 参会人看完能答出"这次要定什么"
- 每项议程都有主责人和时间盒
- 有必读清单且链接可达
- 风险与未决问题写在显眼处
- 每个事实性说法都有出处

## 反面例子

- 只有"讨论 X"没有主责人和结论要求
- 不查过往记录，重复讨论已决事项
- 把调研结论和自己的猜测混在一起，读者分不清
- 材料发了但没说要谁提前准备什么
