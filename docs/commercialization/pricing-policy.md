# Aerie 定价与收费边界（投放测试版）

## 建议模型

Aerie 采用“免费本地核心 + Pro 软件订阅 + 云端用量透明计费”的三层模型：

| 层级 | 建议测试价 | 包含内容 | 云端调用 |
|---|---:|---|---|
| 免费本地版 | 0 元/月 | 本地聊天、基础记忆、单 Persona、单工作区 | 不补贴托管推理；优先使用用户自有模型或本地模型 |
| Pro 试用 | 0 元，14 天 | 多 Persona、工作流配方、主动提醒、Companion Studio 连接器 | 每月 500 次或 500,000 tokens 的试用额度 |
| Pro | 建议 29 元/月起 | Pro 功能、更新、支持和高级工作流 | 仍需用户自有 API key，或另行购买透明用量包 |

29 元是封闭投放的假设价格，不是已经开通的支付价格。先用两个价格变体（19/29 元）验证转化、退款和支持成本，再决定正式价。

## 收什么费用

软件订阅费支付产品能力：Persona 管理、工作流模板、主动调度、Studio 连接器、更新和支持。它不应伪装成无限模型额度。

API、ASR、TTS、RVC 等外部服务按实际用量单独处理：

1. 默认推荐用户填写自己的 API key，Aerie 不代收第三方费用。
2. 若未来提供平台代付，必须显示供应商、估算单价、当月用量和硬上限，按成本加固定服务费收取。
3. 未确认支付供应商、税务地区和退款规则前，不实现“已支付”状态，不在广告中写“无限调用”。

## 投放验收门槛

- 免费层不绑定信用卡，不因外部模型不可用而阻断本地聊天。
- 付费调用在请求前显示预计消耗，并在达到硬上限时停止，而不是静默降级扣费。
- 试用激活幂等，重复点击不会重复延长试用期。
- 退款、删除账户和导出 entitlement 状态必须在正式支付接入前定义。
- 广告只记录 `trial_started` 和真实 `subscription_created`；不上传聊天正文、音频、屏幕或 Persona 私密字段。

## 当前实现状态

`GET /api/billing/entitlement` 返回当前方案、功能列表、软件价格展示元数据、云调用/月度 token 限额和本地用量；`POST /api/billing/trial` 仅创建本地试用状态。两者都不代表真实支付，也不会产生第三方 API 账单。

封闭商业测试环境设置 `AERIE_ENFORCE_ENTITLEMENTS=1` 后，云调用会在请求前执行硬额度检查，成功响应按实际 token 记账；开发环境可保持 `0`，避免改变现有本地调试行为。
