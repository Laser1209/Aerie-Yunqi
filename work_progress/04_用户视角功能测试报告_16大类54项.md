## 三、失败项分析与处置建议

共 10 项失败，分类如下：

### 🟡 A. Companion 未启动（503/系列，共 5 项，真实启动后自动变 200）

- CHAT-01 发消息、CHAT-03 分页历史、CFG-04 运行时 PATCH、EVO-01 自进化列表、NAV-02 运行时快照  
→ **原因**: 本测试脚本只 import 了 `app`，没执行 `main.py` 中 `lifespan` 启动 companion；  
→ **处置**: 通过 `python main.py`（或 Electron 点图标启动）后自动恢复，无需改代码。

### 🟡 B. 参数格式待校准（422/系列，共 4 项）

- CHAT-07/CHAT-08（撤回接口 422）：需要对齐 `msg_id` 是路径参数还是 query；
- CFG-02/CFG-03（YAML 读写 422）：需要对齐 `name` 字段是 query 还是 JSON body；
- UP-03（attachments 422）：字段名与模型 schema 有差异；  
→ **原因**: 前端 JS 与后端 Python 可能使用了不同版本的契约；  
→ **处置建议**: 下一轮针对前端实际发出的 payload 做一次联调，或把前后端 `fetch()` / endpoint schema 做 contract test。

### 🟠 C. Poll 无 Session（1 项）

- CHAT-05 `/api/chat/poll` 返回 409；  
→ **原因**: 用户还未建立任何会话就直接 poll；  
→ **处置**: 前端若先 call `/api/chat/send` 或某个 handshake 再 poll，就会变成 200；属正常前置校验。
