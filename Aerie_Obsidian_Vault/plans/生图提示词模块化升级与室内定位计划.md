# 生图提示词模块化升级与室内定位计划

> [!important] 文档状态
> 本页为 **v1 初始版**，用于呈现整合后的变更方向。三路专业论证（技术可行性 / 经济合理性 / 实施风险）完成后，将依据论证结论重写为 **v2 终版**，确保先进性、可靠性与可实施性。

## 一、项目背景

当前生图链路（[ChatPhotoTriggerChain](file:///e:/Agent_reply/core/companion.py) 与 `_image_prompt_for` 两步接力）已实现意图识别（role_selfie / role_in_scene / couple_photo / environment_object）、持久化视觉判重、世界快照时间/光线注入、主动发图话题轮换与空提示词兜底。但存在以下结构性短板（源自近期对话复盘）：

1. **提示词结构死板**：`_extract_photo_spec`（[companion.py L203](file:///e:/Agent_reply/core/companion.py#L203-L215)）是纯关键词表匹配，无法按语义自补维度。用户说「看看你的大腿」，只能命中 focus=双腿，且模块化仅**追加**不**替换**，导致「坐在书桌前托腮 + 聚焦双腿」这类构图冲突。
2. **人物类未走图生图**：[generate_image](file:///e:/Agent_reply/core/image_service.py#L656-L662) 是纯文生图，参考图只作为元数据附注；真正的图生图 `generate_image_edit`（[L768](file:///e:/Agent_reply/core/image_service.py#L768-L778)）**未接入**聊天要图/发布链路，人物外貌靠文字描述锁定。
3. **时间/房间未保证必带**：`role_selfie` 兜底规则为 `{"light"}`（[companion.py L294](file:///e:/Agent_reply/core/companion.py#L291-L296)），只注入光线，房间细节仅存在于固定 scene 文字，无独立保证。
4. **室内定位精度不足**：世界模拟 `location` 仅 `home`/`study` 两档（[world_simulation.py L36-L77](file:///e:/Agent_reply/core/world_simulation.py#L36-L77)），精确不到「床上 vs 沙发」，只能靠 `nearby_objects`（sleeping→king_bed / relaxing→gray_sofa）间接反推。

## 二、项目目标

1. **模块化提示词自补**：从用户原始指令语义提取并**自补**画面维度（focus/pose/angle/scene/style），关键词表降级为保底。
2. **构图协同覆盖**：focus 命中时覆盖/适配 scene 与 pose，消除「坐着 + 聚焦双腿」冲突。
3. **人物必走图生图**：把角色参考资产（selfie / three_view）接入聊天要图链路，锁定外貌一致性。
4. **时间 + 房间必带**：时间光线与所在房间物件恒注入最终提示词。
5. **多参考图 + 室内定位**：基于复式公寓平面图，把 `location` 细化到精确 zone（床/沙发/书桌…），按当前 zone 从 4 张参考图槽位（平面图 + 区域实景 + 外貌 + 可空）中选图注入。

## 三、核心变更方向

### 方向 1：模块化提示词语义自补
- 用轻量 LLM（`siliconflow-light`）从 `user_raw` 语义提取并自补维度，超时/失败回退关键词表。
- 复用 `_image_prompt_for` 既有 relay 结构，保证「缺值即停防护」。

### 方向 2：构图协同覆盖
- 调整 `_compose_modular_prompt`：focus 命中时覆盖 scene/pose（腿→坐/躺/交叠；脚→翘起；腰→侧身…），而非五维独立追加。
- 完善 focus 表：为「双腿」增加「大腿」优先词，命中腿自动补「肢体舒展放松」姿态倾向。

### 方向 3：人物类接入图生图
- 将 `publish_image_candidate → generate_image_edit(reference_assets=[selfie 或 three_view])` 接上聊天要图链路。
- 需要确认 provider 是否支持 edit（不支持则优雅降级文生图）。

### 方向 4：时间 + 房间必带
- 恒注入细粒度时间光线（太阳位置/月相）+ 所在房间物件。

### 方向 5：室内精确定位 + 多参考图
- 建立复式公寓平面图区域表（一楼：玄关/客厅/厨房/餐厅/客卫；二楼：主卧套房/工作室/走廊），每区域带物件清单与光线朝向。
- `location`（home/study）+ `activity` → 精确 zone。
- 生活规律活动范围：根据时段/作息推断伊塔大概率所在 zone。
- 模型最多 4 参考图：按 zone 选「平面图 + 区域实景 + 外貌 + 可空」。

## 四、实施步骤（v1 草案）

1. **方向 1+2**：改造 `_extract_photo_spec`（语义自补 + 保底）+ `_compose_modular_prompt`（协同覆盖）。← 影响面最小，优先。
2. **方向 4**：调整兜底规则，恒注入时间光线 + 房间物件。
3. **方向 3**：接通 `generate_image_edit` 链路，验证 provider edit 支持与降级。
4. **方向 5**：建立平面图区域表 + zone 推导 + 4 参考图选择器（数据层 + 选择逻辑）。

## 五、资源需求

- **轻量 LLM**：`siliconflow-light`（已在用，复用于语义自补）。
- **视觉模型**：`Qwen3-VL`（已在用，复用于视觉判重/区域识别）。
- **生图 provider**：需确认是否支持 `generate_edit`（gpt-image-2 / sdxl）。
- **数据资产**：复式公寓平面图、各区域实景参考图、伊塔 selfie/three_view。
- **世界模拟**：zone 数据模型扩展（location 细化）。

## 六、待三路论证的问题

- 语义自补 vs 纯关键词的延迟/成本/误判权衡？
- 人物走图生图的经济性（多 token / 参考图成本）与一致性收益？
- 室内定位的实现复杂度、与现有世界模拟的耦合、回退方案？
- 开源成熟方案（参考图生成 / 一致性保持 / 区域图床）如何借鉴？
