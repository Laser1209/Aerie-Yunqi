## 启动方式与部署路径

- **后端启动**：`uvicorn` 提供 FastAPI 服务（主端口约定见修复记录中的端口隔离）。启动前必须清理 7890/7891 端口的孤儿进程，否则 uvicorn 在端口被占时调用 `sys.exit(3)` 抛出 `SystemExit` 导致崩溃（已含 `(Exception, SystemExit)` 双保险）。
- **桌面端启动**：`electron .` 启动主进程；构建为 Windows 安装包用 `npm run build:win`（electron-builder，nsis 目标，x64，`requireAdministrator`，`Aerie · 云栖`）。Electron 启动前同样需清理 7890/7891 孤儿进程，防止后端启动失败。
- **移动端网关**：7891 端口，启动前用 `socket.connect()` 预检测端口，被占则抛 `RuntimeError` 跳过启动。
- **测试**：后端 `pytest tests`；前端 `npm run check:all`（Electron）+ `node --test tests/*.test.js`（chat 契约）。
- **数据隔离**：状态文件默认服从 `AERIE_DATA_DIR` 或等价隔离根，避免回落到仓库相对 `data`。

## 架构机制

- 启动链路：先进入首页，再串联模块、技术、依赖、决策、审计、验证与证据。
- 配置加载：以 Vault frontmatter、计划文档和计划任务为主要配置源。
- 事件流/消息流：以审计发现、验证结果和证据登记为主线。
- 持久化策略：知识以 Markdown 页面保存，证据以路径与摘要保存。
- 错误处理：缺项标记为待核验，不以猜测替代事实。
- 权限与安全边界：不写入密钥、不伪造证据、不隐藏失败记录。
