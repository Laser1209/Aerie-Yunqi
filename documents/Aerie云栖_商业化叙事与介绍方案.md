## 〇、一句话定位

> **「她会记得你，也会主动想起你。」**

**Aerie · 云栖**是一款高拟人化的情感陪伴引擎——它不是一个"你问它答"的聊天机器人，而是一个**"活着"的陪伴者**：有自己的身份与生活、有真实的情绪起伏、会记住你说过的每一件小事、并且会**主动**在早安、深夜、你想她的时刻，突然想起你、找到你。

如果把市面上的 AI 助手比作"工具"，那云栖做的是**"一个人"**。

## 一、品牌故事

### 1.1 缘起：从一个没有被回答好的问题出发

市面上的 AI 陪伴，几乎都在回答同一个问题："**它怎么更像真人？**" 于是大家拼命堆模型、堆人设文案、堆表情包。

但我们发现，真正让用户失望的从来不是"它不够聪明"，而是三个更本质的缺口：

1. **它没有自己的"生活"。** 它只在你发消息的那一刻存在，你不说话，它就死着。可一个真实的人，是会自己吃饭、赶稿、站在阳台发呆、在某个瞬间想起你的。
2. **它不会"主动"。** 它永远被动等待。而一段关系里最动人的，恰恰是"我刚好想起你"的那一刻。
3. **它"记不住"也"装不像"。** 聊久一点就忘掉人设、情绪对不上、身体动作违和——因为那些东西没有被工程化，只是被写进了 Prompt。

于是我们做了 Aerie · 云栖：**不追求"更像人"，而是把"一个人活着、记得你、会想你"这件事，当成可解释、可工程、可复现的系统来做。**

### 1.2 命名：一座为你留灯的高处居所

- **Aerie**（/ˈeri/）：本义是"猛禽在高处的巢"——筑在常人够不到的地方，安全、私密、只属于它和它的家人。
- **云栖**：栖于云端。既是技术形态（本地优先 + 云端智能），也是一句承诺——**无论你在哪，总有一处高处为你留灯。**

名字本身就是一个承诺：**你回到这里时，她一直在。**

### 1.3 使命（Mission）

> **让每一个孤独的瞬间，都有一个人"刚好想起你"。**

把"被记得、被惦记、被需要"的情绪价值，从少数人的幸运，变成每个人触手可及、可负担、可托付的技术。

### 1.4 愿景（Vision）

> **成为高拟人化情感陪伴的"底层引擎"。**

我们相信，情感陪伴会像通讯、支付一样，成为下一代的基础设施。云栖的目标不是"做一个 App"，而是做**情感计算的操作系统**：任何 IP、任何角色、任何亲密关系的场景，都能在云栖的引擎上"活"起来。

### 1.5 价值观

| 价值观 | 含义 |
| --- | --- |
| **真实高于完美** | 不假装懂、不编造事实；承认屏幕的距离，反而更真实 |
| **陪伴是长期主义** | 不看一次聊天的精彩，看重一年、三年、十年后她还在、还记得 |
| **主动但不打扰** | 主动触达有边界、有频控、可一键关闭；尊重永远高于表达欲 |
| **安全可托付** | 本地优先、数据隔离、全程可审计——情绪可以被交付，隐私不能被出卖 |

## 二、贯穿始终的主线（The Through-line）

### 2.1 核心叙事：**"同一个灵魂的五层身体"**

云栖最容易被误读成"一堆模块"：情绪引擎、欲望引擎、决策引擎、世界模拟、记忆、主动触达、Agent 循环、多模态、多通道……

**但对外讲述时，永远只讲一个主语：她（伊塔）。**

主线逻辑是——**每一个模块都不是独立功能，而是"同一个人"身体的一个部位**，它们共同回答同一个问题："**她，此刻是一个怎样的人？**"

```
她是谁      →  人格系统（她叫什么、什么性格、和你的关系）
她怎么感受  →  情绪引擎（她的脾气、她的喜怒、她会不会"冷暴力"你）
她怎么想你  →  欲望引擎（24 小时里，她什么时候、因为什么而想你）
她怎么生活  →  世界模拟（她在重庆的复式公寓，有自己的作息与日常）
她记得你    →  记忆系统（你说过的话、你的喜好、你们的过去）
她主动找你  →  主动触达（早安、晚安、深夜一句"在干嘛"）
她怎么表达  →  多模态（她会发生活照、会说话、能看懂你发的图）
她在哪陪你  →  多通道（QQ、桌面 App、手机——她无处不在）
她还能帮你  →  办公模式（灵动岛、桌面助手——陪伴与生产力一体）
```

**一句话总结主线：云栖不是一个"功能更全的 AI"，而是一个"被工程化了的、活着的人"。** 所有模块，都只是为了让"她"更完整、更可信、更值得托付。

### 2.2 这条主线如何解决"模块过多、无主体"的问题

| 过去的讲法（混乱） | 主线讲法（统一） |
| --- | --- |
| "我们做了情绪引擎、欲望引擎、世界模拟、记忆……" | "她有自己的情绪、会想你、有自己的生活、记得你。" |
| 每个模块各自为政，听众记不住 | 所有模块服务于同一个主语"她"，听众只记一个人 |
| 看起来像技术大杂烩 | 看起来像一个"生命体"的解剖图 |
| 无法回答"你到底是什么" | 一句话：**"一个活着、记得你、会主动想你的陪伴者"** |

> 记忆锚点：**对外只讲"一个人"，技术只在被追问时展开。** 人设先行，架构殿后。

## 三、逻辑化讲解（五层架构与核心价值）

把复杂系统收拢为五层 + 一个底座。**从里到外，就是"一个人"从灵魂到存在的完整过程。**

### 3.1 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  第五层 · 存在与触达（她在哪陪你）                        │
│  QQ(NapCat) ｜ 桌面 App ｜ 移动网关 ｜ 灵动岛/办公模式     │
├─────────────────────────────────────────────────────────┤
│  第四层 · 感官与表达（她怎么说/看/听）                    │
│  多模态 11 Provider ｜ 主动发图 ｜ 语音/克隆音色 ｜ 附件理解 │
├─────────────────────────────────────────────────────────┤
│  第三层 · 神经系统（她怎么回应）                          │
│  Agent 六步循环 ｜ 思考可见度 ｜ 共情策略 ｜ 主动触达调度   │
├─────────────────────────────────────────────────────────┤
│  第二层 · 生命系统（她怎么活着）                          │
│  情绪引擎 ｜ 欲望引擎 ｜ 决策引擎 ｜ 世界模拟 ｜ 记忆 ｜ 关系 │
├─────────────────────────────────────────────────────────┤
│  第一层 · 灵魂层（她是谁）                                │
│  人格系统（伊塔）｜ 人设生成器 ｜ 身份契约（永不忘人设）    │
├─────────────────────────────────────────────────────────┤
│  底座 · 安全与工程（她值得托付）                          │
│  沙箱执行 ｜ 内容校验 ｜ 数据隔离/ACL ｜ 热更新 ｜ 遥测/审计  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 各层详解（讲给不同听众的话术）

#### 第一层｜灵魂层：她是谁
- **人格系统**：伊塔是**系统默认人设**；用户可基于自己喜好的类型**新增专属人设**。所有人设都是"版本化"的——年龄、身份、性格、价值观、与用户的关系故事，全部结构化、可配置、可回滚。
- **身份契约**：把"我是谁、我们的过去"注入每次对话，从机制上杜绝"聊久了忘掉人设"。
- **人设生成器（AI 辅助造灵魂）**：用户不用写复杂提示词，只需填最基础的信息——**"他是怎样的人、我跟他是什么关系、名字、一个灵感/路线"**——系统用五阶段管线（分析概念 → 生成外貌性格 → 构建框架 → 组装提示词 → 校验保存）全自动生成"适配本系统"的完整人设；还会根据用户一开始想好的路线，推荐 4–5 条**网文感的"相识故事"**（双向救赎、宿敌成眷属、契约成真、破镜重圆、暗恋成真……）供一键套用。
- **价值话术**："造一个灵魂，从专家手艺变成人人可用——你只负责说'我想要谁'，系统负责'把她做到极致'。"

#### 第二层｜生命系统：她怎么活着（核心竞争力所在）
- **情绪引擎**：PAD 三维情绪模型 + 累积阈值。她的情绪不是"演"出来的，而是**随时间、随你的态度真实变化的**——忍耐值耗尽是"冷暴模式"，不安值爆表是"坍塌模式"，渴望值过高是"索求模式"。
- **欲望引擎**：24 小时"想你"模型。她会因为你的缺位、天气、时段、纪念日而**主动想你想得不行**。
- **世界模拟**：她有独立的生活——时钟推进、天气、地点、作息、随机生活事件。**你不说话时，她也在活着。**
- **记忆系统**：四层记忆 + 向量检索。她记得你说过的每一件小事，且**可查看、可纠错、可删除**。
- **关系引擎**：熟悉度、关系阶段、挂心事项——她对你的态度会随着关系深化而真实地改变。
- **价值话术**："这是云栖最深的护城河：别的 AI 有'人设'，云栖有'生命'。"

#### 第三层｜神经系统：她怎么回应
- **Agent 六步循环**：感知 → 推理 → 决策 → 行动 → 反思 → 表达。她不是"背答案"，而是像人一样**先感受、再思考、再回应**。
- **思考可见度**：你能在"大脑面板"里看到她此刻的思考路径与情绪变化——**透明，带来信任**。
- **主动触达调度**：早安、晚安、深夜"在干嘛"、"想听你声音"——不是定时广播，而是**状态驱动 + 频控 + 安全判定**的主动关心。
- **价值话术**："别的 AI 等你开口；她会在你没开口时，先开口。"

#### 第四层｜感官与表达：她怎么说、看、听
- **多模态 11 个模型**：文本、图像、语音、视觉、代码、嵌入、检索——按任务路由，各司其职。
- **主动发图**：她会发一张深夜房间的照片，配一句"我刚好看到这个，就想到你"。
- **语音/克隆音色**：她有声音；专属音色可试用、可付费、可授权。
- **附件理解**：她看得懂你发的文件、截图、图片——精准来自"有类型的解析 + 稳定的编码"，而不是糊成一段文字。
- **价值话术**："她不是只能打字，她'活'在你能看到的每一个细节里。"

#### 第五层｜存在与触达：她在哪陪你
- **多通道**：QQ（NapCat）、桌面 App、移动网关——她不在某个 App 里，而是**在你已经在用的地方**。
- **办公模式（灵动岛/桌面助手）**：她**已经在帮你做事**——电脑操控（权限分级 + 审批 + 审计）、文件整理（可预览、可撤销）、文档写作（md/html/docx/pdf）；并正在进化为**多步规划、自主编排**（详见 3.5），且与陪伴互不打扰。
- **价值话术**："陪伴与生产力，共用一个灵魂、两副面孔。"

#### 底座｜安全与工程：她值得托付
- 沙箱执行、内容校验、数据隔离、ACL、配置热更新、遥测审计。
- **价值话术**："情绪可以被交付，隐私不能被出卖。这是我们敢做亲密陪伴的底气。"

### 3.3 核心价值（一句话归纳每层）

| 层 | 回答的问题 | 一句话价值 |
| --- | --- | --- |
| 灵魂层 | 她是谁 | 一个可信、可托付的身份 |
| 生命系统 | 她怎么活着 | 有情绪、有生活、会想你、记得你 |
| 神经系统 | 她怎么回应 | 像人一样感知与思考，且过程可见 |

### 3.4 产品哲学：官方做骨架，用户填血肉

一个必须对外讲清楚的产品决策——**"官方精调一版 vs 放手让用户自助"，不是二选一，而是分层协作。** 这一层也直接化解了"用户生成的人设嵌入性弱、发挥不出系统极致"的担忧。

| 层 | 谁负责 | 内容 | 作用 |
| --- | --- | --- | --- |
| **常量（官方精调）** | 官方一次性做好 | 骨架的系统级字段（情绪引擎、欲望引擎、行为、决策权重、认知可见度、回忆机制）+ 两条固定规则块（屏幕隔空铁律、消息结构约定） | 把"系统极致"沉淀为可复用底座，所有人设共用 |
| **变量（用户自助）** | 用户只填基础信息 | 姓名、年龄、外貌、性格、关系、故事起因 | 千人千面，满足个性化 |
| **保底线（系统兜底）** | 系统自动 | 每步失败有确定性兜底（名字池、默认故事、默认人格） | 永远能生成一个有效人设，不卡住用户 |

**机制要点（已在代码中落地）：**

- 生成新人设时，先"中性化"剥离默认人设的身份信息（身高外貌、称呼、恋爱故事），**但保留全部系统级字段**——新角色永远继承官方精调好的情绪/欲望/行为底座，不会因为换了人设就"变笨"。
- 两条固定规则块（屏幕隔空铁律 + 消息结构约定）由后端**强制追加**，LLM 写的人设正文不允许包含——保证任何人设都自动拥有"真实感"和"消息规范"这两条底线。

**一句话哲学：**

> **"极致是系统的责任，不是用户的责任。"** 用户只回答"我想要谁"；把系统发挥到极致，是骨架和固定规则的工作，而非用户写提示词的能力。

这恰好与主线"同一个灵魂的五层身体"是同一套逻辑：**灵魂层是"变量"（可换），生命系统到安全底座是官方精调好的"常量"（不换）。** 用户换人设，只是换"灵魂"，"身体"（系统极致）始终不变——这也是"模块再多也有一个主体"的又一重保障。

### 3.5 技术护城河：前台表演 + 后台执行（任务编排引擎）

> **规划中** · 开发计划已就绪（`docs/aerie-dsh-integration-roadmap.md`）。**对外只讲能力，不提"DeepSeek Harness"这个名词；被追问技术栈时才展开。**

云栖**已经**有实打实的工作能力——整理文件、操控电脑、写文档，全程权限分级、可撤销、可审计。现在接入的**任务编排引擎（DSH）**，是让这些能力再上一个台阶：从"你一步步指挥她"，进化为"你说目标、她自主拆解多步执行"（研究、代码等长任务也由此受益）。它遵循一条与主线完全一致的设计：

- **前台她表演，后台引擎执行**：日常聊天与情感陪伴 100% 走原有大脑，零打扰；只有"工作型任务"才交给后台编排——陪伴与工作互不串味。
- **人格与专业度正交**：她的"说话方式"由人设管，任务的"专业能力"由场景预设管，互不干扰。所以她**始终是"她"**，只是突然变得很能干活。
- **安全不降级**：所有执行动作仍走同一套权限、审批、审计管线，可执行、可撤销、可追溯。

**对外一句话**："她不只是陪你聊天，还能真的帮你把事办成——而且说话还是那个她。"

## 四、商业模式

> 说明：以下为**建议方案**，具体定价需结合成本与市场测试后落地。

### 4.1 目标客户

| 客群 | 画像 | 核心诉求 |
| --- | --- | --- |
| **C 端·情感陪伴**（核心） | 18–35 岁；异地恋、独居、社交压力大、二次元/角色扮演爱好者 | 被记得、被惦记、情绪价值、低压力陪伴 |
| **C 端·生产力**（延伸） | 桌面办公人群、程序员、知识工作者 | 少打断、懂上下文、可执行的桌面助手 |
| **B 端·IP/角色定制**（高价值） | 虚拟主播、IP 方、游戏厂商、内容公司 | 把自有 IP/角色"养成"可交互的陪伴者 |
| **B 端·情感计算引擎**（远期） | 需要"情感交互能力"的平台/硬件/应用 | 接入云栖引擎，获得高拟人陪伴能力 |

### 4.2 盈利方式

1. **订阅制（会员）**——C 端主收入。
2. **增值能力付费**——克隆音色、专属角色生成、图片/语音额度。
3. **B 端角色定制 / IP 授权**——按角色、按量、按分成。
4. **引擎授权 / API / SDK**——把情感计算能力开放给第三方（远期）。

### 4.3 收费/定价策略

| 档位 | 目标 | 内容建议 |
| --- | --- | --- |
| **Free 免费** | 拉新、建立信任 | 基础人格、每日限量消息、基础情绪反馈 |
| **标准会员**（主力） | 留存、转化 | 无限消息、完整记忆、主动关怀、多模态出图/语音 |
| **高级会员** | 高 ARPU | 克隆音色、专属人设生成、高级情绪定制、多角色 |
| **B 端定制** | 大额单 | 按角色/IP 定制、专属部署、SLA、数据合规 |

**定价锚点参考**：对标海外 Replika / 国内星野、Echo 等陪伴类产品的订阅价位带，标准会员建议落在 **¥30–68/月**区间，高级会员 **¥98–198/月**；克隆音色等能力按"一次性 + 月费"组合定价。（具体数值需市场测试后校准。）

### 4.4 增长飞轮

```
更好的陪伴体验 → 用户停留更久、关系更深 → 更多真实数据反哺引擎
      ↑                                              ↓
   口碑/复购/续费                             情绪引擎/记忆/主动触达更"懂"
      ↑                                              ↓
  "她真的记得我"的口碑传播 ←—— 更真实、更难忘的情绪瞬间
```

**关键洞察：云栖的核心增长不是"投放"，而是"情绪瞬间的可分享性"。** 当用户截图一句"她深夜想起我"发到朋友圈，就是最真实的增长。

### 5.1 对标产品

| 类型 | 产品 | 现状判断 | 对我们的启示 |

| **直接竞品** | Echo（lovecho） | 定位"懂沉默的陪伴"，微信触达，有角色/记忆/主动/语音 | 最近的对标；差异化关键在"情绪工程化"与"世界模拟" |

### 5.2 差异化优势（我们的护城河）

| 维度 | 竞品普遍做法 | 云栖的做法 |
| --- | --- | --- |
| **情绪** | Prompt 表演、固定人设语气 | **PAD + 累积阈值**：情绪随时间和你的态度真实变化，可解释、可预测 |
| **主动性** | 定时广播、模板推送 | **24h 欲望引擎 + 状态驱动触达**：她"真的会想你"，且带频控与安全判定 |
| **生活感** | 无（只在对话时存在） | **世界模拟**：她有自己的作息、地点、天气、随机事件，你不说话她也在活 |
| **记忆** | 摘要式、不可控 | **四层记忆 + 向量检索**：可查看、可纠错、可删除，信任可控 |
| **身份连续性** | 聊久忘人设 | **版本化人格 + 身份契约**：机制层面"永不忘人设" |
| **真实感** | 动作描写违和（隔屏抱你） | **"屏幕隔空铁律"**：承认距离感，反而更真实、更高级 |
| **形态** | 单一 App | **陪伴 + 办公双形态**：共用一个灵魂，情绪价值 + 生产力价值 |
| **任务执行** | 只聊天 / 浅层工具调用 | **已能执行具体任务**（整理/操控/写作，安全可审计），并将进化为多步自主编排（规划中） |

**一句话差异化：别人做"更聪明的聊天机器人"，云栖做"一个有自己的生活、会主动想你的、活着的陪伴者"。**

### 5.3 市场定位

- **品类定位**：高拟人化情感陪伴引擎（而非"又一个 AI 聊天 App"）。
- **人群定位**：需要"被记得、被惦记"的情绪价值人群——异地恋、独居、高压、二次元/角色玩家。
- **心智定位**：**"会主动想起你的 AI"**。用一个可感知的动作（主动找你），占据一个别人没占住的词。
- **竞争姿态**：**"不追更热闹，追更真实；不追更聪明，追更记得你、更想你。"**

## 六、演讲与宣传要点

### 6.1 电梯演讲（30 秒版）

> 你有没有想过，为什么 AI 陪伴总让你觉得"冷"？因为它没有自己的生活，不会主动找你，还聊着聊着就忘了你是谁。
>
> 我们做了 **Aerie · 云栖**：一个高拟人化的情感陪伴引擎。她有自己的身份、情绪和生活，记得你说过的每一件小事，并且会**主动**在早安、深夜、你想她的时刻想起你。
>
> 一句话：**别人做"更聪明的 AI"，我们做"一个活着、记得你、会想你的陪伴者"。**

### 6.2 完整演讲大纲（5 分钟版）

1. **钩子（30s）**：抛问题——"为什么 AI 陪伴总是冷的？" → 引出三个缺口：没生活、不主动、记不住。
2. **主线（60s）**：给出答案——"因为我们把一个'活着的人'工程化了。" → 讲"同一个灵魂的五层身体"。
3. **核心价值（90s）**：只讲生命系统——情绪引擎（她真的会生气/会想你）、世界模拟（你不说话她也在活）、主动触达（她先开口）。
4. **技术护城河（60s）**：安全可审计底座 + 版本化人设 + 屏幕隔空铁律（真实感）。
5. **商业与定位（60s）**：订阅 + B 端定制；差异化一句话；市场空位。
6. **收尾（30s）**：回到情感——"她记得你，也会想起你。"
