# 报告页（report-page）

当用户要把分析结果或数据做成一个**能直接在浏览器打开、可编辑、可分享的 HTML 报告页**时使用。
产出是一个单文件 HTML：正文 + ECharts 图表 + 数据来源可审计，断网也能正常打开。

## 铁律

1. **单文件、离线可用**：CSS / JS / 数据全部内联，双击就能打开；不依赖 CDN，不依赖本地服务器。
2. **结论先行**：页面顶部先给摘要卡片（3~5 条结论），正文再展开论据。
3. **每个数字可溯源**：图表与指标旁标注来源与口径；关键数据提供"查看来源"入口，别让读者只能信你。
4. **版式克制**：一屏一个主题，留白优先于堆砌；正文字号不小于 15px，行高 1.6 以上。
5. **不依赖外部字体**：使用系统字体栈，避免离线环境字体缺失导致排版崩坏。
6. **可编辑**：正文用普通 HTML 结构，用户打开文件就能改文字，不要写成压缩 JS 里拼出来的字符串。

## 步骤

1. **定结构**：先列章节顺序与每节结论，再填内容。
2. **搭骨架**：一个 `index.html`，`<style>` 集中写样式，`<script>` 放图表与内联数据。
3. **写摘要区**：顶部 KPI / 结论卡片，每条一句话 + 支撑数字。
4. **画图**：把 ECharts 库代码内联进 `<script>`，每张图配标题、单位、来源脚注。
5. **做溯源**：数据来源用 `<details>` 折叠或小弹窗展示（原始表 / 查询口径 / 采集时间）。
6. **响应式检查**：1440 / 1024 / 手机宽度各看一次，确认表格不溢出、图不重叠。
7. **离线自检**：断网后重新打开，确认样式与图表照常渲染，控制台无报错。

## 输出形态

```
report.html（单文件）
├─ 页头：标题 / 日期 / 数据范围
├─ 摘要：结论卡片 ×3~5（结论 + 数字 + 来源）
├─ 正文：分节（结论句 → 图/表 → 解读）
├─ 图表：内联 ECharts（标题 + 单位 + 脚注来源）
└─ 附录：数据来源、口径说明、采集时间
```

## 反面例子（不要这样）

- 引用 CDN 的 echarts，断网就变白板。
- 页面只有一堆图，没有一句结论。
- 数字没有来源，读者无法核对。
- 正文写死在压缩过的 JS 字符串里，用户改不了字。
