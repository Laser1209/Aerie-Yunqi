# UI 代码审查清单（web-design-guidelines）

在交付或评审前端界面代码时，用它逐条核对。目标是**可访问、可键盘操作、对比达标、语义正确**——这些是底线而不是加分项。发现问题必须给出片段与具体修法，不接受"整体看着还行"。

## 铁律

1. **语义先行**：该用 `<button>` 的地方别用 `<div onclick>`，该用 `<nav>/<main>/<header>` 别用一堆 `<div>`，屏幕阅读器靠标签判断结构。
2. **对比度达标**：正文文字与背景对比度不低于 4.5:1，大号文字（≥18.66px 粗体或 ≥24px）不低于 3:1。这能算出来，别凭眼睛猜。
3. **键盘可达**：所有交互元素 Tab 能聚焦、Enter/Space 能触发、焦点顺序符合视觉顺序，且焦点样式清晰可见。
4. **图片有替代文本**：功能性图片写描述性 `alt`，纯装饰图用 `alt=""`，绝不留 `alt` 缺失。
5. **表单有可访问标签**：每个输入用 `<label for>` 关联或加 `aria-label`，错误提示要与字段关联且不能只靠颜色表达。

## 步骤

1. **看结构**：核对 landmark（header/nav/main/footer）、标题层级（h1 唯一且不跳级）、列表与表格是否用对标签。
2. **量对比**：逐个检查文字、图标、边框与背景的对比度，标出所有低于阈值的组合并给出替换色值。
3. **走键盘**：只按 Tab / Shift+Tab / Enter / Space / Esc，能否完成所有操作、有无键盘陷阱、焦点会不会丢失。
4. **查替代内容**：图片 alt、图标按钮 `aria-label`、纯装饰元素 `aria-hidden`。
5. **查表单**：label 关联、必填标识、错误提示可读性与关联性、`autocomplete` 属性。
6. **查动效**：是否有 `prefers-reduced-motion` 兜底，有无每秒超过 3 次的闪烁。
7. **查细节**：页面 `lang` 属性、文字放大 200% 不破版、信息不单独依赖颜色传达。

## 反面例子（不要这样）

- 只回一句"整体没问题"，不给具体行号和改法。
- 把纯装饰图也强行要求写详细 alt，制造噪音。
- 只用红字表示错误却不给文字说明，色盲用户无法识别。
- 只检查视觉，完全不管键盘操作与屏幕阅读器。
