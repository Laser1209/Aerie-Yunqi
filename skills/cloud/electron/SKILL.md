# Electron 自动化（electron）

当你要通过 Chrome DevTools Protocol（CDP）自动化一个 Electron 桌面应用——连上它、读取界面、点击操作、抓日志——时走这份流程。产出是**可复现的操作序列与观测证据**，说明某个界面行为是否正常。

## 铁律

1. **先开调试端口再连**：Electron 应用要以 `--remote-debugging-port=<port>` 启动，或用调试方式附加，没有端口就连不上。
2. **连的是渲染进程的页面**：Electron 每个窗口对应一个 CDP target，先列出 targets 找到目标窗口，再挂到它上面操作。
3. **定位要稳**：优先用可访问性角色、标签、测试 id，避免依赖会随主题或语言变化的文案与层级。
4. **等待条件而非固定延时**：等元素出现或状态变化，而不是 sleep；桌面应用启动慢，硬等既慢又不稳。
5. **抓主进程与渲染进程日志**：界面异常常伴随主进程报错或渲染进程 console 报错，两边都要收。
6. **原生弹窗要单独处理**：文件选择、系统菜单这类系统级窗口 CDP 管不到，涉及时要明确说明并改用其他手段。

## 步骤

1. **确认启动方式**：查清应用如何带调试端口启动，记录端口号。
2. **列出 targets**：请求 `http://127.0.0.1:<port>/json`，找到目标窗口的 target。
3. **连接并截图**：附到该 target，先截一张图确认连的是对的应用与页面。
4. **读取界面**：导出可访问性树或关键元素，了解当前有哪些可操作项。
5. **执行操作**：按用户路径点击、输入、切换菜单，每步都用稳定定位。
6. **断言与观测**：对关键节点检查元素状态或文本，收集 console 与主进程日志。
7. **记录证据**：截图加日志加操作步骤，形成可复现结论。

## 输出形态

```
## 应用与连接
- 应用：<name>  调试端口：9222
- target：<title/url>

## 操作序列
1. 点击侧栏"设置" → 断言出现"偏好设置"标题 ✓
2. 输入 … → 断言 … ✗

## 日志摘要
- 渲染进程 console errors: 1  —— TypeError: xxx
- 主进程：无

## 结论
- 设置项保存后未生效，疑似前端未提交
```

## 反面例子（不要这样）

- 应用没开调试端口，脚本一直连不上还反复重试。
- 连到错误的窗口（比如隐藏的后台窗口）就下结论。
- 用 sleep 等界面就绪，机器一慢全崩。
- 想用 CDP 去操作系统文件选择框，方向就错了。
