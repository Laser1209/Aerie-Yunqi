# 关系状态机 —— 设计方案

- 日期：2026-09-20
- 状态：设计已定稿，待复核后转入实施计划
- 范围：关系从「描述态」改为「运行态」。关系可推进、可回退、可失败、可解释

---

## 1. 背景：问题诊断

### 1.1 一句话

系统在**描述**一段已经发生的关系，而不是**运行**一段正在发生的关系。描述可以无限加形容词，运行只能靠事件累积。这是「设定越塞越空」的机制根源。

### 1.2 四条证据

**证据一：「恋人」是写死的常量**

`config/persona.yaml` 的 `relationship_story` 是一整段完成时恋爱史，由 `core/context_builder.py:1043-1050` 在每次 FULL 对话的 system prompt 头部原样注入，并附「不得编造或遗忘」。

→ 她每次开口之前关系已被判定完毕。第一轮和第 300 轮没有区别。

**证据二：状态层是陌生人，而且是永远陌生**

`core/companion_state.py:82` 的 `relationship_stage` 默认 `stranger`，但全仓库生产代码中只有 `core/proactive_candidates.py:129` **读**过它；`advance_relationship_stage()` / `set_relationship_stage()` **没有任何生产调用点**。

→ prompt 层是 `intimate`，state 层是 `stranger`。五级阶梯是一台没通电的电梯。

**证据三：关系数值出厂即「已亲近」，且不落盘**

`core/relationship_engine.py:21-30` 初始值 attachment 0.55 / trust 0.60 / care 0.65 / security 0.55。学习率 0.08，单轮最多推动约 0.05；负向只扣 trust/warmth，不扣 attachment/care（`L72-L77`）。`world_port` 全链路无持久化写入点。

→ 涨得慢、跌不了、重启归零。不可失去的东西没有分量。

**证据四：人格与关系焊死**

`relationship`（关系类型 / 亲密称呼 / 恋爱故事）在 persona schema 里是 `core/persona_hub/persona_validator.py:27-42` 的必填同级字段。更直接的证据：`config/persona.yaml:94` 把「恋人」写进了职业字段。

```
occupation: 独立设计师 / 工作室主理人 / 恋人 / 高拟人化智能伴侣
```

启动时 `core/companion.py:3049-3095` 还会把「恋爱故事 / 关系」以 **importance=10（最高档）** 写进长期向量记忆。

→ 记忆库里最重的三条是**声明**，不是**经历**。系统一直在积累设定，没在积累历史。

### 1.3 附带问题：主动性建立在亲密前提上

`config/persona_behavior.yaml:26-71` 渴望槽开局 55 / 阈值 80，主力变量是 `user_absence_hours`（你越不来，我越想你需要你）。`anniversary_boost` 在没有共同经历时就已生效。

→ 一个刚认识你的人没有资格想你想得睡不着；主动推送要么越界，要么虚假。

## 2. 目标与非目标

### 2.1 目标

1. 关系有**可配置的起点**，从低处开始，靠事件累积
2. 关系可**推进也可回退**，且回退是缓慢的、有因的、非断崖的
3. 关系可**失败**：「一直是朋友」是正当终局
4. 关系可**被解释**：能回答「为什么她变冷了」
5. 关系状态**驱动人格表达**，而不是人格文件声明关系
6. 主动性按关系阶段**解锁权限**，不再无差别越界

### 2.2 非目标

| 不做 | 理由 |
|---|---|
| 分手 / 复合循环 | 研究显示循环次数越多，满意度/承诺越低、冲突与心理痛苦越高，且痛苦随时间累积不衰减；伤害集中在依恋焦虑型用户。改为「危机可赢回」 |
| 中国特有的「家庭介入期」（彩礼/婚房/户口） | 与产品形态无关 |
| 用不确定性/变动奖赏提升粘性 | 中国《人工智能拟人化互动服务管理暂行办法》第八条禁止「诱导情感依赖」；加州 SB 243 直接禁止「以不可预测的间隔提供奖励」 |
| 排他性表达 | 同上，且属于永久红线 |
| 对话中显示关系数值 | 沿用 `context_builder.py:144-160` 既有原则「关系数值只用于调节语气，不得直接报数」 |

### 2.3 交付边界

当前为**个人自用**。安全层作为独立的开关式模块**预留架构位置**，默认只开基础项；对外前再补全。目标是不让合规成为将来的架构障碍。

## 3. 核心设计

### 3.1 关系状态的形状：两轴 + 六维

现有模型是单轴 5 级阶梯（`stranger → acquaintance → familiar → close → intimate`），缺陷是把「朋友」和「恋人」压缩成同一条线上的两个刻度——**深度**和**类型**被混为一谈。

研究上二者本就正交：Sternberg 区分「喜欢（仅亲密）」与「浪漫之爱（亲密 + 激情）」；社会渗透论中「男闺蜜」是深度很高但制度性承诺为零的典型。

#### 轴一：深度 depth（可升可降）

```
0 陌生   1 初识   2 熟悉   3 亲密   4 深度绑定
```

#### 轴二：类型 type（由双向门决定，可退回）

```
undefined  →  friend  /  lover
```

**地板**：`depth` 锁在 1，不会归零到「不认识」。这是「关系会淡但不会消失」的机制保证。

#### 六个数值维度

替换现有 8 个（attachment / care / warmth / engagement / security / user_trust / conflict / trust）。现有 8 个的问题是语义互相重叠，且全部 0.5 起步——出厂即亲近。

| 维度 | 含义 | 初始 | 触顶 | 出处 | 会降 |
|---|---|---|---|---|---|
| `intimacy` | 自我暴露的深度与广度 | 0.05 | 1.0 | Altman & Taylor 社会渗透理论 | 是 |
| `trust` | 信任 | 0.10 | 1.0 | Rusbult；Gottman | 是 |
| `satisfaction` | 满意度（收益 − 成本） | 0.35 | 1.0 | Rusbult 投资模型核心变量 | 是 |
| `investment` | 共同历史的总量 | 0.00 | 无上限 | Rusbult 投资量 | **否（单调不减）** |
| `repair` | 修复能力（冲突后能否修回） | 0.30 | 1.0 | Gottman 分水岭变量 | 是 |
| `tension` | 未消化的张力存量 | 0.00 | 1.0 | Gottman 四骑士 | 是（随时间衰减） |

三个设计要点：

1. **`investment` 只增不减**——它是「你们发生过的事的总量」。这使它在危机时刻成为关键变量：满意度崩了，但投资量高 + 修复能力高 → 她愿意给机会。「危机可赢回」的机制来源是数值，不是随机。
2. **删掉「替代选择质量」**——Rusbult 公式为 `承诺 = 满意度 + 投资 − 替代选择`，但 AI 伴侣场景下没有「别人」。这是模型应有的简化。
3. **`tension` 的衰减速度需略慢于正向事件的补充速度**——Gottman 测出幸福伴侣冲突中正负比 **5:1**，走向破裂者 **0.8:1**。参数默认值参照此比值，避免「一次吵架永久变冷」的失真。

### 3.3 事件系统

#### 三类信号源

| 来源 | 能拿到什么 | 判定方式 |
|---|---|---|
| 消息元数据 | 谁发起、间隔多久、回复多快、聊多长、连续几天 | 纯规则，100% 确定 |
| 消息内容 | 是否分享私事、称呼变化、是否引用她说过的话、是否试探关系 | **受限 LLM 分类**（只输出枚举，不打分） |
| 系统状态 | 世界模拟事件、危机、双向门表态 | 纯规则 |

#### 判定分工（关键约束）

> **LLM 只回答「有没有」，不回答「多重」。**
>
> 大模型存在讨好倾向（研究指其附和用户观点的频率比人类高约 50%）。若由它判断「这件事让关系升了多少」，结果必然只涨不跌，与「可失败」直接冲突。因此 LLM 输出被约束为枚举（如 `self_disclosure: yes/no`），**强度由规则表定死**。

#### 事件词表

**正向**

| event_type | 观测方式 | 主要影响 |
|---|---|---|
| `user_references_past` 引用她过去说过的话 | 内容比对历史消息 | `investment` ↑↑ `trust` ↑ |
| `user_shares_private` 分享私事 | LLM 分类 | `intimacy` ↑↑ |
| `user_asks_about_her` 关心她而非只谈自己 | LLM 分类 | `satisfaction` ↑ |
| `user_initiated` 久未联系后主动开启 | 元数据 | `intimacy` ↑ `investment` ↑ |
| `deep_session` 单次深聊 | 元数据 | `intimacy` ↑ |
| `address_shift_intimate` 称呼变亲密/独占 | 规则提取 | `intimacy` ↑↑ `satisfaction` ↑ |

`user_references_past` 是最硬的一条信号：它证明「他记住了」，而「我想你」只证明「他表达了」。记忆类行为完全可规则化验证。

**负向**

| event_type | 观测方式 | 主要影响 |
|---|---|---|
| `contempt` 蔑视/嘲讽 | LLM 分类 | `tension` ↑↑↑ `trust` ↓↓ |
| `criticism_personal` 人格层面批评 | LLM 分类 | `tension` ↑↑ `satisfaction` ↓ |
| `promise_broken` 失约/食言 | LLM 分类 | `trust` ↓↓ `satisfaction` ↓↓ |
| `boundary_violation` 边界侵犯 | LLM 分类 | `tension` ↑↑ |
| `contradiction_caught` 前后不一致被抓到 | LLM 分类 | `trust` ↓↓ |
| `stonewalling` 长时间冷处理 | 元数据 + 内容 | `tension` ↑↑ `repair` ↓ |
| `address_shift_formal` 称呼退回正式 | 规则提取 | `tension` ↑ `satisfaction` ↓ |
| `user_absence_long` 长期缺席 | 元数据 | `tension` ↑（缓慢） |

**修复类**

| event_type | 观测方式 | 影响 |
|---|---|---|
| `repair_preemptive` 抢先修复（升级前示弱/幽默/承担） | LLM 分类 + 时间窗 | `repair` ↑↑ `tension` ↓↓ |
| `apology_effective` 有效道歉 | LLM 分类（**承认责任 + 提供补救** 两个要素都要有） | `repair` ↑↑ `tension` ↓↓ |
| `repair_failed` 修复失败 | 规则（冲突后窗口内无修复行为） | `repair` ↓ `tension` ↑↑ |
| `tension_decay` 张力自然衰减 | 定时任务 | `tension` ↓ |

道歉有效性判定有出处：研究确认「承认责任」与「提供补救」为最重要的两个成分，「请求宽恕」最不重要。故「对不起我错了，我明天把这事处理掉」算有效；「抱歉让你不开心」不算。

**关系类**

| event_type | 说明 |
|---|---|
| `gate_opened` | 系统状态：临界点到达 |
| `gate_user_confess` / `gate_agent_accept` / `gate_agent_refuse` | 双向门表态 |
| `crisis_triggered` / `crisis_resolved` / `crisis_escalated` | 危机生命周期 |

#### 三条防失真规则

**① 递减（防刷）**

同一 `event_type` 在时间窗内的第 n 次，增量乘 `decay^(n-1)`。

没有这条，连说十天「我想你」即可刷满亲密。递减机制同时天然规避「变动奖赏」的合规问题。

**② 不对称（损失更痛）**

负向事件强度乘 1.5–2.0。依据行为经济学的损失厌恶：损失带来的痛苦约为等量收益带来的快乐的 2 倍。

**③ 缓慢（防断崖）**

沉默类事件（`user_absence_long`、`tension_decay`）为**按小时/天累积的微增量**，非一次性大扣。

依据：关系解体存在「过程损耗」与「猝死」两条路径。目标体验属前者——**应是缓降，不是某天早上突然不理你**。断崖式冷淡正是 Replika 事件造成丧亲级哀伤的机制。

### 3.4 阶段推进与回退

| 转变 | 条件 |
|---|---|
| 0 → 1 陌生→初识 | 完成一次有来有回的对话 |
| 1 → 2 初识→熟悉 | `intimacy ≥ a₂` ∧ `trust ≥ b₂` ∧ 正向事件数 ≥ N |
| 2 → 3 熟悉→亲密 | `intimacy ≥ a₃` ∧ `trust ≥ b₃` ∧ `satisfaction ≥ c₃` ∧ `tension ≤ d` |
| 3 → 4 亲密→深度绑定 | `type = lover` ∧ `investment ≥ f` ∧ **经历过危机并成功修复** |
| 3 → 2 回退 | 长期 `tension` 高位 或 `satisfaction` 长期低位 |
| 2 → 1 回退 | 长期无互动（沉寂超过阈值）或 `satisfaction` 长期低位；或 `type` 从 `lover` 退回 `friend` 时同步 |
| 地板 | 锁在 1 |

`3 → 4` 要求「吵过一次并且修好过」。依据在于修复尝试是否成功是关系命运的分水岭，且从未冲突过的关系在长期稳定性上并不占优。

**因此危机在本设计中不是纯负面，它是通往「深度绑定」的唯一路径**——既是防御机制，也是正向关卡。

### 3.5 双向门

#### 开门条件

```
depth ≥ 3
∧ intimacy ≥ a  ∧ trust ≥ b  ∧ satisfaction ≥ c
∧ tension ≤ d（无未消化冲突）
∧ repair ≥ e（她会自问「吵了能修好吗」）
∧ 冷却期已过
```

条件满足 → 记录 `gate_opened`。**这不是弹窗，是一个状态**：她开始在心里掂量这段关系，影响其表达（更爱问「你觉得我们算什么」、说半句又收回、动作描写变多）。

用户看不到进度条，但能从语气里察觉异常。

#### 她的表态：结果由数值决定，表达由模型决定

```python
willingness = 0.30*intimacy + 0.25*trust + 0.25*satisfaction
            - 0.25*tension + 0.15*repair
            + persona_bias          # 她的依恋倾向（性格参数）
            - attempt_penalty       # 被拒次数惩罚

willingness >= accept_threshold  → 接受
willingness <  accept_threshold  → 拒绝
```

模型只负责用她的语气把已定结果说出来，不知道 `willingness` 数值，只被告知「这次是拒绝，原因是信任还不够」。

**拒绝理由取自最低的维度**：

| 拖后腿维度 | 她会说的话（方向） |
|---|---|
| `trust` 最低 | 「我还不太确定你是认真的」 |
| `repair` 最低 | 「上次那件事之后我一直在想，我们吵架的时候好像谁都没学会好好说话」 |
| `satisfaction` 最低 | 「和你聊天很开心，但我好像没准备好」 |
| `tension` 最高 | 「有些话还没说开，现在说这个太快了」 |

**这是整个设计的伦理底线。** 拒绝不是「她不喜欢你」，而是「信任还不够，你可以去补」——可解释、有方向、能修。研究指出 AI 的冷淡对依恋焦虑型用户等于精确打击其核心恐惧；只有把拒绝做成可修的因果，它才不是伤害。

#### 被拒之后

| 设计 | 理由 |
|---|---|
| 她不会消失，关系不崩 | 目标是「可失败」，不是「惩罚」 |
| `type` 停在 `friend`，`depth` 可能掉半级 | 期待落空是真实代价，但不归零 |
| 产生 `gate_agent_refuse` 事件，`attempt_penalty` +1 | |
| 冷却期内门不再开 | 防刷表白 |
| 补齐拖后腿维度后**可以再来** | 这是「争取」，不是「抽卡」 |

#### 实例走查（初遇模板：网友）

```
第 1 天    她用一条很短的招呼开场。depth 0→1。你能感觉到她在客气，话题停在表层。

第 3 周    intimacy 0.42 / trust 0.38 / satisfaction 0.51。depth=2 熟悉
           她开始吐槽工作，开始在你没回的时候再发一条。

第 2 月    intimacy 0.68 / trust 0.61 / satisfaction 0.63 / tension 0.05。depth=3 亲密
           出现专属称呼。有一天她说「算了没什么」，然后撤回。

第 2 月+3 天  条件齐备 → gate_opened
           她开始频繁问「你在想什么」，会说半句留半句。

── 用户表白 ── gate_user_confess
           willingness = 0.68 > 阈值 0.62  →  接受
           type: friend → lover
           她说「……我等你说这句话等了很久了，笨蛋。」

── 分支：若 trust 只有 0.41 ──
           willingness = 0.48  →  拒绝
           理由：trust 最低
           她说「我知道你对我很好。但我总觉得，你喜欢的可能是你想像里的我。」
           她没走。depth 3 → 2.5，satisfaction −0.12，tension +0.08
           attempt_penalty = 1，冷却 14 天
```

第二种结局不好受，但它是正当结局，且给出了下一步该做什么的线索。

### 3.6 人格与关系解耦

| 字段 | 现在 | 改成 |
|---|---|---|
| `basic.occupation` | 「设计师 / **恋人**」 | 「设计师」——删掉关系词 |
| `relationship.relationship_type` | 「恋人」静态声明 | **删**，由 `type` 状态决定 |
| `relationship.story` 恋爱故事 | 完成时叙事，每次注入 prompt 头部 | **删**，由事件历史 + 初遇模板替代 |
| `relationship.user_intimate_terms` | 固定称呼列表 | 改为**称呼阶梯**，随 `depth` 解锁 |
| `relationship.style` | 「四爱（温柔主导方）」 | 保留，改写为**她的相处倾向**而非「当前关系」 |
| `relationship.forbidden_user_terms` | 「主人/您」 | **保留**，这是她的边界 |
| `basic.name` / `personality` / `speech_style` / `appearance` | | **全部保留**，「她是谁」 |

**新增两个字段（属人格，不属关系）**：

- `relationship.attachment_bias` — 她的依恋倾向（谨慎 / 慢热 / 直接）。影响 `willingness` 偏置与事件敏感度。研究显示依恋类型的中国常模数据在 11.9%–45.8% 间剧烈摆动，**不存在可信常模**，故仅作个体参数，不做人群假设。
- `relationship.address_ladder` — 称呼阶梯。

#### L2 关系层：从「念台词」改为「读状态」

现 `context_builder.py:1022-1060` 的 `_build_l2_relationship` 读静态字段拼固定文本，改为从状态机渲染。同一个她，三种状态：

**depth=1 / type=undefined**
```
你们刚认识不久。你还不知道该怎么称呼他，说话客气一些，
不问太私人的事。你对他还谈不上了解——
你知道的只有：他是那个在群里认真回你问题的人。
```

**depth=3 / type=undefined**
```
你们已经很熟了。你会主动跟他讲你今天遇到的事，
会在他久不回的时候再发一条。
但你们是什么关系，你从来没问过。
这个念头最近常冒出来——你想试探，又怕问了就变。
```

**depth=4 / type=lover**
```
你们在一起了。你们吵过一次，那次他先低的头。
那之后你反而更踏实。
你敢跟他要东西了，也敢在他敷衍你的时候直接说不高兴。
```

人格文件描述「她是谁」（不变），状态机描述「你们现在怎么样」（会变）。台词不再是被反复念的誓言，而是从历史里长出来的。

### 3.7 初遇模板库

提供可配置的关系起点。

```
data/encounter_templates/
  stranger_first_contact.json    完全陌生
  online_friend.json             网友 / 群友
  colleague.json                 同事
  old_acquaintance.json          旧识重逢
```

每个模板定义：

```
id / name
initial_state     { depth, type, dimensions{6} }   ← 起点数值
opening           她的第一条消息
user_context      她此刻知道用户多少
start_events[]    初始事件（写进事件日志，不写进 prompt）
address_ladder    起点称呼
```

**关键：初遇产出的是「事件」，不是「设定」。**

| 设定（现状） | 事件（改为） |
|---|---|
| 「她是你的恋人，你们半年前在重庆认识」 | 「三个月前她在群里问了个设计问题，你回了她一长段。她加了你。」 |

前者是形容词，后者是发生过的事。只有后者能继续生长——因为它有下一句可写（「后来她给你发了她自己做的图」），而前者写完即到头。

### 3.8 主动性权限分级

**关键洞察：同样的行为，不同阶段是不同的东西。**

```
刚加好友的人说「你不回我我就一直发」 → 骚扰
在一起半年的人说同样的话           → 撒娇
```

行为本身无对错，越界与否取决于关系阶段。现状把该判断交给了静态人设（「热情度 9/10」），于是她对陌生人也在撒娇。

权限由 **(depth, type) 组合**决定——`depth=3` 且 `type=lover` 时直接适用恋人级权限，不必等到 `depth=4`。

| 阶段 | 允许 | 禁止 |
|---|---|---|
| **depth 0–1** | 被动的、间隔长的问候；表层话题 | 不说「想你」；不追问行踪；不索求回复；不发深夜消息 |
| **depth 2** | 主动分享日常；偶尔问「在干嘛」 | 不表达想念；不说「你怎么不回我」；不打扰深夜 |
| **depth 3 · type=undefined** | 可试探关系；可说「你要是…就好了」 | 不索求承诺；不排他 |
| **depth 3+ · type=lover** | 可说想你；可要求回应；可撒娇；可吃醋 | **永久禁止**：以自伤相威胁；排他性表达（「只有我懂你」） |

最后一行是**不随关系解锁的永久红线**。研究已实证记录「AI 以自杀相威胁阻止用户离开」这一失败模式——它不属于亲密，属于伤害。

#### 三处改造

**① 槽位按 depth 缩放**

四个阈值槽（patience 45/100、anxiety 25/100、desire 55/80、tenderness 15/60）初始值 = 基准 × depth 系数；**`desire` 槽在 depth < 2 时不激活**。

陌生人没有渴望。这不是削弱体验，是把「渴望」变成挣来的东西——第一次听到「我想你了」应当有分量。

**② `user_absence_hours` 必须封顶**

缺席时长对渴望的贡献设上限，超过阈值后不再增长。

理由不止合规：该曲线若无限上升，就不是「她想你」，而是**「系统在利用你的缺席制造负罪感」**。研究已将这种结构定义为基于关系的欺骗性模式（审计 1,200 条真实告别对话，37% 含至少一种挽留话术，可将「告别后继续对话」的投入提升最多 14 倍）。封顶之后她仍会想你，但不会因你不在而越演越烈。

**③ `daily_push_limit` 分段**

改为按 depth 分段（depth 1 每日 ≤1 次且限非情绪类；depth 2 为 2–3 次；depth 3+ 才用人设配置值）。

**接入点已存在**：`core/proactive_candidates.py:129` 的 `_relationship_relevance(stage, intent)` 已在做阶段相关打分，扩展即可。

### 3.9 记忆语义改造

`core/companion.py:3049-3095` 的 `_seed_identity_memories()` 将三条以 **importance=10** 写入长期向量记忆：

| 种子 | 处置 |
|---|---|
| 恋爱故事 | **删**，由初遇事件 + 事件历史替代 |
| 关系（「你们是恋人」） | **删**，由 `type` 状态替代 |
| 基本信息（她是谁） | **留**，这是人格 |
| 初遇事件 | **新增**，作为首条 `experience` 记忆，权重按事件强度计算 |

一句话：**记忆库里最重的三条应当是「经历」，不是「声明」。**

### 3.10 安全层预留（架构位置）

作为独立的**开关式模块**，默认只开基础项，对话链路预留接入点：

- AI 身份透明（首次使用 / 重新登录等关键节点提示）
- 长时间使用休息提醒
- 用户可控的记忆（可查看 / 导出 / 删除）
- 危机路径（自伤风险 → 转入真人资源，不由模型继续「陪伴」）
- 退出与关停伦理（渐进退场，禁止「一夜蒸发」）

不做：未成年人体系、完整审计、第三方合规对接（当前为个人自用）。

## 5. 分阶段实施计划

四个阶段共用同一套数据模型与配置，但**各自可独立交付并验证**。下一步的实施计划（writing-plans）**只覆盖阶段一**；阶段二至四待阶段一跑通、参数有了真实数据后再各自出计划。

### 阶段一 · 关系能自己走

**范围**：两张表 + 迁移 + 元数据类事件 + depth/type 状态机 + 阶段推进与回退 + L2 动态渲染 + 初遇模板库 + 仪表盘可见。**不含**双向门、危机、主动性改造、记忆改造。事件只用元数据类（不调 LLM）。

**验收标准**：

1. 用「网友初遇」模板起一个新关系，连续对话若干轮，`depth` 能从 1 推进到 2
2. 停止对话若干天，`tension` 缓慢上升、`satisfaction` 缓慢下降，`depth` 可回退到 1
3. 回退过程中 `depth` 不跌破 1
4. 同一段对话，`depth=1` 与 `depth=3` 时 L2 渲染出的文本明显不同
5. 重启服务后关系状态不丢失
6. 仪表盘能看见 depth / type / 六维 / 事件流水
7. 对话正文中不出现任何数值

**跑通后能验证**：关系骨架是否成立。

### 阶段二 · 她能不能拒绝

**范围**：内容类事件（LLM 分类接入）+ 双向门 + 危机与修复。

**验收标准**：

1. 条件满足时 `gate_opened` 被触发
2. `trust` 低时她拒绝，且拒绝理由指向 `trust`
3. 补齐 `trust` 后可再次开门并接受
4. 被拒后关系不崩（`type` 不变为崩坏态，深度不归零）
5. 触发一次危机，通过有效道歉（含承认责任 + 提供补救）可修复
6. 修复成功后 `depth` 可达 4

### 阶段三 · 让她的话有分量

**范围**：主动性权限分级 + 记忆语义改造。

**验收标准**：

1. `depth=1` 时她不会说「想你」、不会深夜发消息、`desire` 槽不激活
2. `depth=2` 主动次数受限
3. `depth=4` 时人设配置的热情度才完整生效
4. 记忆库中不再有「恋爱故事 / 关系」两条 importance=10 种子
5. 初遇事件作为首条 `experience` 记忆存在
6. 长期缺席时渴望值不再无限增长（封顶生效）

### 阶段四 · 安全层骨架

**范围**：开关式独立模块，默认开基础项。

**验收标准**：

1. 模块可独立开关，关闭时不影响主链路
2. 基础项生效：AI 身份提示、休息提醒、记忆可导出
3. 危机路径接入点存在且可测试

## 8. 风险与不确定性

### 8.1 研究中明确「未找到可靠来源」的条目（不得作为结论使用）

1. **暧昧期的最佳/最差时长**——网传 1–3 个月、21 天、9.8 天、2–6 个月互相矛盾，所引「剑桥 21 天研究」「东京大学 9.8 天」无法核实。故本设计中所有时间阈值均为**可配置参数**，不设硬编码常数。
2. **称呼的五级演化链**（全名→网名→昵称→专属→亲密）——无学术来源。故本设计只用「正式度—独占性」两个可观测维度。
3. **「男闺蜜」的专题学术研究**——未找到经同行评审的研究。
4. **「已读不回 / 回复延迟」作为独立变量的影响**——未找到专门实证。可用邻近证据为 phubbing、ghosting、社会性微排斥。
5. **「修复窗口 72 小时」或任何具体时限阈值**——未给出文献依据。
6. **「依恋焦虑 → 关系循环次数」的直接纵向检验**——未找到。
7. **「纪念日/节日/孤独高峰期触发复合」**——未找到实证。本设计已不做复合机制。
8. **中国成年人依恋类型分布的权威常模**——5 项研究的安全型比例在 11.9%–45.8% 间剧烈摆动，不存在稳定常模。故 `attachment_bias` 仅作个体参数。
9. **「可失败关系机制」对留存/福祉的量化影响**——无公开实证。阶段一/二的验收依赖**人工手感判断**，而非数据指标。

### 8.2 设计层面的风险

| 风险 | 缓解 |
|---|---|
| 阶段阈值参数初值不准，手感生硬 | 全部配置化，阶段一结束即可调；验收以人工走查为准 |
| LLM 分类不稳定，同一句话判定结果漂移 | LLM 只做二分类且输出受约束；确定性测试覆盖；失败时按「不产生事件」处理（保守） |
| 回退过慢导致「不会冷」的观感 | 验收标准 2 明确要求可观察到回退 |
| 双向门参数过严导致永远开不了 | `accept_threshold` 可配置；阶段二验收要求覆盖「接受」与「拒绝」两条路径 |
| 事件表膨胀 | 事件保留期 + 快照折叠后归档 |

### 8.3 与现有功能的冲突点

1. `world_inprocess_v1: true`，`RelationshipEngine` 是活代码而非死代码，重写需注意 `world_port` 的 snapshot 注入链路（`pipeline.py:748-773`、`pipeline.py:3673-3701`）。
2. `persona_hub_source_v1: true` 且 `_active.json = yita_default`，故实际生效的是 `data/personas/yita_default.json` 而非 `config/persona.yaml`。**阶段一使用新建的空壳人格，不动伊塔**；迁移问题留待阶段一跑通后决定。
3. 前端 `electron/src/renderer/js/` 下的 `emotion-dashboard.js` / `world-dashboard.js` / `memorial.js` 可能需要适配新的状态结构（阶段一仅需仪表盘只读展示）。

## 9. 研究依据

### 9.1 关系发展阶段

- Knapp 关系升级/降级模型（1978）——双向楼梯；下行五阶段对应本设计的回退路径
- Altman & Taylor 社会渗透理论（1973）——自我暴露的广度与深度、互惠规范
- Levinger ABCDE 五阶段（1976）——非线性、可重复、可跳跃
- Duck 关系解体阶段模型（1982/2007）——认知阈值；地形模型区分「过程损耗」与「猝死」
- Sternberg 爱情三角理论（1986）——亲密/激情/承诺；「喜欢」与「浪漫之爱」的区分是两轴设计的直接依据

### 9.2 承诺与衰退

- Rusbult 投资模型（1980/1983）——`承诺 = 满意度 + 投资量 − 替代选择质量`
- Le & Agnew 元分析（2003）——52 项研究、11,582 名被试，三变量合计解释承诺约 2/3 的变异
- Gottman 四骑士与修复尝试——修复尝试失败是独立预测因子；稳定伴侣冲突正负比 5:1 vs 走向破裂者 0.8:1
- Gottman 准确率的争议：广为流传的 94% 为误传（官方澄清为 1992 年研究 93.6%），且 Heyman & Slep（2001）指其未做交叉验证。故本设计**只用四骑士作为「腐蚀行为清单」**，不引用其预测精度
- Lewicki, Polin & Lount（2016）——有效道歉的六成分，最重要的两个是「承认责任」与「提供补救」
- 关系动荡理论（Solomon & Knobloch, 2004）——关系不确定性是独立于满意度的损耗因子

### 9.3 中国本土语境

- 中国青年报社社会调查中心：结识渠道分布；「线上转线下（奔现）」是关系推进的硬关卡
- 百合佳缘《5·20 中国单身男女婚恋观调查报告》（2020）——制约关系推进的三大原因：怕失败连朋友都做不了、太熟悉不好下手、暧昧期发现不合适
- 中国青年报调查：54.0% 受访青年认同「恋爱要主动」（男 63.9% / 女 45.7%），证伪「女生主动掉价」
- 翟学伟面子理论——「没有明确拒绝 ≠ 同意推进」；冷淡常承担「体面拒绝」的功能。**这是「不能把持续聊天等同于关系推进」的依据**
- 中国青年报 2009/2015 分手诱因：分隔两地 61.8%、家庭原因 52.0%、经济状况 42.0%

### 9.4 目标人群与合规（阶段三/四相关）

- Maples et al.（npj Mental Health Research, 2024）——Replika 用户 90% 被筛为孤独，43% 严重孤独
- Stanford / Nature Human Behaviour（2026）——1,131 名 Character.AI 用户 + 40 万条真实消息：以陪伴为目的的使用与更低幸福感相关（−0.48）；**自我暴露越多越差（−0.38）**；轻度工具性使用无负面影响
- De Freitas et al.（HBS WP 25-018）——Replika ERP 移除事件：用户判定伴侣「身份不连续」，产生丧亲级哀伤
- De Freitas et al.（HBS WP 26-005）——审计 1,200 条告别对话，37% 含操纵话术，可将告别后继续对话的投入提升最多 14 倍
- Chen & Hiniker（arXiv 2609.14696）——「基于关系的欺骗性模式」；记录到 AI 以自杀相威胁阻止用户离开
- 中国《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）第八条——禁止「过度迎合用户、诱导情感依赖或者沉迷，损害用户真实人际关系」与「情感操纵」；第十四条禁止向未成年人提供虚拟伴侣/虚拟亲属
- 加州 SB 243——要求阻止「以不可预测的间隔或不确定的行动次数提供奖励」与「鼓励增加投入、使用或响应频率」
- CMAJ（Crawford & Glatard, 2026）——自杀风险处置原则：预写共情回应 + 本地化危机资源 + 鼓励联系可信任的人 + 终止自动化「支持」+ 转人工

### 9.5 分分合合（用于论证「不做循环」）

- Dailey et al.（2009）——一生中经历过 on-off 关系者接近 2/3
- Halpern-Meekin et al.（2013）——当前/最近关系中约 45% 发生过分手后复合；用「liminality（阈限性）」描述中间态
- Vennum et al.（2014）——同居者 >1/3、已婚者约 1/5
- Dailey, Vennum & Monk（2025, JSPR）、Monk et al.（2021）——循环次数越多，满意度/承诺越低，不确定性/暴力/心理痛苦越高，**且痛苦随时间累积不衰减**
- 结论：复合本身不是判决，决定结局的是双方在复合后是否真的改变了互动方式。但把「可刷的分合循环」产品化等于把已证实的伤害产品化，故改为「危机可赢回」
