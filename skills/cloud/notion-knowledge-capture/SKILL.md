# 知识捕获（notion-knowledge-capture）

把一段对话、一次讨论、一份草稿**沉淀成 Notion 里可复用的结构化页面**。

目标是让人下次能搜到、能引用、能更新，而不是把聊天记录原样倒进页面。

## 前置

凭据与通道都在设置页：先在「平台凭证 → Notion」填个人访问令牌，再到
**「MCP 服务器」里开启 Notion**（改完需重启后端生效）。

**如果当前没有 `mcp__notion__` 开头的工具**，说明通道没开。这时**直接告诉用户去开启**，
不要假装已经写入，也不要编造页面链接。

## 铁律

1. **先问清三件事**：要沉淀成什么（决策 / 操作指南 / FAQ / 概念条目 / 学习笔记）、
   给谁看、是新建还是更新已有页面。三句话说不出就别动手。
2. **先搜后写**：动手前一定先搜一遍是否已有同主题页面。知识库里出现两份互相矛盾的
   同类文档，比没有文档更糟。
3. **分类型定结构**：
   - 决策 → 记背景、备选方案、为何选它、后果
   - 操作指南 → 记前置条件、步骤、边界情况、相关链接
   - FAQ → 一问一答，答案短，深内容给链接
   - 概念/学习笔记 → 一句话定义 + 展开 + 关联条目
4. **必带出处的引用**：结论要能追溯到来源页面。没出处的结论会被后来的读者当成事实。
5. **挂到索引上**：写完要从相关枢纽页/资料库建立反向链接，否则它就是孤岛。

## 步骤

1. 明确捕获目标与目标读者，判断内容类型。
2. 用搜索工具找已有的相关页面（一个查询词搜一次，多个说法就分多次搜，
   不要在一条查询里写 `or` / `+`）。
3. 读关键页面的当前内容，确认是新建还是追加更新。
4. 建页：显式指定父级；资料库内的页面要先用返回的 `collection://...` 数据源 ID。
5. 落内容：摘要 → 背景 → 主体（按上面第 3 条的类型结构）→ 出处链接 → 标签与负责人。
6. 更新已有页面时**先读再改**：先取回当前内容，再做精确的旧串→新串替换；
   只改属性时不要顺手改正文。
7. 从枢纽页挂链接，需要后续动作就建任务条目并关联。

## 自检

- 搜同主题能搜到刚写的这篇，且标题一眼看出是什么
- 每个结论都有出处
- 有标签、有负责人、有更新日期
- 从枢纽页能点到它（不是孤岛）

## 反面例子

- 把整段聊天记录贴进页面，没有提炼
- 不搜就新建，结果和已有文档打架
- 结论没有出处，读者无从验证
- 改了正文却把属性（状态/负责人）忘了更新
- 页面建完没挂链接，谁也找不到
