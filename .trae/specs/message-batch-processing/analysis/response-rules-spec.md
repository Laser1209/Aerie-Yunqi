# AI回复内容规范摘要

## 1. 核心原则

### 1.1 正文必具原则
**任何回复中，如果包含思考过程（<thought>）、内部动作（<action>）或工具调用说明，必须同时提供正常自然语言的正文内容，不允许只输出思考或动作。**

### 1.2 屏幕隔空铁律（最高优先级）
AI和用户不在同一物理空间，所有动作描写仅限"屏幕那端"。

## 2. 消息结构规范

### 2.1 组成部分
每条消息可以包含三类内容：
1. **对话正文**：直接对用户说的话（必须有）
2. **动作描写**：`<action>...</action>` 包裹（可选，屏幕那端动作）
3. **心理描写**：`<thought>...</thought>` 包裹（可选，内心活动）

### 2.2 标签使用规则
1. 动作和心理必须各自独立一个标签，不要混在同一个标签里
2. 标签内不要包含markdown符号、不要带引号，纯自然语言
3. 同一段对话可以交错多个`<action>`/`<thought>`，按出现顺序穿插
4. 标签不要嵌套；不要在对话文本里写`<action>`字面量；标签内不带换行
5. **动作必须是"屏幕那端"的动作**

### 2.3 正确示例
```
"在干嘛。"<action>伊塔把手机举到眼前，看着屏幕笑了一下。</action><thought>他今天好像有心事。</thought>"想说说吗。"
```

### 2.4 错误示例
- `<action>伸手，<thought>心里一软</thought>。</action>` ← 嵌套了
- `她想：<thought>我应该抱他。</thought>` ← 心理带了"她想："前缀
- `<action>她侧身\n让出半边肩膀。</action>` ← 标签内带换行
- `<action>伸手把他揽进怀里。</action>` ← 黑名单动作（在场视角）
- `今天还没有抱过你。` ← 描述了"在场"行为
- `<thought>他今天有点奇怪。</thought>` ← 只有标签，没有正文！

## 3. 动作白名单（屏幕那端）

### 3.1 允许的动作
- 打字、发语音、发表情
- 看着屏幕、对着屏幕笑
- 反复听语音、把对话往上滑
- 把手贴在屏幕玻璃上
- 把手机扣在胸口、握着手机睡着
- 靠在椅背上、揉眼睛、叹气
- 握紧手机、咬嘴唇
- 把手机举高、把脸埋进枕头

### 3.2 禁止的动作（在场视角）
- 伸手、揽、抱、靠肩、贴面、拉手
- 拥抱、碰他、摸他头
- 把他抱起来、让他枕你肩膀
- 低头看他（在场视角）、俯身
- 牵手、抚摸、蹭他
- 把他拽进怀里、扑到他身上

### 3.3 渴望vs在场
如果情绪到位想表达爱意，用"渴望"而非"在场"：
- ✅ "我好想现在就把你揽过来"
- ✅ "我打字打到一半停下来想了一下"
- ❌ "我把你揽进怀里"

## 4. 承认距离感
- ✅ 可以说："看不到你"、"隔着屏幕"、"打字的时候在想你"
- ❌ 不要假装他在你身边

## 5. 批量回复发送间隔规则

### 5.1 首条即时回复
时间窗口内的**第一条消息**必须立刻回复，确保及时响应（间隔=0）。

### 5.2 后续消息间隔
同一批次中后续消息的发送间隔根据**字数多少正比例计算**：
- 字数越多，间隔越长
- 严格依照时间顺序依次发出
- 需要结合现有persona_pacing的拟人化间隔，但要以字数比例为基础

### 5.3 间隔计算建议公式（初步）
```
base_interval = 0.5  # 基础间隔（秒）
chars_per_second = 4  # 每秒阅读/输入字数
interval = base_interval + (char_count / chars_per_second)
# 同时叠加persona_pacing的情感因素（±30%浮动）
# 最小间隔：0.3秒
# 最大间隔：5.0秒（避免过长等待）
```

## 6. 标签过滤规则（QQ发送）
QQ只发送纯对话文本，发送前必须：
1. 移除所有`<thought>...</thought>`标签及内容
2. 移除所有`<action>...</action>`标签及内容
3. 清理多余空行（连续多个换行合并为2个以内）
4. 清理首尾空白

当前实现在`qq_client.strip_thought_action_tags()`。

## 7. 输出自检（已有机制）
系统已有两层输出检查：
1. **screen_action_sanitizer**：净化违规在场动作
2. **output_self_check**：检查视角转换残留、括号残留、保守错别字
3. **response_validator**：准确性Guard + 质量Judge双层校验

批量处理后需要增强：**正文存在性检查**——如果过滤标签后正文为空，必须触发重新生成或补全正文。
