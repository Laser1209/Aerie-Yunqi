# ADR-0001：建立独立知识审计 Vault

## 状态

accepted

## 背景

项目需要一个独立的 Obsidian Vault，用于承载模块总览、技术总览、依赖清单、决策记录、审计报告、验证索引与证据目录，并通过互链形成可巡航、可回溯的知识闭环。

## 决策

创建独立目录 `Aerie_Obsidian_Vault`，并以 [[00_首页|首页]] 为入口建立主回路：[[00_首页|首页]] → [[01_模块总览|模块总览]] → [[02_技术总览|技术总览]] → [[03_依赖清单|依赖清单]] → [[04_决策记录|决策记录]] → [[05_审计报告|审计报告]] → [[06_验证索引|验证索引]] → [[07_证据目录|证据目录]] → [[08_互链地图|互链地图]] → [[00_首页|首页]]。

## 影响

- 文档结构具备稳定入口与回链路径。
- 审计发现、验证记录和证据材料可以双向追踪。
- 后续 ADR 可以独立存放在 `ADR/` 目录，并由 [[04_决策记录|决策记录]] 汇总。

## 验证

- 验证入口：[[06_验证索引#验证矩阵]]
- 证据入口：[[07_证据目录#文档证据]]

## 复盘条件

- Vault 页面超过 30 个时，复查目录分层是否需要细分。
- 审计发现超过 20 条时，复查是否需要按模块拆分报告。
- 验证证据规模明显扩大时，复查证据命名、归档与校验策略。
