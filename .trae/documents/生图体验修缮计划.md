# 生图体验修缮计划

> [!important] 一句话目标
> 让伊塔的每一张图都"**是她本人手持手机拍的**"、"**是她知道内容的**"、"**是系统后台生成而非她写 markdown 的**"——彻底修复视角失控、模板匮乏、发图失忆、提示词外泄四类问题。

## 1. 背景与现状（本次对话已确认的问题）

本次对话系统性排查出四个相互关联的缺陷，全部集中在**生图提示词链路 + 主动发图链路 + 对话上下文**的交界处：

| # | 问题 | 现象 | 根因位置 |
|---|---|---|---|
| P1 | **视角失控（他拍）** | 人物类生图出现"侧身望向镜头"等第三方视角，破坏"她手持自拍"设定 | [companion.py L2734-2741](file:///e:/Agent_reply/core/companion.py#L2734-L2741) 模板无手持约束；`_light_relay_refine_prompt` 无 POV 黑名单 |
| P2 | **模板匮乏 + 翻译缺失** | 主动发图只用一个 `environment_object` 模板；`reading_time` 等话题以英文 token 直接进提示词 | [companion.py L2487](file:///e:/Agent_reply/core/companion.py#L2487) 硬编码；[L89-126](file:///e:/Agent_reply/core/companion.py#L89-L126) 翻译表缺 activity 话题 |
| P3 | **发图后失忆** | 伊塔主动发图后不知道图里是什么，用户追问"你在看书？"接不住 | [companion.py L1179-1194](file:///e:/Agent_reply/core/companion.py#L1179-L1194) QQ 通道发图不写 chat_log；图片内容从未进记忆/上下文 |
| P4 | **提示词外泄** | 伊塔把本应提交生图阶段的提示词写成 `[图片](描述)` 发到 QQ | [context_builder.py L630-659](file:///e:/Agent_reply/core/context_builder.py#L630-L659) L6 未定义发图机制；[qq_client.py L479-540](file:///e:/Agent_reply/communication/qq_client.py#L479-L540) 出口不剥伪 markdown |

## 2. 修缮目标

1. **POV 自拍约束**：所有人物类生图提示词必须含"她本人手持手机拍摄（前置自拍/后置/支架）"的不可变前提，全链路杜绝第三方拍摄视角。
2. **模板能力扩展**：主动发图按素材类型动态映射模板（人物时刻→自拍 / 物件→第一人称物件照），活动话题补全中文翻译，杜绝英文 token 进提示词。
3. **发图自我认知**：每次发图成功后落一条"图片事件"（含中文内容描述 + 图片链接）到 chat_log 与记忆系统，让后续对话能召回。
4. **机制定义澄清**：L6 明确"发图=系统后台生图+附件送达"；QQ 发送出口剥除伪 markdown 兜底，保证 LLM 偶发误写也不外泄。

## 3. 实施步骤（按依赖顺序排列，P1→P2 是提示词侧，P3 依赖 P2 的翻译表，P4 独立可并行）

### 步骤一：手持自拍视角约束（POV，P1 优先级最高）

> 改动文件：`core/companion.py`、`tests/test_modular_photo_prompt.py`

1. **基础提示词注入手持固定语**（[L2668-2754](file:///e:/Agent_reply/core/companion.py#L2668-L2754)）：
   - 重写 L2734-2741 五类人物模板，统一追加手持约束。`role_in_scene` 的"侧身望向镜头"改为"她举着手机，前置摄像头对着自己/或后置镜头对着镜子"。
   - 新增常量 `_SELFIE_POV_PHRASE`，如 `"这张照片由她本人手持手机拍摄，画面角落可见她的手指或手机边缘，微微手持感，绝无他人拍摄。"`。
2. **机位表语义重定义**（[L187-194](file:///e:/Agent_reply/core/companion.py#L187-L194) `_PHOTO_ANGLE_TABLE`）：
   - "仰视低角度"删除或改为"手机放低自拍（支架/手臂垂下）"；"俯视高角度"明确为"手机举过头顶俯拍自己"；其余保留。
   - 组合器输出时所有机位都以"她手持手机"为前缀语境（在 `_compose_modular_prompt` 的 angle 分支补定语）。
3. **语义自补约束**（[L2574-2628](file:///e:/Agent_reply/core/companion.py#L2574-L2628) `_semantic_photo_spec`）：
   - system 提示（L2589-2605）补一条："所有机位均为她本人手持手机拍摄的自拍视角，不存在摄影师/他人拍摄。"
4. **LLM 接力双保险**（[L2910-2957](file:///e:/Agent_reply/core/companion.py#L2910-L2957) `_light_relay_refine_prompt`）：
   - system（L2929-2938）加 POV 硬约束："必须是她本人手持手机拍摄的自拍视角，绝对禁止出现拍摄者、第三人称旁观视角、摄影师。"
   - 校验门（L2952）加 POV 黑名单关键词拒绝：输出含 `摄影师|他人|旁观|第三人称|从背后|路人|拍摄者|别人拍` 任一 → 拒绝采用，回退确定性兜底。
5. **出口兜底 `_ensure_selfie_pov()`**（新增）：
   - `_image_prompt_for` 返回前统一调用：人物类 key（`role_selfie`/`role_in_scene`/`couple_photo`/`default`/`local_send`）若提示词未含 `_SELFIE_POV_PHRASE` 或手持类关键词，自动追加。
6. **测试**（`tests/test_modular_photo_prompt.py`）：
   - 断言 `role_in_scene` 不再含"侧身望向镜头"；含手持/自拍关键词。
   - 断言 `_compose_modular_prompt` 的 angle=仰视低角度 输出含"她手持"语境。
   - 断言 `_ensure_selfie_pov` 对无约束提示词自动补齐、对已含约束提示词幂等。

### 步骤二：主动发图模板扩展 + 活动话题翻译（P2）

1. **补全活动话题中文翻译表**（`core/companion.py` L89-126 区域）：
   - 新增 `_VISUAL_TOPIC_ZH`：`reading_time→她窝在沙发里翻书`、`deep_focus→她在工作台前专注工作`、`morning_plan→清晨在桌前做计划`、`coffee_break→咖啡时间`、`evening_chill→傍晚的放松时刻`、`good_night→睡前片刻`、`desk_view→书桌一角`、`starry_window→窗外的星空`、`quiet_moment→安静的独处时刻`、`lunch_time→午餐时间`、`tea_break→茶歇` 等。

2. **主动链路按素材类型映射 prompt_key**（L2480-2492）：

   - candidate 的 `size` 跟随新 prompt_key（竖屏/横屏自动）。
   - **role_in_scene 分支 topic 参数化（审计 H1 修复）**：`_compose_base_image_prompt` 的 role_in_scene 分支（L2736-2737）当前是固定场景文本且完全不读候选 topic，直接映射会丢失话题语义。必须改为：命中 `_VISUAL_TOPIC_ZH[topic]` 时用它替换/补充固定场景（如 `reading_time` → "她窝在沙发里翻书，举着手机前置自拍"），未命中才回退默认场景——否则翻译表对图片内容输出是死代码。
3. **测试**：
   - `test_visual_topic_zh_translation`：所有 `_ACTIVITY_TOPIC_PREFIXES` 话题（含 `lunch_time`/`tea_break`）都能译出中文且无英文 token 残留。

### 步骤三：发图自我认知落账（P3，依赖步骤二翻译表）

> 改动文件：`core/companion.py`、`memory/layers/layered_memory.py`（只读参考）、测试

1. **QQ 通道发图补写 chat_log**（L1179-1194 `_deliver_world_image`）：
   - 参照 `_deliver_local_chat_image`（L1196-1247）的模式，发送成功后 `db.insert("chat_log", {user_id, role:"assistant", content:"[图片] "+中文描述, msg_type, channel:"qq"})`。
   - 中文描述来自 candidate 的 topic 翻译（复用步骤二 `_VISUAL_TOPIC_ZH`）或实际生图提示词摘要。
2. **发图事件写入记忆系统**（`_record_proactive_photo_tool` L2512-2570 扩展 / 新增 `_record_image_event`）：
   - 用 `self._layered_memory.store(user_id, content="我发了一张{描述}的照片", memory_type=MemoryType.EVENT, importance=7.0, metadata={"occurred_at": <ISO 时间>, "channel": <通道>, "image_path": <相对路径>})`。
   - **层级红线（审计 H2 修复）**：`importance` 必须 **≥7.0**（或显式 `layer=MemoryLayer.LONG_TERM`）。既有召回路径 `pipeline._recall_event_memories`（L2572-2611）**只查询 long_term 层**（L2580），`importance≈6` 会落入 WORKING 层导致永远召回不到；且召回按 `metadata.occurred_at` 降序（L2588-2592），该字段必须写入，否则 `occurred is None: continue` 被过滤。
   - **URL 分离（审计 M2 修复）**：content 只存中文描述 + 相对路径（`uploads/xxx.png`），**不存完整本地 URL**（`http://127.0.0.1:7890/...`）——完整 URL 经 EVENT 召回进上下文（`content[:200]`）后可能被 LLM 复述到 QQ 消息，且当前出口过滤不剥裸 URL。
   - **召回触发词（审计 H2 修复）**：`pipeline._RECALL_KEYWORDS`（L2465-2468）现为"你记得/还记得/我说过/提过…"，**不含"你发的什么"**——须扩展"你发的/发的什么/那张图/照片"等发图回忆触发词，否则 M3 端到端验收"追问'你发的什么'能答"不会触发显式回忆。
   - 覆盖两条路径：主动发图（`_record_proactive_photo_tool`）与聊天要图（`pipeline._record_chat_photo_tool`）。
3. **local_chat 通道补齐内容描述**（L1207 `content = f"![图片]({image_url})"`）：
   - 改为 `![图片]({url})\n[描述]` 或新增辅助字段，让上下文装配能看到图的内容而非只有 URL。
4. **测试**：
   - `test_deliver_world_image_writes_chat_log`：stub qq.send_image 成功 → 断言 chat_log 插入且 content 含中文描述。
   - `test_record_image_event_memory`：断言 LayeredMemory.store 被调用且 memory_type=EVENT、**importance≥7.0、metadata 含 occurred_at**（审计 H2：否则无法被 `_recall_event_memories` 召回）。
   - `test_record_image_event_memory_no_url`：断言记忆 content 不含 `http://127.0.0.1:7890` 等完整 URL（审计 M2）。
   - `test_recall_keywords_include_photo`：断言 `_RECALL_KEYWORDS` 含"你发的/发的什么/那张图"等发图回忆触发词（审计 H2）。
   - `test_local_chat_image_content_has_desc`：断言 local 通道 chat_log 内容含描述而非纯 URL。

### 步骤四：发图机制定义澄清 + 输出端伪 markdown 过滤（P4，可与步骤一二三并行）

> 改动文件：`core/context_builder.py`、`communication/qq_client.py`、测试

1. **L6 机制定义重写**（[context_builder.py L630-659](file:///e:/Agent_reply/core/context_builder.py#L630-L659)）：
   - 在"使用原则"前插入"发图机制"段：发图 = 你说自然语言（"我拍张给你看看"）→ 系统在后台调生图模块生成真实图片，**作为附件**随你的消息送达。
   - 明确禁止：你的回复文本里不得出现 `[图片](...)`、`![图片](...)`、生图提示词、画面描述性文本——这些是给生图系统的输入，不是你的话。
   - 呈现要求：引导句 + 图片送达后的自然收尾（"喏，看到了吗？"），表现"我自己拍的"。
2. **QQ 出口伪 markdown 过滤**（`communication/qq_client.py`）：
   - 新增 `strip_fake_image_markdown(text)`：正则剥掉 `[图片](...)` / `![图片](...)` 且括号内**不是合法 http(s) URL** 的片段（真实图片消息 `![图片](http://127.0.0.1:7890/...)` 不受影响）。
   - 接入 `send_message`（L493 附近）与 `send_message_with_segments`（L740 附近）的既有清洗链：`strip_thought_action_tags → strip_timestamp_markers → strip_fake_image_markdown`。
3. **测试**：
   - `test_strip_fake_image_markdown`：`[图片](局部特写…)` 被剥除；`![图片](http://127.0.0.1:7890/uploads/x.png)` 保留。
   - `test_send_message_strips_fake_markdown`：stub WS，断言发送 payload 无 `[图片](`。

## 6. 质量验收标准

1. **功能**：
   - 所有人物类生图提示词含手持自拍约束（字符串断言）。
   - 活动话题 100% 有中文翻译（含 `lunch_time`/`tea_break`），生图日志、基础提示词与 LLM 接力上下文（`_world_context_text`）均无 `world_visual:reading_time` 类英文 token 泄漏。
   - role_in_scene 生图提示词含话题中文描述（topic 参数化生效），而非固定"站在落地窗前"场景。
   - 主动发图 / 聊天要图成功后，chat_log 有对应"图片事件"记录；记忆库新增 **long_term 层** EVENT 记忆（importance≥7.0 + metadata.occurred_at）。
   - 端到端：伊塔发图后，用户追问"你发的什么"能触发 `_RECALL_KEYWORDS` 并召回图片事件描述回答（跨轮召回）。
   - QQ 收到的任何文本不再出现 `[图片](` 伪语法。
2. **健壮性**：
   - 语义自补/LLM 接力失败仍回退基础提示词，不中断生图（既有护栏保留）。
   - `strip_fake_image_markdown` 不误伤真实 `![图片](http://…)`。
   - POV 出口兜底幂等（重复追加不叠加）。
3. **回归**：全量测试 ≥1278 通过，无新增失败；27 个既有环境性失败不恶化。

## 7. 潜在风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| LLM 接力仍输出第三人称措辞（黑名单漏网） | 偶发他拍图 | POV 出口兜底 `_ensure_selfie_pov` 保证最终提示词含手持约束；黑名单覆盖高频词并留日志便于迭代 |
