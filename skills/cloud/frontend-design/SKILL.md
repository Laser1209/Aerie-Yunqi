# 前端组件设计（frontend-design）

写页面、组件、UI 时套用这套方法论。目标是产出**不像 AI 模板**的界面：有明确的视觉主张、克制的配色、真实的排版层次，而不是"居中大标题 + 三张等宽卡片 + 渐变按钮"的通用货。

## 铁律

1. **先定视觉主张，再写代码**：开工前用一句话说清这个页面的气质（如"冷静的工业感""手写便签的亲切感"），后面所有版式、配色、字体决策都服务于它。没有主张的界面必然平庸。
2. **限制色板**：主色 1 个 + 中性色 3~4 个 + 强调色最多 1 个，整页颜色不超过 5 种。禁止彩虹渐变、禁止满屏高饱和。
3. **字体只选一到两款**：标题与正文可用反差明显的两款（如优雅衬线标题配干净无衬线正文），靠字号、字重、行距拉开层次，而不是不断换字体。
4. **留白是设计的一部分**：内容区外边距不小于 24px，章节间距明显大于段落间距。挤满屏幕是新手最典型的败笔。
5. **动效服务于意图**：只在状态切换、进入视口、悬停反馈处加动效，时长 150~400ms 配缓动曲线，不要让所有元素都在飘。

## 步骤

1. **明确三件事**：这是什么页面、给谁看、希望对方看完做什么（转化目标）。三句话写不出来就先别动键盘。
2. **定栅格**：选一套布局网格（如 12 列 / 1180px 容器），所有区块对齐同一套栅格，禁止随手写死像素。
3. **排视觉层级**：一屏只有一个视觉焦点，主标题与主按钮的字号/对比度要显著高于次要元素，其余全部降噪。
4. **选色与字体**：按上面的限制，优先复用项目已有设计 token；没有才新建，且一次定死不再随手加。
5. **写真实内容**：用贴合的占位文案（真实业务名词、真实数字），不要 lorem ipsum，也不要"标题一、标题二"——占位文案会直接毁掉版式判断。
6. **加少量动效**：只做 1~2 处，并保证 `prefers-reduced-motion` 时关闭。
7. **自检**：缩到手机宽度看是否溢出、放大到 200% 是否可读、去掉颜色后层级是否依然成立。

## 输出形态

```
## 视觉主张
（一句话气质 + 转化目标）

## 设计 token
- 主色：#…  中性色：#… / #… / #…  强调色：#…
- 字体：标题 … / 正文 …
- 间距节奏：8 / 16 / 24 / 40 …
- 圆角与阴影：…

## 结构
1. Hero：…
2. …

## 关键实现
（组件代码或 HTML/CSS，全部引用已有 token）
```

## 反面例子（不要这样）

- 所有页面都是"居中大标题 + 三张等宽卡片 + 渐变按钮"。
- 用七八种颜色、五款字体，靠堆砌制造"丰富感"。
- 元素紧贴边缘、行距压到 1.2 硬塞，读起来透不过气。
- 动效铺满全屏、时长超过 1 秒，让人头晕。
- 文案全是 lorem ipsum 或"标题一/标题二"，看不出真实版式效果。
