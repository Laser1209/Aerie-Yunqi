# Aerie 第三次修正计划知识库更新机制

> 本文档定义第三次修正计划的信息总览知识库如何更新、如何与仓库计划文档同步、如何维护双向链接，以及新发现如何进入决策、审计和验证闭环。它是 [02_第三次修正计划决策记录.md](./02_第三次修正计划决策记录.md) 的配套机制文档，也是 Task 1.4 与 C1.6 的证据入口。

## 2. 目标与边界

### 2.1 目标

- 让独立 Obsidian-compatible Vault 成为第三次修正计划的权威知识入口。
- 让仓库内计划、决策、审计、验证文档保留稳定证据和同步索引。
- 让每个新发现都能追溯到来源、影响模块、相关决策、验证入口和风险状态。
- 让后续实现前可以从知识库首页进入，而不是依赖碎片化聊天记录或临时文件。

### 2.2 同步边界

| 信息类型 | 优先写入位置 | 仓库文档职责 | Vault 职责 |
|---|---|---|---|
| 模块知识 | 独立 Vault 模块笔记 | 只保留索引和交付路径 | 记录模块职责、实现入口、依赖、风险、验证 |
| 技术方案 | 独立 Vault 技术笔记 | 只保留关键决策和阶段计划 | 记录技术路线、替代方案、接口差距、证据 |
| 阶段计划 | 仓库计划文档 | 作为执行真源 | 反向链接到计划和阶段摘要 |
| 决策记录 | 仓库决策记录 | 作为授权和边界真源 | 在相关概念页反链决策编号 |
| 审计记录 | 仓库审计文档 | 保存启动、验收、整改和结论 | 在相关概念页反链审计证据 |
| 验证报告 | 仓库验证文档 | 保存命令、结果、截图、日志、失败项 | 在相关概念页反链验证结果 |
| 临时调研摘录 | 独立 Vault 来源笔记 | 只在最终报告索引重要来源 | 保存摘要、摘录、来源链接和不确定性 |

## 4. 写入规则

### 4.1 新发现分类

| 发现类型 | 写入规则 | 必备反链 |
|---|---|---|
| 模块事实 | 写入 `modules/<模块>.md`，包含职责、代码入口、现状、差距 | 首页、技术页、依赖页、验证页 |
| 技术差距 | 写入 `technology/<技术>.md`，包含能力探测、缺失接口、替代方案 | 模块页、风险页、决策页、验证页 |
| 外部依赖 | 写入 `dependencies/<依赖>.md`，包含版本、权限、账号、成本、安全边界 | 技术页、风险页、决策页 |
| 功能映射 | 写入 `matrices/Function-To-Implementation.md` | 模块页、技术页、验证页 |
| 风险 | 写入 `risks/Unresolved-Risks.md`，高风险同步到决策记录 | 决策记录、审计页、验证页 |
| 决策 | 写入 [02_第三次修正计划决策记录.md](./02_第三次修正计划决策记录.md)，Vault 决策页只建索引 | 相关模块页、技术页、风险页、审计页 |
| 审计证据 | 写入仓库审计文档，Vault 审计页只记录摘要和链接 | 计划页、决策页、验证页 |
| 验证证据 | 写入仓库验证报告，Vault 验证页只记录摘要和链接 | 模块页、技术页、风险页 |

### 4.2 每条知识笔记必备字段

每个 Vault 笔记都应包含以下 frontmatter 或等价结构：

```yaml
---
title: 笔记标题
kind: module_note | technology_note | dependency_note | matrix | risk | decision_index | audit_index | validation_index | source_note
status: Draft | Review | Accepted | Blocked
updated_at: YYYY-MM-DD
owners:
  - ARCH
related_decisions:
  - ADR-TC-XXX
related_risks:
  - R-TC-XXX
related_validations:
  - Cx.x
---
```

### 4.3 正文最低结构

每个核心概念笔记至少包含：

- `定义`：该概念在第三次修正计划中的含义。
- `当前事实`：来自代码、文档或审计的已知事实。
- `目标状态`：P0 闭环完成后应达到的状态。
- `实现入口`：代码文件、计划任务或接口边界。
- `依赖关系`：上游、下游、外部 provider 或运行时依赖。
- `风险与待确认`：链接到风险 ID 或待确认 ADR。
- `验证方式`：链接到 checklist、测试、审计或验证报告。
- `反向链接`：列出相关模块、技术、依赖、决策、风险和验证笔记。

## 5. 互链规则

### 5.1 最小链接闭环

每个核心概念必须至少形成以下四类链接：

| 链接类型 | 示例 | 目的 |
|---|---|---|
| 实现链接 | `[[modules/AttachmentEnvelope]]` → 代码入口或任务链接 | 证明知识能指导实现 |
| 依赖链接 | `[[dependencies/External-Model-Provider]]` | 暴露外部条件和失败路径 |
| 风险/决策链接 | `ADR-TC-003`、`R-TC-005` | 防止绕过授权和边界 |
| 验证链接 | `C3.13`、验证报告路径 | 确保知识不是静态愿景 |

### 5.2 双向链接写法

- Vault 内部概念使用 Obsidian wikilink：`[[ImageObservation]]`。
- 仓库文档使用相对 Markdown 链接：`[02_第三次修正计划决策记录.md](./02_第三次修正计划决策记录.md)`。
- 从 Vault 指向仓库时保留相对路径或文件 URI，具体以 Vault 实际落点决定。
- 从仓库指向 Vault 时先链接 Vault 首页路径；若路径尚未创建，写 `待回填：Vault 首页路径`，不得假造路径。
- 每次新增单向链接时，必须在目标页补一条 `反向链接` 或 `关联来源`。

### 5.3 同步索引

以下索引必须在阶段 1 完成后存在，并在每次阶段验收后更新：

| 索引 | 内容 | 更新时机 |
|---|---|---|
| Vault 首页 | 阶段入口、核心概念、当前状态、风险、决策、验证 | 每阶段启动前和验收后 |
| Decision-Index | ADR-TC 编号、状态、关联模块、确认时间 | 新增或变更决策时 |
| Audit-Index | 阶段启动/验收审计链接、结论、整改状态 | 每次审计后 |
| Validation-Index | Cx.x 检查项、证据路径、通过/失败/未运行 | 每次验证后 |
| Unresolved-Risks | 风险 ID、触发信号、策略、状态 | 新风险出现或风险关闭时 |

## 6. 更新流程

### 6.1 新发现进入知识库

1. 判断发现类型，选择模块、技术、依赖、风险、决策、审计或验证位置。
2. 写入对应 Vault 笔记，补充来源、当前事实、影响范围和不确定性。
3. 为相关模块、技术、依赖、风险、验证添加反向链接。
4. 如果发现改变范围、边界、外部依赖或真实副作用，更新 [02_第三次修正计划决策记录.md](./02_第三次修正计划决策记录.md)。
5. 如果发现影响计划任务或验收标准，更新 [tasks.md](../../.trae/specs/execute-third-correction-p0-fusion/tasks.md) 或 [checklist.md](../../.trae/specs/execute-third-correction-p0-fusion/checklist.md) 的后续整改项。
6. 在阶段审计或累积验证报告中记录该发现是否已处理。

### 6.2 决策变更同步

1. 在决策记录中新增或更新 ADR-TC 条目。
2. 在 Vault `decisions/Decision-Index.md` 增加索引行。
3. 在受影响模块、技术、依赖、风险笔记中增加反向链接。
4. 如决策影响阶段计划，更新计划文档变更记录。
5. 如决策影响验证标准，更新 checklist 或验证报告。
6. 如旧决策被替代，旧条目标记为 `Superseded`，不得删除。

### 6.3 风险关闭同步

1. 风险必须有证据路径、审计结论或用户确认后才可关闭。
2. Vault `risks/Unresolved-Risks.md` 将状态从 `Open` 改为 `Mitigated`、`Accepted`、`Transferred` 或 `Closed`。
3. 决策记录中的对应 R-TC 风险同步更新状态。
4. 验证报告记录关闭证据，阶段验收审计记录关闭结论。
5. 若风险关闭依赖用户接受，必须保留接受范围和后续复核条件。

## 7. 禁止事项

- 禁止把聊天中的临时判断直接当作已接受决策。
- 禁止缺少反向链接的新知识碎片。
- 禁止把未创建的 Vault 路径写成已存在证据。
- 禁止用静态推断替代真实验证、审计证据或用户确认。
- 禁止在未确认前调用真实模型、登录 QQ、写外部向量库或移植未知许可证 helper。
- 禁止删除旧决策、旧风险和失败记录；只能追加变更、标记替代或关闭。
