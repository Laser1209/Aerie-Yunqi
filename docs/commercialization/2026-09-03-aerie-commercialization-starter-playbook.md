# Aerie Companion 商业化入门与市场测试作战手册

> 适用版本：`0.3.2-beta.0904-A12`。下一次包含功能或界面变化的发布版本按规则递增为 `0.3.2-beta.0904-A12`。本文面向第一次做软件开发、上架和收费的负责人，提供可以照着执行的路径，不替代法律、税务或支付机构意见。

## 1. 先把产品卖点说成用户结果

Aerie 不应被宣传成“又一个聊天机器人”，也不应把个人的“伊塔/云栖”设定写进默认产品。商业默认形象使用中性的 **Aerie Companion**；用户可以自行选择专注助手、学习搭档、创作伙伴或生活管家等合规角色，私人 persona 保留为用户自己的选择和兼容数据。

建议定位：

> **把对话、记忆和工作流留在你的设备上，由你决定 AI 连接什么、记住什么、执行什么。**

首发优先面向个人效率用户，第二阶段扩展到内容创作者/主播，第三阶段再考虑团队版。这个顺序能先验证核心价值，避免一开始同时承担企业权限、发票和高并发 API 成本。

## 2. 怎样放大优势

不要只列“记忆、语音、Live2D、提醒”等功能。每个卖点都要在 30 秒内演示，并说明边界。

| 核心优势 | 传播证据 | 用户实际得到的结果 |
|---|---|---|
| 本地优先 | 展示数据目录、联网开关、Key 归属页 | 知道哪些数据留在电脑上 |
| 从对话到执行 | 演示“整理素材 -> 预览 -> 授权 -> 执行日志” | 少做重复操作，过程可追溯 |
| 记忆可控 | 演示查看、修改、删除和 persona 隔离 | 长期上下文有用但不失控 |
| 连接器可替换 | 断开云模型或 Studio 后展示结构化降级 | 单个服务故障不会让整套产品失效 |
| 主动性可关闭 | 展示提醒原因、暂停、撤回入口 | 主动功能可理解、可控、可关闭 |
| 中性默认角色 | 首次启动使用 Aerie Companion，用户再自定义 | 面向大众合规，不绑定小众私人设定 |

当前最值得形成护城河的组合不是“角色数量”，而是 **本地数据边界 + 可审计工作流 + 可替换模型/人格/连接器**。这是 Character.AI、Replika、Pi、LM Studio/Ollama 等单点产品通常不会同时覆盖的交集。

## 3. 迎合当前市场的产品表达

市场正在从“聊天新鲜感”转向三个可验证的问题：能否节省时间、能否控制数据、能否控制成本。因此首屏只突出一个动作：下载后完成第一条消息或一个工作区任务；语音、RVC、Live2D 作为可选连接器，不把未配置能力写成默认承诺。

推荐测试三个主标题，其他页面保持一致：

1. **隐私方向**：你的 AI 数据，留在你的设备上。
2. **效率方向**：从一句话开始，把工作推进下去。
3. **可替换方向**：模型、人格和连接器，都由你选择。

不要使用“永远陪着你”“替代心理咨询”“完全离线语音”“无限调用”“不会忘记你”等无法证明或容易引发合规误解的表达。

## 4. 与同赛道产品的比较

| 赛道/代表产品 | 对方优势 | Aerie 不应硬拼 | Aerie 应强调 |
|---|---|---|---|
| Character.AI | 角色数量、社区规模 | 角色生态和云端规模 | 本地边界、工作流执行 |
| Replika/Nomi/Kindroid | 陪伴叙事、关系连续性 | 情感关系深度、移动端成熟度 | 中性默认、人格隔离、生产力 |
| Pi | 上手简单、品牌认知 | 云端可用性和分发规模 | 模型可替换、无外部服务可降级 |
| LM Studio/Ollama | 本地模型、开发者控制 | 模型运行深度和生态 | 在本地模型之上增加记忆、权限、执行 |

竞争策略是避开“最像真人”“角色最多”“无限 AI”这些昂贵且难以证明的战场，聚焦“陪伴 + 可执行工作流 + 数据控制”。

## 5. 应该收软件费还是 API 费

首发推荐：**免费本地核心 + Pro 软件订阅 + 第三方 API 单独计费**。

| 层级 | 建议测试价 | 包含内容 | 明确不包含 |
|---|---:|---|---|
| Free | 0 元/月 | 本地聊天、基础记忆、单 persona、单工作区、离线降级 | 平台补贴的云端无限调用 |
| Pro | 19 元/月与 29 元/月 A/B 测试 | 多 persona、更多工作区、主动提醒、高级记忆视图、连接器管理、优先支持 | 无限 LLM/ASR/TTS/RVC 调用 |
| Pro 年付 | 月价的 8-10 倍 | 与 Pro 月付相同 | 真实支付、退款和发票未完成前不开放 |
| 团队版 | 暂不公开，建议 99 元/月起 | 共享模板、管理员审计、部署支持 | 账号、权限和企业支持未完成前不销售 |

软件订阅购买的是软件功能、更新和支持；API 调用是外部供应商的可变成本，必须单独说明。

### API 费用的三种模式

**第一阶段：BYOK（用户自带 Key，推荐）**。Aerie 不代收 LLM、ASR、TTS、RVC 或生图费用，设置页显示“费用由对应供应商直接收取”。这最适合封闭测试，成本和供应商政策风险最低。

**第二阶段：透明用量转售**。平台代付时建立独立 API 钱包，展示供应商、模型、输入/输出 token 或音频时长、单价、余额和硬上限；余额不足就停止调用，不能静默透支。

**第三阶段：软件订阅和 API 钱包分离**。订阅状态不能推断 API 余额；取消订阅不自动退还已经产生的第三方调用费，API 余额也不能解锁 Pro 功能。

因此对外应写：

> Pro 订阅解锁软件能力；第三方模型和语音按供应商实际用量计费，支持用户自带 API Key，不承诺无限调用。

## 6. 第一次收费前要补齐什么

### 法律与运营

- 商业 EULA/终端用户许可协议；
- 隐私政策、数据删除和导出说明；
- 退款、取消续费、客服和发票/收据政策；
- 第三方模型、语音、Live2D/RVC 资产许可清单；
- 支付主体、税务主体和收款账户。

当前仓库许可仍偏向非商业学习、研究和内部评估。完成商业 EULA 或获得明确书面授权前，只做免费或书面授权的封闭测试，不直接公开收取软件订阅费。

### 最小支付闭环

```text
用户选择方案 -> 服务端创建订单 -> 支付供应商页面
-> webhook 验签与幂等处理 -> 更新订阅状态
-> 客户端拉取 entitlement -> 解锁 Pro
```

必须测试支付成功、重复 webhook、支付失败、退款、取消续费、网络中断和重新启动。客户端按钮点击、本地 entitlement 文件或前端回调都不能单独证明已付款。

## 7. 新手可以照做的上架和投放顺序

1. **内部验收（1-3 天）**：用 `D:\aerie-dist-v051` 在干净 Windows 配置中测试安装、首次启动、配置保存、第一条消息、退出重启、升级和卸载。
2. **封闭测试（10-20 人，1-2 周）**：让用户完成创建合规 persona、配置模型、执行一次工作区任务、使用一次提醒、断开外部服务后重试。
3. **价值测试（2-4 周）**：只测试三个主标题和 19/29 元价格，不同时改功能；观察首次消息、任务完成、7 日留存、试用开始和支持工时。
4. **公开下载**：先发 GitHub Release 和自有官网，附 SHA-256、隐私政策、许可、已知限制和支持邮箱；官网只链接真实存在的 Release 资产。
5. **商店上架**：等签名、升级、卸载、隐私声明、崩溃处理、退款和客服稳定后，再申请 Microsoft Store 等渠道。

首轮成功标准：安装成功率不低于 90%，首次消息完成率不低于 80%，关键流程崩溃率低于 2%。若安装失败超过 10%、费用误解导致退款集中、或 API 成本超过 Pro 收入的 50%，停止扩大投放并先修产品。

## 8. 可直接使用的宣传文案

**主标题**

> 不是把你的数据交给黑盒，而是把 AI 放回你的工作流。

**正文**

> Aerie Companion 是本地优先的 Windows AI 伙伴：它管理对话、记忆和角色，并在你授权后整理文件、安排提醒、连接语音工具。模型、人格和 API Key 由你选择。免费使用本地核心，Pro 解锁更完整的工作流能力；第三方 API 费用透明分开。

**下载按钮附近**

> Windows `0.3.2-beta.0904-A12` 公开测试版：中性合规默认角色，本地优先，外部服务不可用时明确降级。

## 9. 当前不足与改进优先级

1. 完成干净 Windows profile 的安装、升级、卸载和重启验收；
2. 将首次运行收敛为“选择角色 -> 选择模型/本地降级 -> 第一条消息”三步；
3. 为每个连接器显示健康状态、费用归属和缺失模型提示；
4. 完成真实支付、webhook、退款、发票、客服和商业 EULA；
5. 为工作区模板补齐预览、明确授权、执行日志和撤销；
6. 真实 Pixel ID、用户同意机制和转化边界完成后，再开启广告测量。

### 结论

先卖“可控的软件能力”，再卖“透明的云调用额度”。免费本地核心降低尝试门槛，19/29 元 Pro 验证用户是否愿意为记忆管理、工作流和连接器治理付费；BYOK 让早期成本可控。等安装、支付、退款和支持流程可复现后，再扩大广告预算和商店渠道。
