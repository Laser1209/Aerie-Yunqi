## 4. 数据采集方案

### 4.1 采集数据类型与频率
| 数据类别 | 具体内容 | 采集频率 | 存储路径 |
|---|---|---|---|
| 系统指标 | CPU/内存/磁盘/网络/进程 | 30s | `01_SYSTEM_METRICS\` |
| 健康心跳 | `/api/health` 原始 JSON | 60s | `02_HEALTH\` |
| API 响应 | 响应时间、状态码、请求样本 | 每请求/抽样 | `03_API\` |
| 业务日志 | main.log、通道日志 | 持续（实时归档） | `04_LOGS\` |
| 错误记录 | traceback、异常分级 | 事件触发 | `05_ERRORS\` |
| 异常快照 | 异常发生时的系统状态 | 事件触发 | `06_ANOMALY\` |
| DB 快照 | 文件大小、表行数、完整性校验 | 每 2h | `07_DB\` |
| 状态标记 | 关键节点健康/状态 JSON | 每节点 | `09_STATE\` |

### 4.2 采集格式与命名规范
- **时间戳精度**：每条 JSON 记录的 `ts` 采用**毫秒级** ISO-8601 时间戳，格式 `YYYY-MM-DDTHH:MM:SS.sss`（如 `2026-08-11T12:00:00.123`），保证单条数据可精确到毫秒级追溯。
- 系统指标/健康心跳：`JSON Lines`（每行一条，含毫秒级 `ts`），文件按小时分桶（`{子目录}_{YYYYMMDD_HH}.jsonl`）以控制体积，行内时间戳仍毫秒级独立可溯。
- 日志：保留后端原生格式，按日归档。
- 文件命名统一：`{类型}_{YYYYMMDD_HH}.{ext}`；异常/状态快照等事件型文件的命名补充毫秒级时间戳 `{类型}_{YYYYMMDD_HHMMSS_sss}.{ext}`，确保唯一与可排序。

### 4.3 存储校验机制
- 每次写入后校验文件大小>0 且可读。
- 每小时校验 `D:\Aerie\24H-LOG` 磁盘剩余空间；< 5GB 立即告警并压缩归档。
- 每小时抽查最新文件行数与时间戳连续性（发现断档即告警）。
- 采集进程自身异常时，通过独立哨兵任务上报并重启采集。

## 5. 异常情况处理流程

### 5.1 问题发现与记录
- **自动发现**：指标/健康监控超阈值、错误日志匹配、DB 校验失败。
- **人工发现**：观察员巡检、业务功能抽样发现异常。
- 所有异常统一写入 `05_ERRORS\`，记录：时间戳、模块、现象、分级、相关日志引用、处理动作。

### 5.2 问题分级
| 级别 | 定义 | 示例 |
|---|---|---|
| P0 致命 | 系统不可用/数据丢失/崩溃 | 后端进程退出、DB 损坏 |
| P1 严重 | 核心功能受损但未宕机 | 对话无法收发、QQ 断连 |
| P2 一般 | 单模块异常可恢复 | 单次生图失败、某 Provider 超时 |
| P3 轻微 | 记录即可不影响功能 | 轻微响应变慢、日志噪音 |

### 5.3 应急响应机制
- **P0**：立即停止测试相关压测动作，保留现场（进程、日志、内存 dump），记录崩溃原因后按规范重启，若为测试注入需先回滚；通知负责人。
- **P1**：定位并隔离故障模块，尝试热修复/重启子模块；保留现场证据；记录完整。
- **P2/P3**：记录异常与日志，标记为观察项，不中断主流程，测试结束后统一分析。
- 所有应急动作必须写入异常处理记录，确保可回溯。

### 5.4 异常注入测试（可选，T+20h~T+24h）
- 模拟 Provider 超时/不可用，验证降级与熔断。
- 模拟磁盘空间紧张，验证告警与归档机制。
- 模拟高并发消息，验证排队与背压。

## 6. 测试结束后数据分析与报告生成

### 6.1 数据汇总与校验
1. 停服后对 `D:\Aerie\24H-LOG` 全量文件做完整性校验（数量、大小、时间戳连续性）。
2. 合并系统指标与健康心跳，形成时间序列。
3. 统计错误/异常分级分布。
4. 对账业务功能（消息收发、记忆、世界模拟）成功率。

### 6.2 报告内容
报告生成至 `08_REPORT\`，包含：
- **执行摘要**：24h 总体结论（稳定/存在风险项）。
- **资源趋势图**：CPU/内存/磁盘随时间变化（图表优先）。
- **可用性指标**：uptime、健康状态占比、响应时间 P50/P95/P99、错误率。
- **业务功能完整性表**：各模块通过/失败情况。
- **异常清单**：按 P0-P3 分级的全部异常及处理结果。
- **结论与建议**：发现的问题、风险项、后续优化方向。

### 6.3 报告交付
- 输出 `markdown` 报告 + `CSV/JSON` 原始数据索引。
- 关键发现标注并归档至 Obsidian 审计与当前状态页。
- 报告与全部原始数据统一留存于 `D:\Aerie\24H-LOG`，确保可追溯。

## 7. 数据存储安全与完整性保障（贯穿全程）

1. **实时落盘**：所有采集数据实时写入 `D:\Aerie\24H-LOG`，不依赖内存缓存。
2. **定期校验**：每小时校验存储空间与写入正确性（见 4.3）。
3. **冗余保障**：重要日志（main.log、异常记录）同时在本项目 `logs\` 与目标目录双份留存。
4. **归档压缩**：空间紧张时自动对旧文件压缩归档，不删除原始数据。
5. **权限安全**：目标目录设为仅本机可读写，敏感数据（Provider token 等）不落入明文报告。
6. **终止条件**：目标目录写入失败或空间耗尽时，立即告警并暂停测试，修复后再继续。
