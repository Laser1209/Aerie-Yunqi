# 对话连贯性排查报告（P3 研判）

> 审计时间：2026-08-13（对话话题·行为调度·寻路感知系统修缮 P3）
> 范围：所有会干扰对话逻辑通顺度、会话延续性的潜在问题。

## 1. 主动消息与对话历史衔接（已修复，P0）

**问题**：`_dispatch_push` 生成主动消息时只注入场景模板+情绪+话术原则，
不含最近对话历史/活跃话题 → 上下文割裂（用户第一痛点）。

**修复**：TopicTracker 话题追踪 + `generate_push(topic_mode, dialogue_context)`
续接/再造模式；触发顺序 续接→再造→新话题。修复后被动消息仍需用户实测。

**残余风险**：`desire_care`/`judge tone_hint` 两处 forward 路径的
dialogue_context 注入依赖 `_dispatch_push` 统一入口，若未来新增直接调
`generate_push` 的路径需同步补参数。

## 2. L0 热窗口 8 turn 裁剪（持续观察）

`conversation_continuity.py` `recent_turn_limit=8` 只保留最近 8 个完整 turn；
`max_turn_chars=6000` 从最近向远累加截断。长话题（>8 轮）早期信息只靠分桶
摘要保留。TopicTracker 的 `summary`（最近一次对话前 200 字）提供了轻量补位，
但**话题早期上下文仍可能丢失**。

**建议**：若实测长话题失忆，可把 TopicTracker 的 `summary` 升级为滚动摘要
（每 N 轮追加一次主题句），不引入独立 LLM 管线。

## 3. 分桶摘要丢失主体（持续观察）

`conversation_summary_buckets` 每 8 轮生成新桶，注入最近 3 段；桶间边界处
主体可能被切分。TopicTracker.subject 独立维护"围绕主体"，可作为摘要的
**主题锚点**——建议后续把 topic subject 写入桶 metadata 作为检索键。

## 4. `_hist_label` 时间戳前缀（已达标）

`[MM-DD HH:MM]` 前缀 + 跨通道 `[QQ]/[桌面]` 标记；输出端 `strip_timestamp_markers`
统一剥离（历史遗留，已在生图修缮 M4 验证）。无新增风险。

## 5. `context_budget_v1` 预算裁剪（持续观察）

`max_prompt_chars=12000` / `max_total_chars=16000` 先丢最旧历史再截断 system；
L0.5 话题认知层注入受同一预算约束（FULL/AUTO + flag 开启时，段体很小 ≈
60 字）。**新增段被裁剪时话题事实可能消失**——因 flag 默认关闭，实际影响为 0，
开启后需实测预算余量。

## 6. 时序/寻路联动风险（P1/P2 新增）

- `movement` 实时派生依赖注入 clock()；若调用方误用 `datetime.now()` 会破坏
  确定性（`test_phase12_world_domain` 直接红）——已在 movement.py 文档红线。
- `_consume_daily_plan` 与 `_world_snapshot_for_context` 都在读路径触碰
  movement_manager，**多入口读同一时序状态**；单线程 asyncio 下无竞争，但
  未来若引入多线程读取需加锁。
- 前端蓝点行进依赖 `summary.movement` 透传（白名单已加），Electron 实测前
  无法自动验证（运行时验证项）。

## 结论

P0 割裂根因已修复并有单测覆盖；P1/P2 引入项均有确定性护栏（注入 clock /
flag 默认关 / 白名单透传）。剩余为运行时观察项（长话题失忆、预算裁剪、
前端蓝点），列入验收实测清单。
