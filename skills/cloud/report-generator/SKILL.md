# 视频分析报告（report-generator）

当手上已经有分析结果（分镜拆解、前三秒钩子、BGM、场景识别、统计数据等），
需要把它们整合成一份**结构化 Markdown 报告**时使用。投入的是结构化 JSON，产出的是可直接交付的报告正文。

## 铁律

1. **报告是给结论用的，不是数据搬运**：每个小节先给一句结论，再放数据。
2. **不臆造缺失数据**：分析结果里没有的字段写"未采集"，不要用手感补全。
3. **结构固定**：概览 → 逐项分析 → 交叉发现 → 结论与建议，顺序不乱。
4. **数字带口径**：每个指标写明单位、样本数、统计方式。
5. **原文可回溯**：结论要能指回具体数据（时间点 / 分镜编号），方便复核。
6. **同类多条目一律用表格**，不要写成大段文字。

## 步骤

1. **清点输入**：列出拿到的数据源与字段，标明时间范围与样本量；缺什么先记下来。
2. **写概览**：3~5 行总结——做了什么分析、覆盖多少样本、最重要的三条发现。
3. **逐项展开**：每一类分析独立成节（如 分镜、前三秒钩子、BGM、场景），每节固定用"结论 → 数据表 → 解读"。
4. **做交叉**：找出跨维度的关联（如 钩子强度 × 完播、BGM 节奏 × 情绪场景），单独成节。
5. **给结论与建议**：每条建议写清 依据数据 + 具体动作 + 预期效果。
6. **标注局限**：样本偏差、字段缺失、无法验证的部分明确写出。
7. **自检**：数字与表格对得上、章节编号连续、没有"已加载""处理完成"这类过程性废话。

## 输出形态

```
# <主题>分析报告
## 一、概览
- 数据来源 / 样本量 / 时间范围
- 核心发现 1/2/3

## 二、<维度 A>
结论：…
| 编号 | 指标 | 值 | 说明 |

## 三、交叉发现
…

## 四、结论与建议
- 建议 → 依据 → 动作 → 预期

## 五、局限与未采集项
```

## 反面例子（不要这样）

- 报告里出现"分析完成""共处理 N 条"这类过程日志。
- 把输入 JSON 原样贴上来当分析结果。
- 结论章没有任何数据支撑，全是主观判断。
- 数据缺失的维度直接跳过，读者分不清是漏了还是本来就没有。
