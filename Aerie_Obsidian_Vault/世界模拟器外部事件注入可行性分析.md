# 世界模拟器外部事件注入可行性分析

> [!abstract] 结论先行
> 当前系统**不具备**面向智能体的"外部事件注入"能力。它已具备一条**被动式真实世界数据注入链路**（天气/附近 POI/城市新闻 → `set_reality()`），但该链路既不覆盖生活事件（外卖/快递）、也不支持自定义突发事件，且**关键字段并未注入 LLM 感知层**（天气、事件、附近物件均不进入 prompt）。要支持"外部事件 → 影响内部智能体行为"，需新增事件数据结构、扩展感知注入、扩展世界状态更新机制，并新增事件触发 API 与管理界面。改动范围**中等**，可复用现有 `WorldPort`/事件总线基础设施，架构上**可行**。

## 2. 当前架构分析

### 2.1 世界模拟：确定性时钟驱动

`WorldSimulation.tick()` 依据 `clock + seed` 确定性派生 `WorldSnapshot`：时段(phase)/地点(location)/活动(activity)/精力(energy)/社交(social)/附近物件/视觉话题/天气/随机事件/城市事件。天气与随机事件均来自 **seed+时间戳的确定性哈希**，无随机环境变化。

### 2.2 已存在的"外部数据注入"通道（关键发现）

存在一条 **best-effort 的真实世界数据注入链**，是本次需求最接近的现成基础：

```mermaid
graph LR
  A[fetch_reality(city)] -->|天气/POI/新闻/本地活动| B[set_reality(reality)]
  B --> C[WorldSimulation._reality]
  C --> D[WorldSnapshot: weather_mood / weather_detail / nearby_objects / city_events]
```

- 触发点：`companion._run_world_loop()`（每 `tick_interval_sec`，默认 300s，仅 inprocess 模式）；`/api/world/reality/refresh` 可手动立即刷新。
- 该链能**更新世界快照字段**（天气情绪、窗外 POI、城市新闻），但这些字段**不会进入 LLM prompt**（见 2.4）。

### 2.3 事件/端口基础设施（可复用）

`WorldPort` 已定义 `observe()`、`subscribe()`、`WorldEvent`、事件主题（observations / lifecycle / image_candidates）与 `publish_world_event_once()` 去重转发。但当前仅用于：用户消息观察 → 关系引擎、生命周期控制、图片候选，**没有任何面向"外部世界事件"的注入路径**。

### 2.4 感知层：快照 → prompt 的实际注入（核心缺口）

`context_builder` 在 `route_mode == "FULL"` 时，仅注入**最小切片**进系统 prompt：

- 时段 / 地点 / 活动 / 精力 / 社交场景
- ⚠️ **未注入**：`weather_mood`、`weather_detail`、`city_events`、`random_events`、`nearby_objects`

主动消息路径（`proactive_candidates`/`proactive_visual_scheduler`）使用 `available_visual_topics`、`phase:activity` 生成话题与图片 prompt，但**消息正文仅形如"和你聊聊{topic} (此刻: 地点·活动)"**，不含天气/事件内容。

> [!warning] ⚠️ 关键结论
> 即使现实世界天气突变、城市有新闻、附近有生活事件，**智能体在对话中"感知不到"**——这些数据停留在仪表盘展示层，未进入认知/决策层。这是"外部事件影响智能体行为"的最大结构性缺口。

## 3. 三类外部事件的支持程度评估

| 事件类型                      | 数据模型                                    | 注入通道                     | 感知(prompt)     | 影响路径          | 结论             |
| ----------------------------- | ------------------------------------------- | ---------------------------- | ---------------- | ----------------- | ---------------- |
| 自然环境变化（风力/天气突变） | 部分：仅`weather_mood`/`weather_detail` | 仅周期刷新，无"突变"事件语义 | ❌ 未注入 prompt | 仅仪表盘/图片话题 | **不完整** |
| 生活事件（外卖送达/快递上门） | ❌ 无概念                                   | ❌ 无                        | ❌ 无            | ❌ 无             | **不支持** |
| 自定义活动/突发事件           | ❌ 无通用事件结构                           | ❌ 无注入 API                | ❌ 无            | ❌ 无             | **不支持** |

> [!note] ✏️ 说明
> `WorldSnapshot.random_events` 是**固定文本池的确定性派生**（如"阳台的花今天开了"），非外部可注入事件，也不进 prompt，与"生活事件注入"需求不同。

---

## 4. 事件触发后的影响路径评估

当前**不存在**"外部事件 → 智能体行为"的完整闭环。可复用的半程路径：

- `WorldPort.subscribe()` / `event_stream` → **UI/SSE 展示**（已通）
- `available_visual_topics` → **主动生图**（已通，但事件不改变其内容）
- 无路径：外部事件 → 主动推送消息 / 注入对话上下文 / 改变决策

要实现影响路径，需打通三处：**事件入库/注入 → 快照携带事件 → 感知层(prompt/主动消息)消费**。

## 5. 代码修改范围（逐项评估）

| 需求项               | 是否必须 | 说明                                                                                                                            |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 新增事件定义数据结构 | ✅ 是    | 新增`ExternalEvent`/`WorldEvent` 负载 schema（类型、标题、描述、生效时间、失效时间、关联物件/话题）                         |
| 扩展智能体感知模块   | ✅ 是    | `context_builder` 增注入 `weather`/`city_events`/`active_events` 切片（受预算与 FULL 模式约束）；主动消息可引用事件话题 |
| 修改世界状态更新机制 | ✅ 是    | `WorldSimulation` 增"活动事件队列"（可过期），`set_reality()` 或新 `inject_event()` 接收；`tick()` 合并进快照           |
| 新增事件触发 API     | ✅ 是    | `POST /api/world/events/inject`（受 `X-Aerie-Main-Token` 鉴权）；复用 `/api/world/control` 鉴权模式                       |
| 管理界面             | 可选     | 世界仪表盘新增事件注入/管理面板（Electron`world-dashboard-host`）                                                             |

### 5.1 适配器双模覆盖（关键）

事件 API 必须在 **InProcess 与 Remote/Sidecar 两模**都生效：

- InProcess：`InProcessWorldAdapter` 增 `inject_event()`，透传至 `WorldSimulation`
- Sidecar：`HttpWorldSidecarClient` 增 `/events` POST，`world_service/main.py` 增对应路由
- `WorldPort` 协议增方法（或复用 `control` 扩展动作）

## 6. 技术挑战与兼容性

1. **确定性与注入的冲突**：模拟器保证"同 seed+时钟 → 同结果"，注入事件会破坏可复现性。需明确注入是**覆盖**还是**合并**，并纳入 `revision`/`snapshot_id` 派生以保持审计可追溯。
2. **持久化与重放**：inprocess 为内存态，Sidecar 有 `world.db`。事件跨重启持久化、`replay_events` 语义需在两侧对齐。
3. **并发/节奏**：`_run_world_loop` 每 300s 才 tick；注入事件需**立即触发一次 tick** 或在下个周期合并，避免事件延迟不可感知。
4. **上下文预算**：往 prompt 注入天气/事件会耗 token，需受 `context_budget` 与 L 层机制约束，且不得与"内部连续性模拟，非现实已证事实"的 guard 冲突。
5. **鉴权/安全**：事件注入 API 必须沿用 `X-Aerie-Main-Token` 门禁，防止外部任意改写世界状态与操控智能体。
6. **兼容性**：`WorldSnapshot` 多字段 + dict 访问 + `restore()`/checkpoint 白名单需同步加入新字段；`Observation` 脱敏/摘要策略应沿用。

## 7. 实施建议（分阶段）

> [!tip] 💡 推荐路径：先 inprocess 最小闭环，再扩展到 Sidecar
> 遵循"先跑通最小端到端，再往上加"的原则，避免一次性动两侧适配器。

### 阶段 A：最小端到端闭环（inprocess）

1. 定义 `ExternalEvent` dataclass + 事件池/校验。
2. `WorldSimulation` 增 `active_events`（含过期）与 `inject_event()`；`tick()` 合并进快照。
3. `InProcessWorldAdapter` 增 `inject_event()` 透传。
4. `context_builder` 在 FULL 模式注入 `weather`/`active_events` 切片（受预算约束）。
5. `POST /api/world/events/inject`（Token 鉴权）→ 立即 tick。
6. 测试：注入"外卖送达"事件 → 断言快照含事件 → 断言 prompt 片段出现。

### 阶段 B：Sidecar 对齐与持久化

- `world_service/main.py` 增 `/events` 路由；`HttpWorldSidecarClient` 增方法；`RemoteWorldAdapter` 透传。
- 事件写入 `world.db`，支持 `replay_events`/`ack`。

### 阶段 C：管理界面与主动消息增强

- Electron 世界仪表盘增事件注入面板。
- 主动消息生成（`generate_push`/`proactive_visual_scheduler`）可引用 `active_events` 作为话题与破格素材。

### 风险规避策略

- 事件字段纳入 `snapshot_id` 派生，保证审计与幂等。
- 注入 API 严格 Token 鉴权 + 字段白名单 + 长度限制。
- prompt 注入受预算保护，事件条目设上限（如最近 3 条 + 摘要）。
- 为三类事件各建测试用例，纳入 `tests/test_phase*_world*` 回归。
