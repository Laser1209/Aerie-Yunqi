# 生图提示词模块化升级与室内定位计划

> [!success] 文档状态
> v2 终版：基于三路专业论证（技术可行性 / 经济合理性 / 实施风险）交叉综合后重写。v1 中 5 个方向的优先级、实现方式与风险护栏均已根据论证结论调整。论证摘要见 [[#六、三路论证结论]]。
>
> **2026-08-12 更新**：方向 1–4 全部完成并测试通过；方向 5（室内精确定位）基于全新 132㎡ 江景复式设计方案（ita-river-loft-room.design-project）完成首期对接，见 [[#八、方向 5 落地记录（2026-08-12）]]。

## 一、项目背景

当前生图链路已实现意图识别（role_selfie / role_in_scene / couple_photo / environment_object）、持久化视觉判重、世界快照时间/光线注入、主动发图话题轮换与空提示词兜底。仍存在 4 个结构性短板（v1 已列）：提示词结构死板、人物类未走图生图、时间/房间未保证必带、室内定位精度不足。

## 二、项目目标

1. 模块化提示词**语义自补**（LLM 主判 + 关键词保底）。
2. **构图协同覆盖**：focus 命中时覆盖/适配 scene 与 pose。
3. 人物类**接入图生图**锁定外貌一致性。
4. 时间光线 + 所在房间物件**恒注入**。
5. 室内精确定位（zone）+ 多参考图选图（条件可行，最后落地）。

## 三、核心变更方向（v2 结论化）

### 方向 2：构图协同覆盖 —— 【优先落地 · 零成本 · 低风险】
> 论证结论：最简单、可立即落地；纯确定性规则即可，**不要为它引入 LLM**。
- 把 `_compose_modular_prompt` 从「追加」改为「协同覆盖」：focus 为主轴，反向裁剪 scene/pose/angle 可取值（例：focus=双腿 → pose 限坐/跪坐/盘腿/跷腿；scene=沙发 → pose 限坐/倚靠）。
- 用**冲突覆盖矩阵**（确定性规则表，扩展现有 `_PHOTO_*_TABLE`），保持「未命中用 base 默认、缺值兜底」语义（`if not parts: return base` 必须保留）。
- 为「双腿」增加「大腿」优先词，命中腿自动补「肢体舒展放松」姿态倾向。

### 方向 3：人物类接入图生图 —— 【最高 ROI · 中高风险 · 关键切入路径】
> 论证结论：`generate_image_edit` + `_resolve_reference_assets`（selfie/three_view）**已存在，只差接线**；是全计划唯一「省钱 + 提质」双赢项（废图率 40%→15%，多数口径下每日成本不升反降）。
- 在 `_deliver_chat_photo` 按 intent 从 `visual_identity` 取参考资产，调用 `generate_image_edit` 而非 `generate_image`。
- **能力探测先行**：进入 edit 前检查 provider 是否有 `generate_edit` + 参考资产可解析；失败/不支持统一回退文生图（同一 prompt + 同一 idempotency），`missing_reference_asset`/`image_edit_unsupported` 静默降级，仅 `provider_failed`/超时报 warning 落盘。
- 参考图建议 **1–2 张**（selfie + three_view 之一）；用「身份复述 + 新场景 + 负向'不要重设角色'」prompt 模式，服装由文本覆盖。
- **provider 评估**：gpt-image-2 已具备参考图一致性（edit 最多 16 图、单批 10 图一致性）；备选 **Seedream（即梦/豆包，$0.045/张 + $0.003/参考图，原生角色一致性）** 与 FLUX.2（开源多参考，可本地化）——经济性显著优于 gpt-image-2，建议顺带验证。

### 方向 4：时间光线 + 房间物件恒注入 —— 【免费 · 中风险】
> 论证结论：纯数据注入，零成本；需扩展兜底函数以支持 `room` 键。
- 分层注入：**光线类恒注入**（时间/相/月相/天气，优先级最高）；**物件类条件注入**（`nearby_objects[:N]`，须与覆盖后 scene/zone 一致，空则跳过）。
- 扩展 `_inject_world_context_fallback` 支持 `room` 键；保证轻量 LLM 接力成功与兜底两条路径语义一致。

### 方向 1：`_extract_photo_spec` LLM 语义自补 —— 【低成本增强 · 高风险 · 需 flag】
> 论证结论：可做但**价值有限**，且同步→异步重构破坏面大；建议在方向 2 覆盖不足时才补。
- 用 **JSON mode + 受控 enum**（与 5 张表对齐）从 `user_raw` 语义提取并自补维度，复用 `siliconflow-light`；延迟约 180–280ms。
- **两层结构**：先跑确定性关键词表得 base spec（现状，同步、恒返回 5 键 dict）→ 再用 `asyncio.wait_for(≤5s)` + 校验决定是否覆盖；**任何异常/超时/非法输出回退确定性 spec，契约硬约束"绝不返回 None、值允许空串"**（防历史空提示词坑复发）。
- 调用链统一 async（`_image_prompt_for` 已 async），严禁在 to_thread 里跑同步 LLM。

### 方向 5：室内精确定位 + 多参考图 —— 【最后落地 · 最高风险 · 条件可行】
> 论证结论：技术上成立，瓶颈在**区域实景资产生成**（一次性工作量大），且跨世界模拟/端口/存储/生图四层，属唯一需协同部署、非纯 flag 可回滚的高风险项。
- 建立复式公寓平面图区域表（一楼玄关/客厅/厨房/餐厅/客卫；二楼主卧套房/工作室/走廊），每区带物件清单 + 光线朝向 + 场景定妆图（场景锚点库，一次性生成、全局复用）。
- `WorldSnapshot` 增加 `zone` 字段（**带默认值**）；`location`+`activity` → 精确 zone。
- **跨 adapter 能力协商 + 双 adapter 契约测试**（InProcess vs Remote sidecar），统一 snake_case 命名，旧侧缺失用 `""`/空表兜底——直接防住历史"发布协议不一致"坑；core 与 sidecar **同版本协同部署**。
- 4 参考图选择器：平面图 + 区域实景 + 外貌 + 可空（可降级，任一不可用退回子集/单图/文生图）。参考图**建议 ≤3 张**封顶输入成本。

## 四、实施步骤（v2 分阶段 · 已按风险与依赖重排）

> 综合论证：经济侧建议 3 优先，风险侧建议先建 2/4 基线。合成后执行顺序为 **2 → 3 → 4 → 1 → 5**，前四方向 flag + golden sample 灰度，方向 5 最后跨层协同。

1. **阶段 0 · 基线**：建立 golden sample（固定 persona+spec+world → 固定提示词字符串断言；固定提示词→固定参考图人工对比）；规划 feature flag 清单与监控埋点。
2. **阶段 1 · 方向 2**（零成本低风险）：协同覆盖矩阵 + 完整 focus 表，锁 golden sample。
3. **阶段 2 · 方向 3**（最高 ROI）：`generate_image_edit` 接线 + 能力探测 + 优雅降级 + `image_edit_v1` flag；按场景/人物灰度；顺带验证 Seedream provider。
4. **阶段 3 · 方向 4**（免费）：`room` 键扩展 + `room_inject_v1` flag；监控 `dedup_skipped` 与每日图量连锁影响。
5. **阶段 4 · 方向 1**（低成本增强）：JSON mode 语义自补 + 确定性保底 + `photo_spec_llm_v1` flag；先验证异步下"缺值即停防护"不回归。
6. **阶段 5 · 方向 5**（高风险）：zone 数据模型 + 能力协商 + 双 adapter 契约测试 + 平面图/场景资产 + 4 参考图选择器；拆 `world_zone_v1` + `ref_selector_v1` 两 flag；核心与 sidecar 协同部署。

## 六、三路论证结论

### 技术可行性
- 方向 2/4 低风险纯逻辑；方向 3 基础设施已存在（只差接线），性价比最高；方向 5 条件可行，瓶颈在场景资产生成。
- 参考图：gpt-image-2 edit 最多 16 图、FLUX.2 8–10 图；**2 张内足够锁单个角色，3–5 张是多参考甜区**。
- 语义自补用 JSON mode + enum 优于 function calling（轻、省 token）。

### 经济合理性
- 方向 1/2/4 增量成本≈0；方向 3 因废图率 40%→15%，**每日成本不升反降**（gpt-image-2 口径省 ~$0.31/日，Seedream 口径省 ~$1.09/日）；方向 5 净增成本，建议延后 + 参考图≤3 封顶。
- 建议设每日生图上限（30–60 张）+ 参考图输入预算护栏。

### 实施风险
- 风险排序：方向 5(最高，跨层协同、半可逆) > 方向 1/3(高，需 flag) > 方向 4(中) > 方向 2(低)。
- 关键护栏：`缺值即停防护` 契约硬约束、provider 能力探测 + 优雅降级、双 adapter 契约测试 + 能力协商防"发布协议不一致"坑、"单侧改 schema"设 review 红线。

## 八、方向 5 落地记录（2026-08-12）

## 九、生图体验修缮（M1–M4）记录

> **2026-08-12 追加**：基于用户四轮反馈（① 生图第三人称视角失控；② 主动发图模板匮乏 + 发图后伊塔"失忆"；③ `[图片](...)` 伪 markdown 被当正文输出；④ 需要系统性修缮计划），执行《生图体验修缮计划》M1–M4 四步，全部实现并测试通过。实现细节见 [[modules/ChatPhotoTriggerChain#2026-08-12 升级：POV 自拍约束 + 发图自我认知闭环（M1–M4）]]。

### 修缮目标

1. 生图恒定"她本人手持手机拍摄"POV，杜绝第三方视角。
2. 活动话题模板动态映射 + 中文翻译，解决模板匮乏与"活动场景无图可发"。
3. 发图后自我认知闭环：发什么图记什么账，用户追问"你发的什么"能回答。
4. 出口清洗伪 markdown，杜绝生图提示词外泄为正文。

### 实施步骤与优先顺序

| 步骤 | 内容 | 关键落点 |
|---|---|---|
| M1（P0） | POV 手持自拍约束 | `_SELFIE_POV_PHRASE` 恒定注入 + `_PHOTO_ANGLE_PHRASE` 机位自拍化 + `_ensure_selfie_pov` 出口兜底 + `_POV_THIRD_PARTY_BLACKLIST` 接力黑名单 |
| M2（P1） | 模板扩展 + 活动话题翻译 | `_VISUAL_TOPIC_ZH` 11 话题翻译 + `_prompt_key_for_visual_topic` 动态映射（活动→role_in_scene / 物件→environment_object）+ `_world_context_text` 接线 |
| M3（P2） | 发图自我认知落账 | `_deliver_world_image`/`_deliver_local_chat_image` async 化 + `_persist_image_event`（EVENT 记忆 importance≥7.0 + occurred_at + 不存 URL）+ `_RECALL_KEYWORDS` 扩展 |
| M4（P3） | L6 机制定义 + 出口过滤 | `_build_l6_image_capability` 重写（发图=系统后台生图）+ `strip_fake_image_markdown` 接入 QQ 双发送通道 |
| M5 | 全量回归 + 基线校准 + 文档回写 | 本记录所在环节 |

- 新增/扩展测试全绿：`test_modular_photo_prompt` 34 例 / `test_phase14_world_image_candidates` 27 例 / `test_pipeline`（RECALL 关键词）/ `test_communication` 22 例。
