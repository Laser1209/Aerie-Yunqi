# Aerie 首次商业化、投放与收费实操指南

> 面向第一次做产品、上架和收费的开发者。本文以当前 `0.3.2-beta.0904-A12` 为基线，区分“已经能验证的能力”和“还需要接入的商业基础设施”。不要把未完成的支付、账号或云端服务写成已上线功能。

## 1. 先确定卖什么

Aerie 不应把自己包装成单纯聊天机器人，也不应把“恋人”“虚拟人设”作为默认卖点。商业默认形象是中性的 **Aerie Companion**，用户可以自行选择专注助手、学习搭档、创作伙伴或生活管家等合规角色；用户自己的私有 persona 只保存在本地，不进入产品默认资源和广告素材。

最值得放大的差异化是三点的组合：

1. **本地优先的数据边界**：对话、记忆、persona 和工作区数据默认留在用户设备；联网模型、语音和 Studio 连接器都是可选项。
2. **从对话到执行**：不仅回答问题，还能把长期记忆、工作区工具、主动提醒、世界状态和可选语音放在一条可审计链路中。
3. **可替换而不被锁定**：用户可以选择自己的模型/API Key，切换 persona，并在没有外部服务时继续使用本地降级能力。

一句话定位：

> **Aerie Companion：把对话、记忆和工作流留在你的设备上，由你决定它连接什么、记住什么、执行什么。**

不要宣传“完全离线的云端语音”“永远在线监控”“医疗/心理治疗效果”或恋爱承诺。当前 ASR、RVC、Live2D 仍属于可选连接器，缺少模型或外部服务时必须明确显示降级状态。

## 2. 当前阶段应该怎么投放

### 阶段 0：内部可发布检查（1-3 天）

目标不是买广告，而是证明陌生用户能完成第一次成功体验。

- 使用 D 盘 A04 构建包做安装测试：安装、首次启动、无模型降级、配置保存、发送第一条消息、退出后重启。
- 准备一台干净 Windows 用户配置或虚拟机；不要用开发机已有的 persona、API Key 和数据库代替验收。
- 只保留一个首屏任务：启动后 5 分钟内完成“选择角色/配置模型/发送消息”其中一条闭环。
- 记录匿名错误代码、安装成功率、首条消息完成率和崩溃率，不记录聊天正文、原始音频、屏幕内容或完整 persona。

阶段通过标准建议为：安装成功率不低于 90%，首次启动不低于 95%，首条消息完成率不低于 80%，关键流程崩溃率低于 2%。

### 阶段 1：封闭测试（1-2 周）

招募 10-20 名 Windows 用户，优先选择需要“长期上下文 + 工作流”的人，而不是泛泛寻找聊天用户。给每人一份明确任务：

- 导入或创建一个合规 persona；
- 配置本地模型或自己的云模型 Key；
- 创建一个工作区任务；
- 使用一次主动提醒；
- 断开外部服务后验证降级体验。

观察用户是否在没有人工讲解的情况下理解数据边界和费用边界。此阶段不收款，最多收集自愿的问卷和错误日志。

### 阶段 2：小额价值测试（2-4 周）

营销页只测试三种信息，其他页面和价格保持一致：

| 变体 | 主标题方向 | 验证问题 |
|---|---|---|
| 隐私 | 数据留在你的设备上 | 用户是否愿意为可控的数据边界注册/下载 |
| 执行 | 从聊天直接推进工作 | 工作区和主动提醒是否带来激活 |
| 可替换 | 模型、角色和连接器由你选择 | 用户是否重视不被单一平台锁定 |

只用小预算验证注册、首次消息和试用开始，不要以点击下载作为唯一成功指标。广告 Pixel 只部署在营销页，并且需要真实 Pixel ID 和用户同意；没有真实注册/支付成功边界时，不要伪造 `trial_started` 或 `subscription_created`。

### 阶段 3：公开测试与上架

**许可闸门：** 当前仓库的 `LICENSE` 只授予非商业学习、研究和内部评估许可，
并明确禁止未经书面授权的销售、订阅或企业生产使用。因此本 A04 Release 在法律条款
未更新或未向测试者提供书面授权前，只能作为非商业技术评估版分发；不能直接向公众
收取软件订阅费，也不能把“付费测试”写成已授予商业使用权。正式收费前必须由权利人
确定面向终端用户的商业 EULA/许可、退款政策和适用地区，再同步官网、安装器和支付页。

推荐顺序：

1. GitHub Release：最适合技术用户和早期反馈，先提供 NSIS 安装器，portable 作为备选。
2. 自有官网：展示版本、SHA-256、隐私政策、退款/支持入口和已知限制；下载链接必须指向已存在的 Release 资产。
3. Microsoft Store：等签名、安装升级、卸载、隐私声明和崩溃处理稳定后再申请。商店审核前要准备开发者账号、应用标识、截图、年龄分级和隐私政策链接。
4. 其他渠道：逐一确认许可、自动更新、支付分成和用户支持责任，不要同时铺开多个渠道。

## 3. 软件费和 API 费怎么收

### 推荐的首发模式：本地免费核心 + Pro 软件订阅 + API 按实际成本

| 层级 | 建议价格 | 包含内容 | 收费边界 |
|---|---:|---|---|
| Free | 0 元 | 本地聊天、基础记忆、一个工作区、persona 编辑、离线降级 | 不承诺云端模型额度；不限制本地能力 |
| Pro 封闭测试 | 19 元/月（A/B）或 29 元/月（默认展示） | 多 persona、更多工作区、主动提醒、高级记忆视图、连接器管理、优先支持 | 订阅购买的是软件能力和服务支持，不包含无限模型调用 |
| Pro 年付 | 月价的 8-10 倍 | 与 Pro 月付相同，减少流失 | 真实支付和退款回调完成后再开放 |
| 团队/工作室 | 暂不公开，建议 99 元/月起 | 多设备策略、共享模板、管理员审计、部署支持 | 需要账号、团队权限和发票流程后再定价 |

模型、ASR、TTS、RVC 和生图 API 不建议在早期打包成“无限量”卖给用户，原因是成本、并发和供应商政策都不稳定。按以下优先级处理：

1. **用户自带 API Key（BYOK）**：Aerie 不代收 API 成本，设置页明确显示“费用由供应商直接收取”。这是当前最适合封闭测试的方式。
2. **透明用量转售**：未来如果统一代付，必须记录供应商、模型、输入/输出 token 或音频时长、单价、税费和余额；用户先充值或购买额度，余额不足时停止调用，不得静默透支。
3. **软件订阅和 API 钱包分开**：订阅状态不能推断 API 余额；退款订阅不能自动退第三方已产生的调用费。

因此首发宣传应写“软件订阅不包含第三方模型调用费用，支持自带 Key”，而不是模糊地写“每月无限 AI”。

## 4. 第一次收费需要开发什么

### 最小可收费闭环

1. 一个营销页和版本下载页；
2. 一个明确的 Free/Pro 权益表；
3. 一个服务端订单记录和支付供应商 webhook；
4. webhook 验签、幂等处理、退款/取消状态；
5. 客户端只读取服务端签发的 entitlement，不接受“前端按钮点击成功”作为付费依据；
6. 发票/收据、退款政策、客服邮箱和隐私政策；
7. 支付失败、网络中断、重复回调、退款后重新启动等测试。

支付链路应是：

```text
用户选择方案 -> 服务端创建订单 -> 支付供应商页面
-> 供应商 webhook 验签 -> 服务端更新订阅状态
-> 客户端重新拉取 entitlement -> 展示已解锁能力
```

在真实供应商和 webhook 完成前，Aerie 只能展示“试用/价格说明”，不能把本地 entitlement 文件当作真实订阅凭证，也不能在 Ads 中发送订阅成功事件。

### 账号和隐私的最低要求

- 只收集支付和支持所需的邮箱/订单信息；
- 不把聊天正文、音频、屏幕截图、私有 persona 字段写入 Ads 或商业分析；
- CAPI secret 只放服务端 secret manager 或环境变量，绝不放前端 bundle、安装包、日志或文档；
- 提供删除账号、导出本地数据、关闭测量和退款的路径；
- 为儿童、医疗、心理治疗和高风险自动化场景设置明确限制。

## 5. 如何把优势变成可传播的证据

不要只说“功能很多”，每个卖点都要有可展示的证据：

- 隐私：设置页显示本地数据目录、联网开关和 API Key 归属；
- 执行：录制 30 秒演示“自然语言任务 -> 工作区动作 -> 结果/审计记录”；
- 可替换：演示切换 persona 或模型后，历史数据仍保持隔离；
- 可靠性：展示外部服务断开时的结构化降级，而不是假装成功；
- Companion Studio：展示 `/api/health` 和明确的 chat/TTS/ASR 状态，不承诺未配置的模型。

可直接使用的宣传文案：

> **不是把你的数据交给一个黑盒，而是把 AI 放回你的工作流。**
>
> Aerie Companion 在本地管理对话、记忆和角色；需要联网时，由你选择模型、Key 和连接器。它能记住长期上下文，也能把聊天推进到工作区和提醒里。免费使用本地核心，Pro 解锁更完整的工作流能力，第三方 API 费用透明分开。

下载按钮附近的短文案：

> Windows A04 公开测试版：本地优先，合规中性默认角色，支持无外部模型降级运行。

## 6. 关键指标和停止条件

每周只看一张表：访问、下载、安装成功、首条消息、7 日留存、主动功能使用、试用开始、付费成功、退款、支持工时和 API 成本。按渠道加 UTM，但不把 UTM 和聊天内容绑定。

建议停止投放的情况：安装失败率超过 10%、首条消息完成率低于 80%、退款/投诉集中在费用误解、外部 API 成本超过 Pro 收入的 50%、或发现默认 persona/广告文案暗示恋爱、医疗、监控等不合规承诺。

## 结论

当前最稳妥的商业路径不是先收一笔“全包 AI 费”，而是先用免费本地核心降低试用门槛，用 19/29 元 Pro 测试用户是否愿意为工作流、记忆管理和连接器治理付费；模型和语音费用由用户自带 Key 或独立透明计费。等安装、支付、退款和支持流程都能复现后，再扩大广告预算和商店渠道。

上线前必须由运营者重新审核隐私、消费者权益、税务、支付供应商条款、第三方模型许可和广告平台政策；本文是实施指南，不替代法律或财务意见。
