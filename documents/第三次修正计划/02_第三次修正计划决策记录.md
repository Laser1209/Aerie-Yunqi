## 2. 使用规则

### 2.1 状态定义

| 状态 | 含义 | 是否允许据此实施 |
|---|---|---|
| `Accepted` | 用户或上位规格已经明确确认，且本文档记录了原因、影响和验证要求 | 允许实施，但仍需满足阶段启动审计 |
| `Proposed` | 已提出候选方案，等待用户或阶段门禁确认 | 不允许改生产代码、正式数据、外部账号或不可逆配置 |
| `Needs Confirmation` | 风险已识别但缺少明确授权、账号状态、成本边界或技术证据 | 不允许执行真实副作用，只能做静态分析或沙箱验证 |
| `Rejected` | 已明确不采用 | 不允许作为后续实现依据 |
| `Superseded` | 被后续决策替代 | 只能按替代决策执行，并保留迁移说明 |

### 2.2 权威顺序

1. 用户在当前任务中明确确认的选择。
2. [spec.md](../../.trae/specs/execute-third-correction-p0-fusion/spec.md) 中的 `Decisions` 与 `Requirements`。
3. 本决策记录中状态为 `Accepted` 的条目。
4. 阶段启动审计与验收审计的已通过结论。
5. 当前代码事实、测试证据和运行时审计记录。
6. `Proposed` 或 `Needs Confirmation` 条目只能作为讨论材料，不能替代授权。

### 2.3 写入门槛

出现以下任一情况时，必须新增或更新决策条目：

- 范围从 P0 扩展到 P1/P2，或阶段数量、阶段顺序发生变化。
- 引入真实模型调用、真实 QQ 登录、外部向量库、外部文件服务或不可逆数据迁移。
- 改变附件、图片、记忆、Persona、World、知识库、Renderer 暴露边界。
- 删除旧接口、结束兼容期、替换既有事实源或改变数据所有权。
- 审计发现风险需要用户接受、降级、延期或阻断。

## 3. 已确认决策

### ADR-TC-001：第一轮执行范围锁定为 P0 闭环优先

| 字段 | 内容 |
|---|---|
| 状态 | `Accepted` |
| 来源 | [spec.md §Decisions](../../.trae/specs/execute-third-correction-p0-fusion/spec.md#L47-L52) |
| 决策 | 第三次修正计划第一轮只做 P0 闭环优先，不提前扩展到关系面板、办公入口、语音、表情包或其他 P1/P2 增强。 |
| 理由 | 输入、解析、视觉、展示、知识源和审计底座未稳定前继续叠加功能，会扩大返工面和回归风险。 |
| 影响 | 阶段计划必须围绕知识库、计划门禁、P0 修复、累积验证四类主阶段展开。 |
| 风险控制 | 任意新增范围必须先新增 `Proposed` 决策，并经过阶段启动审计确认。 |
| 验证入口 | [checklist.md C2.2、C3.1-C3.13](../../.trae/specs/execute-third-correction-p0-fusion/checklist.md#L24-L66) |

### ADR-TC-002：知识源采用独立 Obsidian Vault

| 字段 | 内容 |
|---|---|
| 状态 | `Accepted` |
| 来源 | [spec.md §Decisions](../../.trae/specs/execute-third-correction-p0-fusion/spec.md#L54-L57) |
| 决策 | 第三次修正计划的信息总览知识库采用独立 Obsidian-compatible Vault，不与 `.trae/specs` 或普通计划文档混用。 |
| 理由 | 独立 Vault 便于维护模块、技术、依赖、风险、验证、审计和决策之间的双向链接，也避免知识节点碎片直接污染代码仓库根结构。 |
| 影响 | 新发现优先写入对应 Vault 笔记；仓库文档只保存计划、决策、审计、验证和同步索引。 |
| 风险控制 | Vault 与仓库文档之间必须保留同步边界和反向链接，避免出现两个互相冲突的真源。 |
| 验证入口 | [checklist.md C1.3-C1.6](../../.trae/specs/execute-third-correction-p0-fusion/checklist.md#L11-L18) |

### ADR-TC-003：向量接入策略采用专用向量库

| 字段 | 内容 |
|---|---|
| 状态 | `Accepted` |
| 来源 | [spec.md §Decisions](../../.trae/specs/execute-third-correction-p0-fusion/spec.md#L59-L62) |
| 决策 | 本轮按专用向量库方向设计和尝试接入，而不是把关键词知识库视为已经具备语义检索能力。 |
| 理由 | Echo/Pyisland/Aerie 融合知识需要语义检索能力；当前仓库是否具备 embedding 或 vector adapter 必须通过能力探测确认，不能用文档假设替代证据。 |
| 影响 | 如存在可用向量实现，则准备索引并做语义检索测试；如不存在，则记录缺失接口、阻塞原因和后续适配边界。 |
| 风险控制 | 外部向量服务、网络调用、付费模型或本地大模型索引必须另行确认，不得静默调用。 |
| 验证入口 | [checklist.md C3.13](../../.trae/specs/execute-third-correction-p0-fusion/checklist.md#L65-L66) |

### ADR-TC-004：执行采用严格阶段门禁确认

| 字段 | 内容 |
|---|---|
| 状态 | `Accepted` |
| 来源 | [spec.md §Decisions](../../.trae/specs/execute-third-correction-p0-fusion/spec.md#L64-L67) |
| 决策 | 每个阶段启动前必须完成启动审计，每个阶段完成后必须完成验收审计；未通过不得进入下一阶段。 |
| 理由 | 第三次修正计划涉及知识、附件、视觉、前端、安全、向量库和真实桌面体验，必须用可追溯审计减少遗漏和回退。 |
| 影响 | 所有阶段结论都需要记录任务覆盖、技术可行性、资源配置、风险点、代码质量、调试证据、安全审计、Electron 体验和整改状态。 |
| 风险控制 | 审计失败项必须转化为整改任务；不得把 `Not Run`、静态推断或缺证据项写成 `Pass`。 |
| 验证入口 | [checklist.md C2.6-C2.8、C4.1-C4.8](../../.trae/specs/execute-third-correction-p0-fusion/checklist.md#L32-L85) |
