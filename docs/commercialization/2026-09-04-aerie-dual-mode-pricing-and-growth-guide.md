# Aerie 双模式定价、优势放大与首次收费实操指南

> 适用基线：`0.3.2-beta.0904-A12`  
> 目标用户：AI 陪伴用户、个人创作者与自由职业者  
> 适用阶段：10-100 人封闭商业测试，不等同于已经具备公开大规模收费条件  
> 本文是产品与经营建议，不替代法律、税务、支付机构或模型供应商意见。

## 一、先给结论

Aerie 可以采用两种付费模式，但不能把它们描述成“15 元买 API 输入框”和“39 元无限用 API”。建议对外销售的是两种不同的省心程度：

| 方案 | 正式测试价 | 首月测试价 | 用户真正购买的内容 | API 费用 |
|---|---:|---:|---|---|
| Aerie 自选版 | 15 元/月 | 9.9 元 | 完整软件能力、多供应商配置、Key 本地加密、模型切换、连通性检测、用量统计和故障切换 | 用户向自己的 API 供应商支付 |
| Aerie 云享版 | 39 元/月 | 29 元 | 自选版全部能力 + 无需配置 Key 的托管模型通道 + 有上限的标准文本额度 | 包含有限额度，超出后停用或购买加量包 |

推荐先只展示月付，不立即做年付和自动续费。等至少获得 50 名真实付费用户、连续两个月退款率和 API 成本稳定后，再测试年付。

**不建议把 30 元作为云享版长期正式价。** 29 元可以做首月体验价，但支付手续费、税费、服务器、客服和模型调用都由平台承担时，29 元很容易被少数重度用户打穿。39 元更适合作为起始标价。

## 二、为什么这个价格更符合当前消费环境

当前个人用户会同时比较免费聊天产品、本地模型工具和付费 AI 订阅。Aerie 既没有必要和免费大厂比“谁的聊天更便宜”，也暂时不具备高价成熟 SaaS 的品牌与服务能力。因此定价需要满足四点：

1. **第一次决策足够轻**：9.9 元或 29 元首月，比一次性年费更容易验证真实付费意愿。
2. **续费价格足够清楚**：付款前同时显示首月价、次月价、是否自动续费和取消方式。
3. **用户能说出钱花在哪里**：15 元买软件工作流和可控性；39 元买“不配置 Key 也能用”的便利与有限云服务。
4. **重度使用不会拖垮项目**：云享版必须有实际成本硬上限，不能依赖“多数用户用得少”来补贴少数无限使用者。

公开 AI 陪伴产品通常依靠免费层降低尝试门槛，再用记忆、语音、定制或更高模型能力收费；通用 AI 产品则普遍用订阅加额度限制控制成本。Aerie 的人民币价格明显低于海外成熟订阅，但国内免费替代品很多，所以必须用“本地记忆 + 可执行工作流 + 用户可控”证明价值，而不是只卖聊天次数。

## 三、两类用户分别为什么付费

### 1. AI 陪伴用户

他们不是单纯购买回答质量，而是购买连续性、可塑性和安全感。应重点展示：

- 长期记忆可以查看、修改、删除和迁移；
- 人格由用户创建，默认角色中性合规，不绑定伊塔、云栖或私人设定；
- 主动消息有原因、频率、静默时段、暂停和撤回；
- 换模型不等于丢角色，换角色不串用另一角色的记忆；
- 数据默认留在本机，联网能力逐项说明去向和费用。

陪伴用户的核心文案：

> 不是租一个平台规定好的角色，而是在自己的电脑上，养成一个由你定义、记忆由你掌控的 AI 伙伴。

### 2. 个人创作者与自由职业者

他们更愿意为时间节省和交付结果付费。应重点展示：

- 从聊天直接生成选题、提纲、脚本和任务清单；
- 将项目资料放入独立工作区，减少不同客户之间的上下文混淆；
- 对文件操作先预览、再授权、留审计记录；
- 主动提醒把“想到”推进到“按时完成”；
- 可以按任务切换便宜模型和高质量模型，避免被单一供应商锁定。

创作者的核心文案：

> 从灵感、资料到交付，都在同一个有记忆的桌面工作流里推进。

两类人使用同一个产品，但官网和广告必须分两个落地页。不要在同一个首屏同时讲陪伴、Live2D、文件整理、QQ、世界模拟和所有技术模块。

## 四、怎样把 Aerie 的优势放大

### 优势 1：人格属于用户，不属于品牌

同赛道产品常以平台角色库、固定关系叙事或云端账号为中心。Aerie 应明确主张“人格可创建、可替换、可隔离、可导出”。商业默认素材统一使用 **Aerie Companion**，私人 persona 不进入安装包、官网、广告、截图和演示数据。

可展示证据：30 秒内创建一个“创作搭档”，再切换到“生活助手”，展示两者记忆与工作区不串线。

### 优势 2：陪伴不止聊天，还能推进现实任务

角色聊天产品擅长关系感，本地模型工具擅长运行模型，通用助手擅长回答问题。Aerie 最有机会形成差异的是把三者连接起来：长期上下文、主动提醒、工作区、受控电脑操作和可选语音共用一条可审计链路。

可展示证据：用户说“把这周三个选题整理成明天的拍摄计划”，系统先给预览，用户确认后生成文件和提醒，并能看到执行记录。

### 优势 3：用户掌控模型、数据和费用

BYOK 不是廉价版的缺陷，而是面向懂成本用户的卖点。设置页需要同时显示 Key 归属、当前模型、预计费用、月累计、故障切换和关闭联网入口。

可展示证据：切换两个 OpenAI 兼容供应商；断开其中一个后明确提示降级，不假装成功，也不丢失本地历史。

### 优势 4：主动性可解释、可停止

“会主动联系”容易成为卖点，也容易造成打扰和合规风险。将其做成可解释能力：为什么触发、何时再次触发、如何暂停、如何撤回。

可展示证据：提醒卡片显示来源和下次时间，用户一键暂停 24 小时或永久关闭。

## 五、15 元自选版不能只卖 API 配置权

如果免费版完全不能配置 API，而付费后只是出现一个 Key 输入框，用户很容易认为这是人为设限。15 元档至少应同时交付：

- 支持多个 OpenAI 兼容端点；
- Windows 本地加密保存 Key，返回界面始终掩码；
- 一键连通性和模型可用性检测；
- 主模型、备用模型和故障自动切换；
- 按供应商/模型统计请求数、Token 和估算费用；
- 导入、导出不包含明文 Key；
- 完整 persona、长期记忆、工作区和主动提醒能力；
- 软件更新与基础支持。

为了让陌生用户先验证产品，建议提供 **7 天完整试用**，试用不要求绑定支付方式。试用结束后保留本地数据和只读导出，不删除用户内容；未订阅时回到有限本地体验。

更稳妥的 A/B 测试：第一批用户一半看到 12 元/月，一半看到 15 元/月。若 15 元组的试用转付费率下降不超过 15%，保留 15 元；若下降明显，采用 12 元而不是长期用 9.9 元。

## 六、39 元云享版怎样控制成本

### 1. 对外展示额度，对内按真实成本记账

不要承诺固定“无限消息”。不同模型、上下文长度、语音和图片的成本差异很大。对外可以显示“本月云额度”和常见任务的预计可用次数；对内必须记录每次调用的供应商、模型、输入/输出 Token、缓存、音频秒数、图片张数和实际人民币成本。

建议 39 元套餐的**平台 API 实际成本硬上限为 8-10 元/用户/月**。达到 80% 时提醒，达到 100% 时停止托管调用，但允许用户切换自己的 Key。不要静默超额，也不要默认自动扣费。

可以给用户一个易懂的估算：

> 包含日常标准文本使用额度。短对话、长文、深度推理、语音和图片消耗不同，发送前显示预计消耗；额度用完后可切换自有 Key或购买加量包。

### 2. 能力按成本倍率扣减

| 能力 | 建议额度倍率 | 原因 |
|---|---:|---|
| 标准短文本 | 1x | 高频基础能力 |
| 长上下文/长文输出 | 3x-8x | 输入和输出 Token 明显增加 |
| 深度推理/高价模型 | 按模型动态倍率 | 模型价格可能快速变化 |
| 语音识别/TTS/RVC | 按秒或分钟 | 成本不应伪装成文本次数 |
| 生图/图生图 | 按张 | 单次成本和失败重试成本较高 |

首轮 39 元只建议包含标准文本。语音和生图可以少量赠送用于体验，其余做可选加量包。只有确认供应商明确允许中转、转售或面向终端用户提供服务后，才能正式售卖托管 API。

### 3. 加量包建议

第一阶段只开一个加量包，避免用户看不懂：`10 元云额度包`。它不是 10 元供应商原价余额，而是一组明确展示的 Aerie 云服务额度；购买页必须说明有效期、包含能力、退款边界和消耗记录。获得真实消耗分布后，再决定是否增加 20/50 元档。

## 七、单用户经济模型

### 自选版 15 元

```text
月收入 15
- 支付/渠道/税务预留 2
- 更新、下载、账号与基础设施摊销 1
- 客服与退款准备 2
= 目标贡献毛利约 10 元
```

BYOK 档不承担模型调用，目标贡献毛利率应高于 65%。如果平均每位付费用户每月需要超过 15 分钟人工支持，15 元可能无法覆盖服务成本，应优先改善 onboarding，而不是立刻涨价。

### 云享版 39 元

```text
月收入 39
- API 实际成本上限 10
- 支付/渠道/税务预留 4
- 云服务与监控 3
- 客服与退款准备 4
= 目标贡献毛利约 18 元
```

首轮应以贡献毛利率 40%-50% 为警戒线。连续两周出现以下任一情况时，停止扩大投放：

- API 成本超过云享版实收收入的 30%；
- 最重的 10% 用户消耗超过总 API 成本的 50%；
- 因“额度/无限”理解不一致造成集中退款；
- 客服成本超过实收收入的 20%；
- 供应商条款不允许中转或转售。

## 八、费用应该以什么名义收取

### 自选版

收取 **Aerie 软件订阅服务费**。发票/订单描述应对应软件功能、更新和支持。第三方 API 费用由用户直接向供应商支付，Aerie 页面不得把它算作已包含。

### 云享版

收取 **Aerie 软件与有限云服务订阅费**。订单、权益页和账单中把“软件权益”和“云额度”分别列出。内部必须维护两个账本：

```text
订阅账本：是否拥有软件权益、起止时间、取消、退款
用量账本：供应商、模型、实际成本、剩余额度、硬上限
```

取消订阅不能抹掉已经发生的 API 成本；剩余额度如何处理必须在购买前写清。API 余额也不能反向解锁已经到期的软件权益。

## 九、可直接使用的宣传文案

### 产品总定位

> **Aerie Companion：一个由你定义、在本地记住你，也能把事情推进下去的桌面 AI 伙伴。**

### 陪伴用户落地页

**标题**

> 角色由你定义，记忆由你掌控。

**正文**

> 创建属于你的 AI 伙伴。对话、人格和长期记忆默认保存在本机；主动联系可以解释、暂停和关闭。你可以选择自己的模型，也可以使用 Aerie 提供的有限云服务。

### 创作者与自由职业者落地页

**标题**

> 从一句灵感，到下一步行动。

**正文**

> Aerie 把对话、项目资料、长期记忆和提醒放进同一个桌面工作流。为不同客户建立独立空间，在执行文件操作前先预览并授权。

### 价格卡

**自选版 15 元/月**

> 适合已有 API Key、希望掌控模型和成本的用户。多供应商切换、Key 本地加密、用量统计、完整记忆与工作流能力。

**云享版 39 元/月**

> 适合不想研究 API 配置的用户。开通即用，包含有限标准文本云额度；用完可切换自有 Key 或购买加量包，不自动超额扣费。

### 禁止使用的表达

不要宣传“无限 AI”“永远陪伴”“绝不忘记”“完全离线的云模型/语音”“替代心理咨询”“自动操作一切”或“充值即永久拥有”。

## 十、第一次收费前必须完成的开发

当前 `core/entitlements.py` 只有本地 `free/trial/pro` 权益与用量骨架，`Pro` 价格仍是展示元数据；它不能证明用户已经付款。要直接开始商业测试，至少需要：

1. 将权益改成 `trial`、`byok`、`cloud` 三种服务端可验证方案；
2. 接入真实订单、支付页和服务端 webhook 验签；
3. webhook 幂等处理支付成功、重复回调、退款、取消和到期；
4. 客户端只读取服务端签发的 entitlement，不信任本地改文件；
5. 中转服务逐请求鉴权、限速、成本计量、余额检查和硬停止；
6. Key 使用 Windows 安全存储或等价加密方案，日志和诊断包不得含明文；
7. 用量页显示方案、周期、费用归属、已用、剩余和预计耗尽时间；
8. 完成用户协议、商业 EULA、隐私政策、退款/取消/自动续费说明和客服入口；
9. 核验第三方模型、语音、Live2D/RVC 资产及供应商的商业使用和转售许可；
10. Ads 只有在用户同意后发送匿名漏斗事件，不发送聊天正文、persona、音频、屏幕或 API Key。

支付链路必须是：

```text
用户选方案 -> 服务端创建订单 -> 支付供应商页面
-> webhook 验签并幂等入账 -> 服务端更新订阅
-> 客户端重新拉取权益 -> 解锁对应能力
```

现有根目录 `LICENSE` 只授权个人学习、研究和内部试用，`TERMS_OF_SERVICE.md` 仍是草案。二者未改成面向终端消费者的正式商业条款前，不能直接公开收费。

## 十一、四周商业测试步骤

### 第 1 周：10-20 人免费封闭测试

验证安装、首次启动、创建中性 persona、第一条消息、一次工作区任务、一次提醒、断网降级。只收匿名错误码和流程指标。

通过线：安装成功率不低于 90%，首次消息完成率不低于 80%，关键流程崩溃率低于 2%。

### 第 2 周：价格意愿测试

只展示价格和“申请测试”按钮，不伪造已付款。先测试用户是否理解两个方案，再问愿意购买哪一档以及原因。不要同时改变标题、功能和价格。

### 第 3 周：支付沙箱与成本压测

完成支付成功、失败、重复 webhook、退款、网络中断、额度用尽和重启后的回归。用合成负载验证单用户和全局硬上限。

### 第 4 周：最多 50 人真实小额测试

先开放月付。首月 9.9/29 元，续费前明确提醒下月 15/39 元。每天检查真实 API 成本、失败率、支持工时和退款原因。

## 十二、每周只看这些指标

| 环节 | 核心指标 | 初始目标 |
|---|---|---:|
| 安装 | 安装成功率 | >= 90% |
| 激活 | 10 分钟内完成第一条消息 | >= 80% |
| 价值 | 24 小时内完成一次陪伴或工作流核心动作 | >= 50% |
| 留存 | 7 日仍有有效使用 | >= 25% |
| 试用 | 试用用户进入价格页 | >= 20% |
| 付费 | 价格页到成功支付 | 先观察，不预设虚高目标 |
| 质量 | 关键流程崩溃率 | < 2% |
| 成本 | 云享版 API 成本/实收收入 | <= 25%，30% 停投 |
| 服务 | 退款原因和每用户支持分钟数 | 每周人工复盘 |

不要只看下载量。下载不等于成功安装，安装不等于第一次价值，第一次价值也不等于愿意续费。

## 十三、最终建议

先以 `15 元自选版 + 39 元云享版`进入封闭商业测试，首月分别用 `9.9 元 + 29 元`降低尝试门槛。15 元卖的是软件工作流、长期记忆、模型治理和更新支持；39 元卖的是这些软件能力加“无需配置 Key”的有限云服务。所有高成本能力按倍率计量，额度耗尽后硬停止并允许切换 BYOK。

真正值得放大的不是角色数量或“像真人”，而是以下组合：

> **人格属于用户 + 数据本地优先 + 陪伴能推进现实任务 + 模型和费用由用户掌控。**

这组优势同时服务陪伴用户和创作者，并且是 Aerie 与纯角色聊天产品、纯本地模型工具和通用云助手最清楚的区分。
