# 内部沟通（internal-comms）

当你要写给公司内部读者看的沟通材料时使用：状态周报、给上级的进展更新、
全员 FAQ、事故/故障复盘、项目立项与结项通报。
产出是**结论先行、读者 30 秒内能抓到重点并知道该做什么**的短文，而不是流水账。

## 铁律

1. **结论先行**：第一段就写清"现在什么状态、需要对方做什么"。细节放后面，对方可能只读前三行。
2. **只写对读者有用的**：判断标准是"读者看完能不能做决定或行动"，读不出动作的信息直接删。
3. **状态分级统一**：用 绿灯（按计划）/ 黄灯（有风险，需关注）/ 红灯（已阻塞，需介入）三档，不用"基本顺利""还行"。
4. **数字代替形容词**：写"覆盖率 82%，目标 90%"，不写"覆盖率略有不足"。
5. **坏消息不藏**：风险与阻塞单独成节，写清影响面、已做处置、需要谁在什么时候支援。
6. **长度自律**：周报/更新控制在一屏内（约 300 字）；FAQ 每条不超过 3 行。

## 步骤

1. **定读者与目的**：先明确"给谁看、看完要做什么"。给直属上级看和给全员看，取舍完全不同。
2. **选文体骨架**：周报/进展、事故报告、FAQ、通报各有固定结构，按下面"输出形态"套用。
3. **先写摘要**：3 行以内写清 状态 / 相较上次的变化 / 需要什么支持。
4. **填事实**：只放带数字、带日期的确定信息；未定的事写"待定 + 何时定"。
5. **列风险与支援**：逐条写 风险 → 影响 → 已做处置 → 需要的支援（人 + 时间）。
6. **收尾给动作**：明确下一步由谁负责、截止时间。
7. **回读删冗余**：删掉所有"为了 xx 而努力""持续推进中"这类不承载信息的句子。

## 输出形态

```
【状态】黄灯 · 截至 09-30
一句话结论：核心链路已打通，联调延期 2 天。

进展（带数字）
- …

风险 / 阻塞
- 风险 → 影响 → 已做处置 → 需要支援（人 + 时间）

下一步
- [负责人] 事项（截止日期）

FAQ（如适用）
- Q：… A：…（≤3 行）
```

## 反面例子（不要这样）

- 通篇"持续推进""稳步提升"，读完不知道项目到底行不行。
- 把 10 条细节按时间顺序铺开，重点淹没在中间。
- 坏消息用"遇到一些小挑战"轻轻带过，支援请求不写。
- FAQ 的回答写成一段 200 字长文，读者还是找不到答案。
